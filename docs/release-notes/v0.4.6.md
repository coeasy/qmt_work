# v0.4.6（R23）· 公式执行效率优化 + 指标引擎修复

> 发布日期：2026-10-04 ｜ 上一版本：v0.4.5
> 主题：**公式/指标执行更快、更诚实**——求值热点消除 + 跨请求结果缓存 + 修复「指标目录看得见、一算就炸」的存量缺陷，并归档历史规划文档。

## 核心变更

| # | 变更 | 说明 |
|---|------|------|
| 1 | **求值热点消除（P0-A/B）** | `registry.calc` 新增 `raw=True` 内部原语：选股求值路径保留 numpy 数组，省去整条指标序列 numpy→list 的转换（默认路径/REST JSON 契约完全不变）；`_col` 对象路径 `np.fromiter` 直出 float64、`_as_float` 对 ndarray 直通；条件求值内字段整列缓存（同 (bars,字段) 只建一次列）。**基准：5000 只×250 根求值 1910ms→1301ms（-32%）**。基准脚本 `backend/scripts/bench_formula_scan.py` |
| 2 | **公式选股结果缓存（P0-C）** | `scan_async` 同参数 TTL 缓存（env `QMT_SCREEN_CACHE_TTL`，默认 60s，`0`=禁用；LRU 16 条；**store 身份入 key**，不同库绝不串结果）。命中时响应顶层 `cached_result=true` + `cache_age_ms`（**绝不伪装成新鲜计算**），重复执行同公式从秒级降到毫秒级。前端统计行显示「缓存」徽标 |
| 3 | **修复 EMA 计算必炸的存量 bug** | 指标注册表 `ema` 的 kwargs 把 `close` 映射到不存在的形参 `closes`（`builtin.ema(series,...)`）——指标目录可见、服务端一调即 TypeError。新增守卫测试对全部 16 个注册指标做 kwargs↔形参反射校验，杜绝同类「看得见算不出」 |
| 4 | **孤儿参数清理** | `evaluate_scan(prefilter=...)` 从未被使用（ST/停牌预过滤唯一实现在 `scan_async` 取数前的 `_prefilter_codes`）→ 删除 |
| 5 | **在线取数并发可配（P1）** | `QMT_BARS_ONLINE_CONCURRENCY`（默认 4→8）；easy_tdx MAC 为单连接内部排队，提高并发不打挂源 |
| 6 | **文档归档** | 5 份已完成使命的历史规划移入 `docs/archive/`（BIG_QMT×2、UNIVERSAL_V4、UNIFIED_TRADING_ABSTRACTION、PROJECT_OPTIMIZATION_1003）；活引用路径同步改写，全仓无断链 |
