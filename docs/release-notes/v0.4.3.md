## 二、契约贯通：唯一入口消灭一条潜伏断链（R19 第 3 轮 · ①）

`GET /market/quote`（单只）与 `GET /market/indices`（指数条）在 OpenAPI 上声明响应模型 `Quote`
（`price` **必填**），但实际出口**只有批量端点 `/market/quotes` 做了「原生名 → 界面契约名」归一**。

多生产者字段名不一致是断链高发区：`eltdx` 与公开源**只给原生名 `last`**（无 `price`），
券商行情两套名都给。于是同一个 `Quote` 契约，**在不同的端点上时而成立、时而不成立**；
前端读到 `Quote.price === undefined`，K 线/概览类面板**静默空白**（不抛错，最难查的一类）。

**修法**：把归一抽成**键序唯一入口** `core/quote_fields.apply_ui_quote_contract()`：

- `price` / `pre_close` **成对处理**——取不到就**删键，绝不写 0**（「零粉饰」纪律）；
- 三处共用（批量 / 单只 / 指数条），口径分叉只能靠 grep 抓得到一处；
- 单只与指数条**复制再改**（`{**q}`）：否则就地改会**污染券商 `latest_quotes` 里的共享 dict**，
  把「一次读」的副作用留给所有后续消费者。

**护栏**：`test_quote_field_unity.py` **20 → 35**（+15）：入口语义 7 例 + 端点级 4 例
（monkeypatch `get_hub`，断言两端点出口含 `price` 且源对象未被改）+ **内联回潮扫描**
（正则 `\.pop\(\s*["']price["']\s*\)` 禁止端点绕过唯一入口自行归一）+ 幂等。

## 三、假绿灯家族清零（R19 第 3 轮 · ②③）

「绿灯被另一个 bug 或过宽判据遮出来」是本项目的**核心反面模式**。本轮一举抓出三个：

### 3.1 能力覆盖门禁：把「声明」当「入口」

`services/api/*.ts` 里 `xxApi.foo: () => http.get("/x")` 这种**声明**本身不是入口——
只要**没有任何调用点**，能力依然不可达。可这层声明会让门禁报「已覆盖」⇒ **死声明遮住真实缺口**。
实测被遮端点 **21 个**（`accountApi.pnl` / `marketApi.quote` / `marketApi.indices` /
`systemApi.ready` / `brokerApi.launch` / `researchApi.factorCompute` …）。

**修法**：判据改为「**声明不算入口、接线才算**」——方法名必须在客户端之外有调用点，
或该 URL 出现在客户端之外的源码里，才记为「有入口」；21 条按 **R19-3** 登记豁免。
并新增**豁免反腐烂**：登记了豁免但**后端已无此端点**（或已有真实入口）⇒ **报红**。
反测立刻抓出 **2 条既有过期豁免**（`GET /api/v1/data/providers`、`GET /api/v1/datahub/policies`
其实已被 `SystemStatus.tsx:122/135` 真实接线，且原登记方向还写反了）。

> 成效：`缺口 30 → 0`、`覆盖 173 / 豁免 58 / 过期 0`。

### 3.2 API 契约门禁：看不见 `http.del` 与嵌套泛型

两个独立正则盲区叠在一起：

- **别名盲区**：`services/http.ts` 的 DELETE 助手叫 `del`，而调用正则的方法白名单只列了 `delete`——
  全仓 `http.del(` **9 处**、`http.delete(` **0 处** ⇒ 9 个 DELETE 端点**从未被对账**。
- **泛型盲区**：调用形态用 `[^<>]*` 描述到括号，遇到 `http.post<Record<string, unknown>>`
  会**多出一个 `>`** 而匹配失败 ⇒ 22 个嵌套泛型调用被跳过。

**修法**：字符类补 `del`、泛型段改 `[^(\n]*`；**并补 `_METHOD_ALIASES = {"del": "delete"}`**——
否则刚认出来的 9 条会**反过来误报「后端不存在」**（第一次跑确实报了 9 条假红，
核对后端 `DELETE /api/v1/...` 11 条全部存在后才确认是归一化漏配）。

> 成效：前端**可见端点 160 → 191**，契约门禁从此覆盖 DELETE 与泛型调用。

## 四、孤儿逻辑清理（R19 第 3 轮 · ④）

**29 个前端 API 方法声明但零调用点**。先例是 R38 已删的同类死代码 `referenceApi`。
死声明不只是噪音——它会让 §3.1 的门禁说假话。

删除 29 个方法 + 4 个失效 `import`（**−146 行**），载荷类型保留（仍被别处引用），
并在 `frontend-next/src/services/api/index.ts` 写明「客户端表面积纪律」。

> 工具坑：一次性删除脚本会把**下一个方法的文档注释**当成上一个方法的尾部吃掉
> （`account.ts` 的 `batchCancel` 丢了 `/** 批量撤单… */`）⇒ 回滚 5 个文件、改算法：
> 尾部只吃「方法自己最后一行之前」的 trivia，**尾部空行/注释归下一个方法**。

## 五、门禁可证伪化（R19 第 3 轮 · ⑤）

一个「永远绿」的检查比没有检查更糟。本轮新增/重写两条**可证伪守卫**：

| 守卫 | 例数 | 覆盖的违规形态 |
|---|---|---|
| `verify_api_contract_falsifiable.py` | 4 → **7** | 端点改名 / 方法错配 / 顶层段不存在 / 对照（仅改查询串不应报）/ `http.del` 别名 / 嵌套泛型 `post` / 嵌套泛型 `get` |
| `verify_capability_coverage_falsifiable.py` | **3**（新建） | 制造「已接线端点变孤儿」/ 破坏调用点 / 制造**过期豁免** ⇒ 门禁必须变红 |

写守卫本身踩了两次坑，恰好印证主题：锚点缩进不符 ⇒ **未命中**；只改对象名而不改**方法名**
⇒ 门禁按方法名判定仍命中、`rc=0`。**结论：制造违规必须对准「判据本身」，否则守卫会自己变成假绿灯。**
每例后都做**字节级还原**，并以「不制造违规 ⇒ 门禁绿」的终态对照收尾。

### 5.1 全量回归抓出的真回归（独立于守卫）

R18 给 `SignalRouter.submit` 加了 `account_type`，却漏改测试替身
`test_p0_manual_confirm.py::_SpyRouter` → 路由 `trade.py` 传该参数即
`TypeError: _SpyRouter.submit() got an unexpected keyword argument 'account_type'`（3 例失败）。
这是 TD-34 已记录过的「**给接口加参数会打断所有替身**」**第二次复发**。
修法：① 补齐 `_SpyRouter` 与 `test_v9_unification.py` 两处替身签名；② 新增 **AST 机械护栏**
（并入 `test_order_account_type_wiring.py`）——以 `SignalRouter.submit` 真签名为真源，
扫描 `tests/` 下全部 `async def submit` 替身，缺参即点名，从源头堵死复发。

> 另有 1 例 `test_bigqmt_relay_redis.py::test_relay_moves_request_to_file_bridge` 失败，
> 经**隔离重跑通过**（13 passed）证明是**构建并发抢 CPU** 导致的 2 秒 deadline 抖动，非回归。
> 「失败也分真假」——隔离复跑是最廉价的判据。
