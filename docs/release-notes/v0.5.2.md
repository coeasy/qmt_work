## 一、P0 修复（4 条，全部有实测证据）

### 1. `asyncio.Semaphore` 自我阻塞 —— 日常增量同步永久挂死

`_sync_one_zones`（编排层）用 `async with self._sem` 包住 `await self.sync_one(code)`，
而 `sync_one` 内部也取**同一把** `asyncio.Semaphore`。`Semaphore` 不可重入，
槽占满后内层永远拿不到 ⇒ **整个同步任务永久挂死**，`gather` 无超时、日志零输出、
进程仍活着。`sync_many` 每只标的都走这条路径，日常增量 / EOD 全市场同步全中招。

**修法**：**槽只由叶子取，编排层不占槽**。`sync_one`（热）和 `_sync_one_cold`（冷）
各取各的槽，`_sync_one_zones` 改成纯编排。挂死用例 `test_sync_many_concurrency_bounded`
从 25s timeout 变 0.32s。

> 教训：**不要给冷路径「不占槽」豁免** —— 冷区间取数比热窗口更重，
> 无闸门时 `zone=cold/both` 会让几千只标的同时打券商区间接口。

### 2. `_pfx6` 在无 easy_tdx 环境把**所有**代码判非法

`datasource/tdx_transport.py` 的 `_MARKET_BY_PFX` 曾是
`{...: Market.SH/SZ/BJ} if _HAS_EASY_TDX else {}` —— 未装 easy_tdx 时**整表退化为空字典**，
而 `_pfx6` 最后一道判定 `s[:2] not in _MARKET_BY_PFX` 于是把三种代码形态
（`sh600519` / `600519.SH` / `600519`）全部判「非法 TDX 代码」并 raise。

**部署影响**：`runtimes/cp311/python.exe`（测试与打包运行时）**未装 easy_tdx**
（easy_tdx 只在 `.venv` 和 `dist/_internal`）⇒ `test_tdx_data_completeness.py`
**13 个用例全红**。部署环境若 easy_tdx 缺失，整条 TDX 查询链路**静默不可用且零日志**。

**修法**：拆分「规范字符串表」与「easy_tdx 枚举表」—— 新增
`_MARKET_PFXES = ("sh", "sz", "bj")`（纯字符串协议，不依赖可选依赖），
`_pfx6` 三处判定全改用它；`_MARKET_BY_PFX` 仅供 easy_tdx API 调用
（消费方必须先过 `is_available()`）。双环境验证（无 easy_tdx 56 passed /
有 easy_tdx 74 passed）。

> 教训：**「可选依赖缺失时整表置空」会把纯逻辑函数一起带走**。
> 纯逻辑判定表不得挂在一个可选依赖的可用性上。

### 3. paper 持仓 `profit_pct` 口径与实盘错位 **100 倍**

`paper_ledger.py` 直接透传 `profit_ratio`（**分数**，0.0528 = 5.28%），
而实盘路径 `positions.py` 用 `(price-cost)/cost*100` 产出**百分数**（5.28），
前端 `format.ts` 的 `fmtPct` 直接当百分数渲染。

**后果**：模拟盘持仓盈亏比显示 **+0.05%** 而实盘显示 **+5.28%** ——
同一字段、两种口径，差 **100 倍**。用户拿模拟盘数据决策时会被误导。

**修法**：`profit_ratio is not None` 时 `round(float(ratio) * 100, 2)`；
`None`（成本缺失）时保持 `None`（「无盈亏可言」≠「零盈亏」）。
新增回归测试 `test_paper_positions_profit_pct_is_percent_not_ratio`。

### 4. 冷仓 `dt` 未归一 —— `cold_complete` 断点续传判定失效

`bars_cold.py:_normalize_for_cold` 对 `b["time"]` 只做 `str(x).strip()`，
未归一到 `YYYYMMDD`。源链三形状混入（QMT `"20260105"` / 腾讯 `"2026-01-05"` /
东财 `datetime` 或 `"2026/01/05"`），冷仓 `kline_archive.dt` 因此**混存两种格式**：

- `MIN(dt)` 取字典序最小值而非真实最早日 —— 字符串 `'2026-01-05'` 与 `'20150101'`
  相比，`'-'`(0x2D) < `'0'`(0x30)，`_covered` 判定（`best <= cold_target`）会误判；
- 同一天跨源产出两行，跨源对账认为「两个不同交易日」；
- `WHERE dt BETWEEN start AND end` 区间过滤对另一种格式整体失效；
- `KlineCache.get` 合并热 + 冷时同日重复且顺序错乱。

**修法**：改用 `core.clock.bar_date`（唯一入口）；解析不出合法日期的行**丢弃**
（不兜底为今天、不抛异常）。新增回归测试 `test_cold_dt_normalized_to_yyyymmdd`
覆盖四种输入形状 + 坏日期跳过。

> 热路径（`bars.py:434`）早就归一了；冷路径是新写的，漏了这一步。
> 教训：**同一张表的两种写入路径必须共用同一个归一函数**。

## 三、结构性改进

### 并发模型的显式契约

`bars.py:sync_one` 的 docstring 现在明确写着：

> **★ 热路径的并发槽只在这里取**；冷路径的槽在 `_sync_one_cold` 各取各的，
> `_sync_one_zones` **不占槽**只做编排。
>
> **绝对不要**写「先占槽再调 sync_one」的包裹层：`asyncio.Semaphore` **不可重入**，
> 外层槽占满后内层永远拿不到 ⇒ 整个同步任务永久挂死且日志零输出。

同类教训也写进了 `_sync_one_zones`、`_sync_one_cold` 与 `bars_cold.py` 顶部注释。
下次有人想「顺手加个并发保护」时，注释会告诉他为什么不行。

### 状态流的分区与向后兼容

`app/sync/state.py` 现在暴露三个流名：

- `STREAM_SYNC_BARS = "sync.bars"`（历史遗留，**仅用于读取旧库**）
- `STREAM_SYNC_BARS_HOT = "sync.bars.hot"`（zone=hot/both）
- `STREAM_SYNC_BARS_COLD = "sync.bars.cold"`（zone=cold）

`sync_bars_stream(zone)` 是唯一的分流入口。`routes/market.py:_last_hot_bars_run()`
对旧库回退遗留流 —— 升级后老库用户不会看到「上次同步」瞬间变成「尚无记录」。
