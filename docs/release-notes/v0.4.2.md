## 二、定时补数：三处「隐形浪费」被根因修掉

### 2.1 每日一次的全市场无效补数（根因）

收盘后数据源约 17:00–18:00 才稳定吐出当日 K 线。旧口径把「期望日期」写成 `bar_date or prev_trading_day`
（今天，不是交易日就退回上一交易日），于是交易日 16:15 的定时选股永远判「数据落后」→ 触发全市场 `auto_backfill`
→ 数据源还没吐当日数据 → 补完仍是昨天 → 第二天重复。

**一次每天必现、且永不可能成功的几万次 RPC。**

修复：新增唯一口径 `app.sync.calendar.expected_bar_date(ready_hour=18)`——交易日且已过 `ready_hour` 才是今天，
否则一律是上一交易日；周末/节假日由既有日历规则保证。`ready_hour` 可经任务参数覆盖（`16` 更保守、`19` 更宽松）。
口径收敛后 `system_jobs.py` 删掉了三处内联局部导入，调用点全仓唯一——口径再分叉只能靠 grep 抓得到一处。

### 2.2 增量同步的「已最新跳过」

`BarsSyncer(skip_fresh=True)` + `LocalStore.latest_dt_map()`（单次聚合查询 `MAX(dt) GROUP BY code`，500 码分批）
+ `expected_bar_date()` 比对。**默认「定时更新日线」schedule 已开启 `skip_fresh: true`。**

返回体新增 `skipped_fresh`，与既有 `skipped_complete` **含义分离、分别呈现**（不可相加、不可合并）：

| 字段 | 含义 |
|---|---|
| `skipped_complete` | 历史已补到起点、本次压根不用问源（`backfill_from` 有值时） |
| `skipped_fresh` | 本次增量目标日已是最新，不用再问源 |

失败语义：`latest_dt_map` 查询抛错 → 返回 `{}` → 全部当作「不知道」→ **全部重跑**（宁可多问源几次，不可漏同步）。

### 2.3 单点异常不再吞掉整批成果

`asyncio.gather` 默认行为是「一个抛异常整批作废」。两处都改成了 `return_exceptions=True` + 失败点名单列：

- **`BarsSyncer.sync_many`**：一只标的抛任务级异常（含 `CancelledError`）只记它自己 `failed=1`，
  其余标的的 `ok` / `bars` 全部保留落库。
- **`classic_screen` 多策略**：N 个策略**并行**计算；失败的那个从 `results` 剔除，在 `strategy_failures` 里点名
  （形如 `ma_volume: 策略内部错误：除零`），其余策略结果照常落库。**只有全部失败**才向上抛错。

附带修掉一个连带误报：`sync_runner` 的空股票护栏原来只判 `total`，「全市场已最新 → total=0」会被报成
「未获取到任何股票」——惩罚刚省下来的 RPC。现改为 `total` / `skipped_complete` / `skipped_fresh` 三者同时为空才算失败。

## 三、界面：默认深色 + 极夜黑，且旧皮肤 id 自动迁移

- **首次启动默认** `theme=dark` + `skin=midnight`（极夜黑 `#000000`），并在挂载 HTML 前由
  `public/theme-boot.js` 预热 `data-theme` / `data-skin`——**不会先闪一屏白**（no-FOUC）。
- **修掉三处默认值漂移**（同一字段三个默认值，其中两处是错的）：
  1. `ui.ts` fallback 与 JSON 分支的 `customBg` 不一致（`#f2f4f8` vs `#0a0a0a`）；
  2. `theme-boot.js` 注释声称「回退到新默认（深色）」而代码实际回退 `"light"`；
  3. 皮肤 id `tongdaxin` / `dazhihui` / `ths` 用的是第三方行情软件名，与 `skins.ts` 自己的注释
     「不使用第三方行情软件名称」自相矛盾。
- **皮肤 id 中性化更名**（新 id → 视觉名）：`midnight`（极夜黑 `#000000`）、`graphite`（石墨黑 `#0a0a0c`）、
  `obsidian`（曜石黑 `#050608`）；`slate` / `forest` / `light` 不变。
- **旧 id 仍可用**：`skins.ts` 的 `LEGACY_SKIN_IDS` 与 `theme-boot.js` 各有一份
  `{tongdaxin: midnight, dazhihui: graphite, ths: obsidian}` 映射（**必须同步**）。
  老用户 `localStorage` 与服务器「外观配置」里的旧 id 读回时自动迁移，**不为零件改名买单**。
  `normalizeSkinId()` 同时用在读取与 `setSkin` 写入两侧；`resolveSkin` 出口也归一到新 id——
  否则旧 id 会让 `skins.css` 的 `[data-skin="midnight"]` 选择器全部落空，表现为「选了皮肤但背景没变」。

> 使用者侧的影响：**无**。所有旧配置自动迁移；未设置过时首次进入即深色 + 极夜黑。

## 七、安装与升级

- **无需手工迁移**。旧配置里的皮肤 id 自动映射到新 id。
- 首次启动即深色 + 极夜黑；如需浅色，在「设置 → 主题」切换，或改 localStorage 的 `qmt.ui.v1`。
- 「定时更新日线」默认已开启 `skip_fresh`；若不希望跳过（例如强制每日重拉），
  可在触发参数里传 `{"skip_fresh": false}`。

## 八、一句话总结

**这版不新增交易通道，只让每天的定时任务停止浪费 RPC、让单点失败停止连累整批、
让首次启动不再闪一屏白。**
