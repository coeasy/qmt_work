# v0.4.4 · 行情工作台深度重构：成交流换真源 + 五档盘口去券商依赖 + 涨跌色三套可选

> 发布日期：2026-10-03 · 上游基线 v0.4.3（见 [`v0.4.3.md`](v0.4.3.md)）
>
> 本版本的主题是「**看盘页不再是券商在线才好用**」。三项改动都指向同一个根因：
> 行情工作台的成交流与五档盘口**都挂在券商桥上**，而项目里明明有券商无关的本地
> TDX 数据路径没被用上。三轮逻辑审计（R21）各修完全部问题后才进入下一轮。

## 二、成交流：从「本账户成交回报」换回真实市场逐笔（①）

### 问题

工作台右栏的「实时成交流」消费 WS 的 `deal` 事件，而它的真实来源是
`sync/__init__.py::_push_order_deal_events`（`adapter.get_deals`）与 `_on_realtime_deal`
（`on_trade`）—— 即**本账户的成交回报**，不是市场逐笔成交：

- 默认标的是上证指数，**永远不会有行**；看别人的票同样恒空；
- 即便连上券商，显示的是「我自己的成交」，对判断盘口活跃度**没有意义**；
- 标题却写着「实时成交流」⇒ 语义错误，不只是没数据。

旁边那条「逐笔（券商 L2）」`/market/l2` 也是券商专属，未连接恒 503。
于是「行情工作台的成交流」在未连券商时**结构性空白**。

### 修复

新增 `GET /api/v1/market/ticks` —— 走本地 TDX（`eltdx` `0x0FC5` 当日成交明细），
**无需券商**：

- `DataSourceManager.get_ticks()`（`datasource/manager_ticks.py`，与 quotes/kline 同构的
  mixin 拆分）；能力链只挂 `eltdx`（**刻意不含 broker**，否则 auto 优先券商会把
  「无券商可用」重新掐掉）。
- 返回 `{code, items:[{time,price,volume,amount,side,order_count}], count, trading_date, source}`。
  `volume` 单位**手**、`amount` 单位**元**、`side` ∈ `buy`/`sell`/`neutral`、**最新在前**。
- ⚠️ `items == []`（盘前无成交）与 503（源不可用）**语义不同**，前端文案分开。
- ⚠️ 休市时 TDX 返回**最近一个交易日**的逐笔，故必须回 `trading_date`
  （源未给时由 `session_snapshot().as_of` 补齐）——否则周六打开会把上一交易日
  的成交当成今日行情。

前端新增 `panels/MarketTicksPanel`（工作台右栏与独立「逐笔成交」页共用），
`DealFeedPanel` 与之合并后删除。独立页与路由标签由「成交明细」更名为**「逐笔成交」**。

## 三、五档盘口：不再只认 WS 推送（②）

`OrderBookPanel` 原先**只**读 WS 推送的快照，而 WS 行情推送的前提是**有活跃券商桥**
（`sync/__init__.py::_subscribe_to_qmt` 无桥直接 `return`）。后果：

- 未连券商 / 授权串封死 ⇒ 通道一条都不推 ⇒ 五档**恒空**；
- 同一个界面里头部用 `useDisplayQuotes`（含 REST 兜底）**有价**，下方五档却写着
  「行情通道尚未连接」—— 自相矛盾。

而五档本身**不需要券商**：本地 TDX 在 `/market/quote` 就返回 `bids` / `asks`。

取值改为 **WS 优先 + `GET /market/quote` 兜底**（5s 轮询，只拉当前一只）：
WS 有五档就用 WS；没有则从 REST 借 `bids`/`asks`，价格/时间等字段仍取 WS。
两边都没有时按真实成因分叉空态，**不再**单一归因到「通道未连接」。

> 顺带消灭一处孤儿：`marketApi.quote`（单只）在前端**此前没有调用方**
> （批量端点为省带宽不带 `bids`/`asks`），现由盘口面板接上。

## 四、布局：右栏按用途分三块，中列底部坞移除（③）

```
中：头部工具条 + K 线 / 分时（吃满整列高度）
右：① 资料（基本信息 | 基本面）
    ② 盘口与成交（五档盘口 | 成交流，占满剩余高度）
    ③ 下单
```

- 「基本信息 + 基本面」合并为一块**资料**面板 Tab 切换（原先分属底部坞与右栏，
  且基本面**要展开才看得见**，而市值/PE/涨跌停是看盘时随时要瞄一眼的）。
- **中列底部坞整体移除**：它的存在前提是「基本面只能放在中列」，基本面进了右栏后
  底部坞只剩一块与右上重复的下单区 —— 等于用 42% 的图表高度换重复内容。
- 「逐笔（L2）」移出右栏（券商专属 + 与市场逐笔重叠），仍可从头部「独立盘口」进入。

## 五、涨跌配色三套 + 成交量柱颜色（④⑤）

| `data-updown` | 涨 | 跌 | 说明 |
|---|---|---|---|
| `red-up-blue` | 红 | 蓝 | **默认（0.4.4 起）**。绿色已被 `--success` 占用表示「成功」，用它表示「跌」会让「一片绿」被读成「一片顺利」；蓝与红/绿区分度也更高。 |
| `red-up` | 红 | 绿 | 传统 A 股口径，设置页一键切回 |
| `green-up` | 绿 | 红 | 欧美 / 港美股口径 |

顺序与文案的真源是 `stores/ui.ts` 的 `UPDOWN_CYCLE` / `UPDOWN_LABEL`（设置页按钮与状态栏
循环共用同一份定义，避免两处漂移）；`theme-boot.js` 同步校验（防首屏闪色）。

**修一处真实的颜色打架**：`chartStyles()` 只给 `candle.bar` 接了令牌，而
`indicator.bars`（**成交量柱**）没给 ⇒ 走 klinecharts 图库内置默认（绿涨红跌），
与蜡烛**正好相反**。现在 `indicator.bars` 也接 `--up`/`--down`/`--flat`。

**修一处「假注释」**：`chartStyles()` 的注释写着「主题切换时重建」，但 `init()` 只在
建图时取一次令牌，代码里**没有**任何随主题变化的重刷路径 —— 切到浅色或换涨跌口径后，
画布停留在建图那一刻的颜色，只有切走页签再切回才生效。新增监听 `theme`/`updown` 的
`setStyles` effect（增量刷新，不 `dispose`，缩放/十字光标不复位），并由
`tests/klineLoadFailure.test.tsx` 第 4 条锁钉死。
