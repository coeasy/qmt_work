## 一、P0 修复（4 条，全部有真机证据）

### 1. 自动连接**时序**：路径 A 慢失败饿死文件桥 + 守护首轮晚 30s

用户反馈「客户端没有自动连接大 qmt」。首轮修掉「只探路径 A」后，真机复验发现
机制通了但**太慢**：启动预算 8s 在冷缓存机器上连探测都跑不完 ⇒ 交后台守护；
守护 `while True: sleep(30)` **先睡后跑** ⇒ 首轮 +30s；路径 A 的连接尝试
（`add_connection(cfg, True)` → `adapter.start()`）**无 bound**，本机慢失败
41.87s 起，把整轮拖死 ⇒ 文件桥（路径 B）60~75s 都出现不了。

- `phase_broker._bounded_connect_action`：`CONNECT_HARD_TIMEOUT=32s` 硬超时，
  路径 A 的 `activate`/`add_connection` 与路径 B 的两个分支全部改走它；
  超时按「未连通」放行继续走 B（连接已注册，交 `BrokerHealthMonitor` 后台重连）。
- `phase_watchdogs._broker_auto_connect_guard`：循环改**先跑再睡**（首轮在相位
  装配结束立即执行，与启动自动连接无缝衔接）；连带修掉「无事可做也计入失败
  退避」的潜伏缺陷（连上后每 30s 白涨一节拍，真掉线要等 5 分钟才复探）。

真机效果：修复前「就绪后 38s+ 仍未连通」，修复后 **ready 18.1s 时桥已连上**
（等待 0.0s，active 连接）。

### 2. 能力门禁被路由层前缀**伪装**成「没连券商」（误导归因）

桥**已连接**时 live 下单 503 的消息却是「未连接任何券商客户端：请到券商连接页
添加并连接券商。（当前通道不具备下单能力…）」——前缀与事实相反，把用户引向
「去连一个已经连上的券商」。

- `app/routes/trade.py`：`broker_unavailable` 分支**原样透传** router 的 reason
  （删掉无条件 `MSG_NO_BROKER` 前缀）；路由层只做 HTTP 语义映射，病因由各
  拒绝点自负。
- `gateway/signal_router.py`：conn 闸门 missing 带出「请到连接管理核对连接 ID」；
  真正无桥场景自带完整 `MSG_NO_BROKER` 引导。
- 前端 `.banner` 补 `white-space: pre-line`（多行可执行指引不再被折成一行）。

### 3. 全量回归 **flaky**（单跑绿 / 全量红）——测试桩打了进程级全局

新增守护用例 `monkeypatch.setattr(pw.asyncio, "sleep", stub)` —— `pw.asyncio`
就是**全局 asyncio 模块**，这一刀击中进程内**所有**后台任务（app_client 的
lifespan 装在 TestClient portal 线程上的 broadcast 5s / pump 2s / health 5s /
条件单 2s / 守护 30s 循环）：用例 patch 窗口里任一线程醒来调到桩 ⇒ 断言桶被
污染成假失败 + 桩内 `_StopGuard` **炸死生产任务**
（`PytestUnhandledThreadExceptionWarning`）。

- 测试侧：`_ThreadScopedSleepShim` —— 只替换 `pw.asyncio` 这个**模块属性**，
  `__getattr__` 委派其余一切，`sleep` 按 `threading.get_ident()` 分流
  （只有发起线程拿测试桩，其它线程拿真实 sleep）。
- 产品侧：`_install_auto_connect_guard(app)` —— `broker_auto_connect=False`
  时**不装配**守护任务（与「完全不介入」的文档语义一致；旧实现照样 create_task
  空转）。正反两面回归锁（开⇒装配 / 关⇒不装配；装配条件写反的后果是自动
  连接整体停摆，即用户报过的故障）。
- 验证：组合跑 5/5 轮全绿 + 最终全量 0 failed。

### 4. `check_execution_architecture` Gate 4 红线：bigqmt_bridge.py 越过 50KB
