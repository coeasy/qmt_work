R24：修复冷启动阻塞 —— optional 相位「慢」也会阻断启动

**问题**

`phase_broker` 标为 `optional` 只保证「连接**失败**」不阻断启动，**不保证「连接慢」不阻断**。
券商客户端未启动或未登录时，`_ping` 会一直阻塞到 30s 超时；这期间 lifespan 不返回、
uvicorn 不接请求 ⇒ 客户端起来后约 **32s** 界面才真正可用。

**修复（四件套）**

- 启动期给持久连接一份**总预算** `STARTUP_CONNECT_BUDGET = 8.0s`（原先无上限、逐条顺序 `await`）；
- 多条连接**并发**拉起，共享同一份预算（顺序 await 耗时随连接数线性增长）；
- 预算到点**交还后台**继续重连 —— 不取消：真实工作跑在 `run_in_executor` 的线程里，取消协程停不掉它；
- 后台补连成功时**回调补同步** `state.bridge` / `state.gateway` 并重刷交易日历。

**实测**

启动期 `32011ms → 8015ms`，**省 24.0s**。打包态日志签名：

```
WARNING 启动期 <conn_id> 未在 8s 内连上 —— 已转入后台自动重连，不阻断启动
INFO    bootstrap phase broker (optional) done in 8015ms
INFO    后台拉起连接 <conn_id> 结束：failed（connected=False）
```

**归因分离：慢 ≠ 失败**

计数由 3 类扩为 4 类 `{started, failed, skipped, deferred}`；`deferred` 的 `last_error`
写的是**出路**（「已转入后台自动重连，不阻断启动」）而不是判决。自愈路径本就存在
（`BrokerHealthMonitor` 每 5s 检查 + 退避重连；`_broker_auto_connect_guard` 每 30s 复探），
所以「预算到点交还后台」不会丢连接。
