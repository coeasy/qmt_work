# v0.4.8（R25）· 断链归零 + 架构门禁回绿：把「没人看得见的问题」变成门禁

> 发布日期：2026-10-05 ｜ 上一版本：v0.4.7
> 主题：**让门禁真的能报警**。本轮不新增业务功能，做的全是「有没有断链 / 有没有孤儿 / 有没有死循环」这类平时没人测、出事却最贵的事。过程中四次踩到本项目反复记录的同一族缺陷——**诊断工具自己在说谎**——并每次都把它变成了带回归测试的判据（详见变更表 2 / 12 / 13 / 14）。

## 沉淀

- **两条教训都是「工具自己在说谎」**：正则交替顺序截断扩展名（20 处假断链）、通用换行把 CRLF 写回成 LF（整文件 diff）。它们与 TD-33 同族，且都**不会自报**——只能靠「报表结论与直觉不符时先怀疑工具」抓出来。
- **门禁只抓铁证**：无出口循环如果连 `await` 都没有才是铁证；有 `await` 的常驻循环、`daemon=True` 的守护循环都是合法设计。**误报比漏报更快杀死一条门禁**——红色满屏的 CI 和没有 CI 是一样的。
- **拆分必须连测试打桩点一起拆**：`from X import f` 让每个模块持有独立绑定，跨模块打桩会静默失效（测试变红，但根因在打桩点不在被测逻辑）。
- **`EXIT=$?` 抓的是管道最后一个命令的退出码**：`python x.py | tail -12; echo $?` 拿到的是 `tail` 的 0，本轮差点把一条**真红**的架构门禁当成绿的。核退出码必须用重定向，不能用管道。
- **同一个判据写两遍，比不写更坏**：两张裁定表各自维护时，同一条结论会以两种面貌出现（A 里「已判定」、B 里「待判定」），读者被迫重复判断，最后整份报告都被忽略。**裁定表必须只有一张**，工具之间要互相借，而不是各自造。
- **死分支是孤儿逻辑的极端形态**：`if X:` 里 X 恒假 —— 不报错、不覆盖、测试也发现不了，唯一线索就是「注释说的和代码做的不一样」。工具/门禁类代码尤其要拿注释逐条比对实现，因为它们的「产品」就是结论本身。
- **修判据优先于加白名单**：白名单是「把告警藏起来」的地方，藏一次就永远藏下去；拓宽判据则会让未来同类东西**自动**被正确识别。本轮两个活入口都是靠拓宽判据救回来的，且测试显式断言它们**不在**白名单里。
