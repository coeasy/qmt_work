> 发布日期：2026-09-30 · 基线版本 v0.3.10（安全修复线，见 [`v0.3.10.md`](v0.3.10.md)）

## 一、产品说明（Product Description）

**qmt_work** 是基于 QMT / XTQuant 等多券商客户端的**量化交易 Agent 平台**：同一进程内提供可视化 Web 界面 + MCP + FastAPI REST + WebSocket 实时推送，可打包为**独立桌面客户端（EXE）**。所有行情 / 交易 / 账户接口均经真实券商 SDK 调用，**零 mock**（未连接券商时返回 503 + 引导，绝不返回假数据）。

| 项 | 值 |
|----|----|
| 版本 | `0.4.0`（单一真源为仓库根 `VERSION`，构建随包分发并由 `build_exe.py` 校验） |
| 许可证 | Apache 2.0 |
| 平台 | Windows 10 / 11（迅投系券商依赖 xtquant 的 Windows 二进制，须与券商客户端**同机**运行） |

**支持券商（10 个档案）**

| 类型 | 券商 |
|------|------|
| 迅投系（xtquant 实调，7 家） | 国金 / 华鑫 / 银河 / 中信建投 / 兴业 / 广发 / 恒生 UF 定制版 |
| 接口契约（3 家，待对应 SDK 接入） | 同花顺量化 / 恒生 PTrade / 掘金量化 |

**核心能力**

| 模块 | 说明 |
|------|------|
| 可视化界面 | React + Vite + ECharts SPA，纯前端、前后端解耦；6 分组 / 43 页 + keep-alive 多标签工作区 |
| MCP 接口 | FastMCP Streamable HTTP，Cursor / Claude Desktop 直连 |
| REST API | FastAPI `/api/v1/*`，35 个路由模块（账户 / 行情 / 下单 / 回测 / 因子 / 再平衡 / 风控 / 配置…） |
| 实时推送 | WebSocket，活跃券商只订阅一次，多客户端扇出；断线重连补发最近 30s 行情 |
| 多账户网格 | 多券商 / 多账户统一看板，批量下单 / 撤单 / 重连 |
| 回测 / 因子 / 模拟盘 | 向量化回测 + 参数扫描；SMA / EMA / RSI / MACD / BOLL / ATR / ADX 等指标；虚拟撮合 + 实时行情 mark-to-market |
| 选股 / 算法交易 / 策略 | 公式 DSL + NL 自然语言选股；TWAP / VWAP 拆单；策略模板生成 + 作业运行 |
| 风控 / 审计 / 可观测性 | 日级风控（金额 / 亏损 / 次数）+ 订单超时自动撤单 + 审计 hash 链；Prometheus 指标 |
| 告警 / 外部信号 / 对账 / 目标持仓 | HMAC-SHA256 签名 Webhook；信号路由 + 二次确认；WAL 统计/归档/轮转；差量同步 |
| 数据面 | 统一数据源链（QMT → eltdx → baostock → akshare，可显式指定 / 兜底） |

**界面导航（6 分组 / 43 页）**：行情（11）· 研究（5）· 交易（6）· 账户（4）· 自动化（4）· 系统（7）。

## 二、为什么是 v0.4.0 而不是 0.3.11

- v0.3.9 安装包被发现**内嵌构建者主密钥**（发布阻断级缺陷，详见 TD-26 / [`v0.3.10.md`](v0.3.10.md)），该版本**已作废、不再分发**。
- v0.3.10 是仅针对该安全缺陷的修复发布，未对外正式宣发。
- 因此以 **v0.4.0** 作为新的公开发布版本线，明确与「带缺陷的 0.3.9」切割；自动更新（electron-updater 拉 `latest.yml`）从 0.3.10/0.3.9 平滑过渡到 0.4.0。

## 四、构建与发布文件（Build & Release）

### 4.1 构建产物清单

本地或 CI 构建后，`frontend-next/dist-electron/` 下产出：

| 文件 | 说明 |
|------|------|
| `qmt_work-Setup-<ver>.exe` | NSIS 安装包（需本机安装 NSIS；否则退回 zip） |
| `qmt_work-<ver>.zip` | 便携版（解压即跑，配置/数据在 exe 同目录 `data/ logs/`） |
| `latest.yml` | electron-updater 自动更新清单（`version` 必须等于 `VERSION`，否则客户端更新静默失效） |
| `*.blockmap` | 增量更新块映射（随 exe 一并上传） |

> 安装包**不进仓库**（`dist-electron/` 被 `.gitignore` 排除），必须作为 Release 资产挂载。

### 4.2 本地构建

```bash
bash build_all.sh --nsis        # Git Bash / Linux / macOS（Windows 用 build_all.bat）
```

脚本内置闸门（任一失败即中断，不产半包）：static 就绪核对 → 包内孤儿文件比对 → 入口核对 → `latest.yml` 硬核对 → 客户端自检（DOM 渲染自证）→ MCP 端到端。常用参数：

| 参数 | 说明 |
|------|------|
| `--clean-dist` | 打包前彻底删除上一轮 `backend/dist` 产物 |
| `--nsis` | 同时产出 NSIS 安装包（需本机 NSIS） |
| `--portable` | 仅 zip 便携版（默认） |
| `--skip-frontend` / `--backend-only` / `--no-verify` / `--force` | 跳过前端构建 / 仅后端 EXE / 跳过自检 / 跳过实例检测 |

### 4.3 CI 自动发布流程（`release.yml`）

在 GitHub Releases 页面**发布（published）**时自动触发（亦可 `workflow_dispatch` 手动触发），在 Windows runner 执行：

1. **版本一致性闸门**：校验 `tag = VERSION = package.json`，不一致直接失败（避免"装得上更不了"）。
2. **桥接运行时现备**：`fetch_runtimes.py --only cp311 --with-deps --strict`，并由 `build_exe.py` 的 `QMT_BUILD_REQUIRE_RUNTIMES=1` 硬闸门兜底（杜绝"构建全绿、包里没桥接运行时"）。
3. 前端 `npm ci && npm run build` → 后端 PyInstaller EXE → `electron-builder --win -p always` 上传资产到 Release。
4. 兜底上传（按版本号通配，避免误传历史旧包）+ 产物校验（`verify_artifacts.py --require-client`）+ 构建清单 Artifact。

> 该工作流声明 `permissions: contents: write`，Release 写权限由 **CI 的 `secrets.GITHUB_TOKEN`** 提供。
> **本地环境的 `GITHUB_TOKEN`（fine-grained PAT）缺少 Contents 写权限**，无法用 REST API 建 Release（返回 403）；须由用户在 GitHub 网页手动创建（见 4.6）。

### 4.4 版本一致性闸门

`VERSION`、`frontend-next/package.json` 的 `version`、`git tag` 三者必须相等。`release.yml` 开头校验；`build_all.sh` 的 `latest.yml` 硬核对同样依赖此一致性。

### 4.5 包内无运行期状态门禁（R39 新增）

`build_all.sh` / `build_all.bat` 在打包前清理 `backend/dist/qmt_work` 与上一轮 `win-unpacked` 的
`data logs export kline_data qmt_work_config.json`；打包后用 `verify_no_runtime_state_in_package`
断言包内无 `master.key`/`app.db`/配置/日志，命中即 **fail**。门禁逻辑已用三分支 harness 独立验证
（污染→清理后通过 / 跳过清理→exit 1 / 干净→通过）。

### 4.6 网页手动创建 Release（本环境令牌权限受限时的路径）

1. 打开 **https://github.com/coeasy/qmt_work/releases/new**
2. **Choose a tag** 选 `v0.4.0`（已推送）→ **Release title** 填 `v0.4.0`
3. **Describe** 复制本文件全文，或点 "Auto-generate release notes"
4. 勾选 **Set as the latest release** → **Publish release**（发布即触发 4.3 自动构建并挂载资产）

### 4.7 资产核对清单

发布后确认 Release 资产齐备：

- [ ] `qmt_work-Setup-<ver>.exe`
- [ ] `qmt_work-<ver>.zip`
- [ ] `latest.yml`（三者 `version` 一致）

## 五、安装与升级

- **全新安装**：下载 `qmt_work-Setup-0.4.0.exe` 安装即可。
- **已装 0.3.10 的用户**：应用内自动更新会拉取 `latest.yml` 并升级到 0.4.0（两者同源，平滑过渡）。
- **请勿使用 0.3.9 及更早版本**：0.3.9 安装包内嵌固定主密钥，存在密钥共享风险。
