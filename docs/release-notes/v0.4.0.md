# v0.4.0 · R40 公开发布版本线

> 发布日期：2026-09-30 · 基线版本 v0.3.10（发布说明见 [`v0.3.10.md`](v0.3.10.md)）
>
> v0.4.0 **不是一次功能新增**，而是把 R35–R39 连续多轮审计与修复的成果，以一个**干净的公开发布版本线**对外发布。
> 代码本体与 v0.3.10 完全一致；本版本的核心意义在于**发布链路本身的可靠性已被根因修复并落成门禁**。

## 一、为什么是 v0.4.0 而不是 0.3.11

- v0.3.9 安装包被发现**内嵌构建者主密钥**（发布阻断级缺陷，详见 TD-26 / v0.3.10.md），
  该版本**已作废、不再分发**。
- v0.3.10 是仅针对该安全缺陷的修复发布，未对外正式宣发。
- 因此以 **v0.4.0** 作为新的公开发布版本线，明确与「带缺陷的 0.3.9」切割，且让自动更新（electron-updater 拉 `latest.yml`）从 0.3.10/0.3.9 平滑过渡到 0.4.0。

## 二、本版本包含的关键修复（汇集 R35–R39）

| 轮次 | 主题 | 关键修复 |
|------|------|----------|
| R35 | 三遍深度审计 | 孤儿环境变量 `QMT_SCHEDULER_INTERVAL`、前端 `referenceApi` 死代码、3 处悬空 `create_task`、参数级契约门禁 + CI 补齐 |
| R38 | 执行架构审计 | 停机路径禁止无界等待、事件派发三参形态、常驻循环必须 try/except、hot path 缓冲必须有界 |
| R39 / TD-26 | **发布阻断缺陷** | 主密钥改为跟随主库目录（与 `.qmt_work.lock`/`.qmt_work.port`/`wal.jsonl`/`bars_cold.db` 同口径）；构建流水线新增 `purge_dist_runtime_state` + `verify_no_runtime_state_in_package` 硬门禁，杜绝「自检把密钥/库/日志写进产物又被打包带走」 |

## 三、发布链路可靠性（本次发布本身即验证项）

- **版本一致性闸门**：仓库 `VERSION`、`frontend-next/package.json` 的 `version`、`git tag` 三者必须一致，
  `release.yml` 开头显式校验，不一致直接失败，避免「装得上更不了」。
- **包内无运行期状态**：`build_all.sh` / `build_all.bat` 在打包前清理 `backend/dist/qmt_work` 与上一轮
  `win-unpacked` 的 `data/logs/export/kline_data/qmt_work_config.json`，打包后断言包内无 `master.key`/`app.db`/配置/日志，
  命中即 **fail**。门禁逻辑已用三分支 harness（污染→清理后通过 / 跳过清理→exit 1 / 干净→通过）独立验证。
- **资产来源**：`release.yml` 在 Release 发布时于 GitHub Windows runner 自动构建并上传 `exe`/`zip`/`latest.yml`；
  桥接运行时由 `fetch_runtimes.py --with-deps --strict` 现备，`build_exe.py` 的 `QMT_BUILD_REQUIRE_RUNTIMES` 硬闸门兜底，
  杜绝「构建全绿、安装包里没有桥接运行时」。

## 四、验证状态（v0.3.10 基线，v0.4.0 同源）

- 五门禁全绿：`ci_reconcile`（1704/72/43 + README 计数一致）、`check_api_contract_drift`（路径+参数级）、
  `check_ws_consumption`（34/34 零差）、`check_execution_architecture`、`check_capability_coverage`（未覆盖 0）。
- 定向测试：`test_crypto` 14 / `test_config_paths` 11 / `test_paths_guard` 16 / `test_db_backup_policy` 46 全通过。
- 包内后端树根仅 `_internal/` + `qmt_work.exe`（无 `master.key`/`app.db`/配置/日志）；密钥落到可写 `userData`。

## 五、升级指引

- 全新安装：下载 `qmt_work-Setup-0.4.0.exe` 安装即可。
- 已装 0.3.10 的用户：应用内自动更新会拉取 `latest.yml` 并升级到 0.4.0（两者同源，平滑过渡）。
- **请勿使用 0.3.9 及更早版本**：0.3.9 安装包内嵌固定主密钥，存在密钥共享风险。
