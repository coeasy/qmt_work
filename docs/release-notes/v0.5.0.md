## 一、本版新增能力

### 1.1 数据集（数据中心）——「下载来的数据」第一次能被看见、被查询、被验证

此前平台能同步数据，但**「有哪些数据集、现在库里有多少、上次什么时候同步的、点了同步数据从哪来、下完的数据长什么样」没有入口**。
本版补齐整条链路，共 **18 个数据集 / 7 个分类**：

| 分类 | 数据集 |
|---|---|
| K 线（8） | 日线 · 周线 · 月线 · 1/5/15/30/60 分钟线 |
| 逐笔（1） | 逐笔成交 |
| 分时（1） | 当日分时 |
| 参考数据（5） | 证券列表 · ETF 列表 · 板块列表 · 板块成分 · 股本结构 |
| 财务（1） | 财务数据 |
| 资金流（1） | 资金流 |
| 日历（1） | 交易日历 |

**接口**（5 个 REST + 4 个 MCP）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/datasets` | 清单 + 运行时状态（本地行数 / 上次同步时间） |
| GET | `/api/v1/datasets/sources` | **此刻**数据源真相：`declared`（声明链）vs `resolved`（实际链） |
| GET | `/api/v1/datasets/{id}` | 单数据集详情 |
| POST | `/api/v1/datasets/{id}/sync` | 触发同步（默认**只跑 50 只**，`limit` 上限 500） |
| GET | `/api/v1/datasets/{id}/data` | 查**本地已下载**数据（离线可用，不打远程源） |

**三个设计约束（都是「不许骗人」）**：

1. **HTTP 请求不做全市场**：`limit > 500` 必须同时给 `codes`，否则明确 400；
   全市场回补走定时调度 `POST /api/v1/runtime/schedules`（新增 runner `system.sync_dataset`
   与 `dataset_default_schedules()` 默认调度生成）。
2. **同步「成功但一行没写」= 数据源不可用**：后端返回 **503 + `problems[]`**，
   **绝不**让界面显示「已完成」。
3. **本地查询端点存在的意义**：不提供它，用户同步完只能靠信任。`GET /datasets/{id}/data`
   读的是本地表，离线可用 —— 这是「下载来的数据真能用」的**证据**。

**落库分派**：`DatasetSyncer` 按 4 条游标语义分流
（`CUR_BAR_DATE` 按 K 线日期 / `CUR_SNAPSHOT` 快照 / `CUR_EVENT` / `CUR_REPORT`），
落到 `dataset_store` 归口的 SQL；新增 **9 个本地落库方法**
（`upsert_ticks` / `upsert_minutes` / `upsert_capital` / `upsert_fundamentals` /
`upsert_moneyflow_hist` / `upsert_board_members` / `upsert_calendar` / `prune_dataset` …）
与迁移 **29** 建的 6 张本地表（`local_ticks` / `local_minutes` / `local_board_members` /
`local_capital` / `local_fundamentals` / `local_moneyflow_hist`）。

**分钟仓独立**：分钟线落在**独立的** `local_bars_intraday`（`datasource/intraday_store.py`），
与日线 `local_bars` 物理分离，避免「分钟线把日线视图撑爆」。其 `upsert_bars` **同签名接收**
`batch_id` / `schema_version` / `quality_state` 但 `quality_state` **刻意不落库**——
签名漂移会让分钟线同步 100% 失败而调用方只看到一句「落库失败」，是**最阴的断链**，
故显式接收 + 明说不存。

**界面**：新增「系统 → 数据中心」页（`DataCenter.tsx`），把上面所有载荷**真正接上**：
单位口径（`unit_note`，警告色）· 周期/复权/游标/增量回看（`specMeta`）·
声明链 vs 实际链（`chainMeta`）· `supports_range` · `providers[]` 可用性矩阵（含 `title` 提示依赖/商用/能力）。

### 1.2 大 QMT Agent 部署（REST + 界面）

把此前只有脚本的「bundle 生成 → 部署到策略目录 → 注册态/心跳诊断 → 配置读写」搬上接口，
共 **10 个 REST 端点**（`/api/v1/qmt-agent/*`）：

`GET status` · `GET bundle` · `POST deploy` · `POST diagnose` ·
`GET|POST config` · `GET tools` ·
`GET distribute/status` · `POST distribute/{check,pull}`

界面新增「系统 → 大 QMT 部署」页（`QmtAgentDeploy.tsx`）。
写盘一律 **先备份 `.bak.<epoch>.py` 再原子替换**（先写临时文件、再 `os.replace`），CLI 与后端同语义。

> 说明：`qmt-agent` 是**运维/管理**端点，**不**暴露为 MCP 工具（MCP 新增的 4 个全是数据集查询）。

### 1.3 部署 / 诊断脚本通用化（「适配所有安装环境」）

`deploy_qmt_work_agent.bat` 与 `diag_qmt_work_agent.bat` 此前**写死了 5 个券商安装路径 +
3 个本机 Python 路径**。本版全部改成**通用发现链**：

- **QMT 目录**：判据 = 该目录下有 `python\` 策略目录 **且**命中任一安装标记
  （`bin.x64` / `userdata` / `config/user/root` / `user.dat` / `userdata_mini` / `xtitdata`）；
  `QMT_DIR` 环境变量 → `--txt` 参数 → `discover` 逐盘符扫 1~2 层 → 人工输入，**四级降级**。
- **Python**：`QMT_PYTHON` → `py -3` → `where python` → 常见安装目录 → 注册表。
- `scripts/qmt_agent_deploy.py discover`（新子命令）：只读探测，打印
  `QMT_DIR=` / `QMT_STRATEGY_DIR=` / `QMT_RUNNING=`，未找到打 `(none)`、**退出码恒 0**，
  供 `.bat` 与自动化消费。

**`_find_qmt_dir`（后端）同步收敛**：删掉写死候选根，改用同一套「策略目录 + 次级标记」判据，
并加 **30s TTL 缓存 + `_reset_qmt_dir_cache()`**（进程级全局缓存必须能被测试清空，否则制造假绿灯）。
`explicit` 点名与 `QMT_DIR` 环境变量**语义分离**：点名失败 = **诚实报错**（不偷换目录）；
env 失效则记 warning 后**回落全盘扫描**。

## 四、残留风险（诚实列出，未闭环）

1. **`.md` 仍未纳入行尾门禁**（TD-39）：`ci_reconcile` 的第 5 项只扫描在 `.gitattributes`
   里声明了 eol 的文件，`.md` 不在其中 ⇒ 下一次 AI 整文件改写仍可能复发。
   **刻意不做全仓 `.md` 归一**：本仓库 `.md` 现为 CRLF/LF 混存，现在归一会在发布提交里塞进
   上千行「纯换行符」diff，比问题本身更糟。根治方式见 TD-39（单独一个提交 + 同步 `.gitattributes` + 门禁项）。
2. **`_candidate_roots()` 对掉线网络盘可能阻塞**：已用 30s TTL 缓存缓解，
   但 `_listdir` 本身无超时。
3. **`gen_qmt_agent_bundle.check()` 与 `qmt_agent_verify.bundle_health()` 双份 AST 语法检查**（未收敛）。
4. **`providers[].health` 与 `per_dataset[].health` 前端只用于 `title` 提示**，未做详情面板。

## 五、升级注意

- **无破坏性变更**：REST 删除 0，配置键新增不删（老配置文件可直接用）。
- 数据库迁移 **29** 为**纯新增表**（`CREATE TABLE IF NOT EXISTS`），不触碰既有表；
  分钟仓是**独立文件**（跟随 `settings.db_path.parent`）。
- 若你在**旧版**用 `deploy_qmt_work_agent.bat` 部署过，本版脚本**参数兼容**
  （`--txt` / `--reveal` / `--no-run-check` / `--force`，首个非选项参数 = QMT 目录）；
  新脚本首次运行会自动探测 QMT 目录，不再要求你手工改脚本里的路径。
- 大 QMT 的「策略列表」仍是**客户端侧持久化注册树**，拷 `.py` 进 `python\` 不会出现在列表里，
  需在客户端 GUI 里登记一次 —— 这是 QMT 客户端限制，非平台缺陷。
  `status` / `diagnose` 会如实区分「文件就位」与「已注册」。
