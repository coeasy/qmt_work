R25：四遍全链路审计与 24 处修复 —— 四个会真的亏钱 / 丢数据的缺陷

**问题**

按要求做了**四遍独立审计**（① 前后端贯通（API↔路由双向）② 孤儿逻辑 / 死循环 / 异常吞噬
③ 主体流程端到端与状态机 ④ **归因类专项**：逐条复核 60 余处 `err(503`），
共确认 4 高危 + 14 中危 + 5 低危。其中四个会**直接造成资金或数据损失**：

**① 权重被当成股数 ⇒ 全仓清仓**

前端目标持仓默认 `mode="ratio"`，后端 `target_portfolio.sync()` 只认 `"weight"`，
未知值落到 `else` 分支按**股数**处理 ⇒ 权重 `0.3` 被当成 `0.3 股`，`int(0.3) == 0`
⇒ **对每一只持仓都生成卖出 0 股的清仓意图**。

**② 持仓查询失败返回 `0.0` ⇒ 重复建仓**

`strategy_runtime._held_volume()` 异常分支 `return 0.0`，上游判据是
`if signal == "buy" and held <= 0` ⇒ **查询出错被判定成「没有持仓」⇒ 再买一次**。

**③ 启动补跑早于工厂注册 ⇒ 崩溃残留任务永久判死**

`phase_db` 恢复持久化任务时 `system.*` 的 runner 工厂还没注册（在 `phase_misc` 才
`register_all()`）⇒ 被标成「无法恢复未知任务类型」，且此后不处于 `queued/running`
⇒ **永不恢复**。

**④ EOD 读不存在的键 ⇒ 假 `final`**

`eod.py` 读 `steps["bars_sync"].get("failed_count")`，而 `SyncSummary.to_dict()` 的真键是
`failed` ⇒ **恒得 0** ⇒ 同步大面积失败仍标 `quality="final"`。

**修复**

- **枚举参数一律归一化 + 未知值报错**：`_MODE_ALIASES`（`ratio`/`weight`、`shares`/`volume`），
  未知 mode 直接 `{"ok": False, "reason": ...}`，**绝不静默走默认分支**；补 `amount` 分支。
- **「查询失败 ≠ 没有数据」**：`_held_volume` 返回类型改 `float | None`；
  `None` = **查不到**（≠ `0.0` = 确实没有）；调用方 `if held is None: 记 warn + 本轮跳过`，
  且**不写基线状态**（避免把「未知」固化）。
- **「现在还不知道 ≠ 永远不知道」**：`attach_db(db, defer_unknown=True)` 延后判定；
  `register_all()` **移到** `attach_db()` **之前**，注册后 catch-up。
- **读不存在的键恒得 0** ⇒ 键名必须由 `to_dict()` 实证，改读 `failed`。

**同时修掉的孤儿逻辑（「声明了却没人用」的一类）**

- `app/routes/signal.py` 把**所有**失败一律报 503「服务不可用」，而 `signal_router` 刻意设置的
  `broker_unavailable` 标志**从未被读取** ⇒ 风控熔断 / 超出限额 / 可用资金不足 / 参数非法
  全被归因成「后端挂了」，用户被引向错误的排查方向。现按该标志分流：
  `broker_unavailable=True ⇒ 503`（券商没连上 / SDK 缺失，给「去连接」引导），
  其余 ⇒ **400**（业务拒绝，带真实原因）。
- `app/routes/target_portfolio.py` 同一问题：`/target-portfolio/sync` 对所有失败返 503，
  而失败原因绝大多数是业务性的（`未知 mode：'ratio'`、targets 为空、总资金为 0）
  —— 上面 ① 刚把「未知 mode」从静默改成**显式报错**，若出口仍是 503，这条提示就被归因错埋掉。
  现同样按 `broker_unavailable` 分流。
- `app/routes/broker.py::connect_broker` 把 `KeyError`（`未知连接：<conn_id>`）
  和 `BrokerError` 合在一个 `except` 里统一报 503 ⇒ **用户传错 conn_id 被告知「服务不可用」**。
  现拆开：未知 conn_id ⇒ **404**，券商层不可用 ⇒ 503。
- `bootstrap/__init__.py` 的 `PhaseFn` / `_ordered()` / `run_all()` 全仓零调用（编排真源是
  `lifecycle.run_phases`）⇒ **删除**。
- `quote_bus.publish/subscribe` 无订阅者 ⇒ docstring 明写现状，不留悬念。

> 另复核了撤单在「模拟盘委托号 / 模拟盘·预演模式」下返 503 的一处，判定为**上一轮刻意订立的
> 契约**（该文件的规则是「参数错 ⇒ 400；模式 / 券商不适用 ⇒ 503」，文案已如实点明成因），
> **维持原判**。改它属判断而非修缺陷。

**其它（节选）**

  自动连接纳入 `STARTUP_CONNECT_BUDGET`；`shutdown` 在 `bridge.stop()` **之前**收敛后台启动任务。
