# QMT Work 整体架构重构与核心能力保留实施总纲 V9

> 日期：2026-09-09  
> 仓库：`coeasy/qmt_work`  
> 状态：**当前唯一实施基线**。V3–V8.1 继续保留作为阶段审计和架构演进记录；后续架构、数据面、交易面、插件、调度、前端、桌面、打包与 CI 改造优先以本 V9 为准。  
> 总目标：在**完整保留现有 MCP、REST、WebSocket、多券商/多账户、批量交易、研究、回测、风控、WAL、审计、对账等核心能力**的前提下，将 QMT Work 升级为“插件化、多行情源、多交易连接、本地优先、可离线研究、每日持续同步、可审计实盘”的量化研究与交易平台。

# 1. 一级原则

## 1.1 Preserve Capability, Replace Coupling

后续重构只允许替换内部耦合和实现，不允许丢失已有用户能力。

允许：

- 引入 AppContext / Ports / Adapters；
- 把 QMT 降为标准 Connector / Provider；
- 把单一 DataSource 升级为多行情源 Data Plane；
- 引入 Plugin Kernel；
- 升级 Scheduler / Durable JobRuntime；
- 重构目录、类和内部调用链；
- 把前端 Broker-First 改成 Platform-First；
- 把打包链升级为 Core/Plugin/Runtime Pack。

禁止：

- 删除 MCP / REST / WS 等对外入口；
- 砍掉多账户网格、批量下单/撤单/重连；
- 让现有高级交易能力在重构期间退化成占位；
- 让研究能力重新依赖 QMT；
- 让插件绕过真实交易安全链；
- 为了 CI 绿色降低测试、风控或安全门禁；
- 用 mock 掩盖真实数据缺失；
- 先删除旧能力再承诺“以后补回来”。

正确迁移方式：

```text
现有能力
  ↓
锁定 Contract / Regression Gate
  ↓
建立新 Application Service / Port
  ↓
双轨迁移
  ↓
新实现达到同等或更强能力
  ↓
删除旧内部实现
```

# 2. 最终产品定位

QMT Work 的最终定位：

> **插件化、多行情源、多交易客户端、本地优先的量化研究与交易平台。**

四条核心产品原则：

1. QMT 是重点支持的 Connector/Provider 之一，不是 Core 宿主依赖；
2. 不连接 QMT 时，行情、K 线、指标、选股、因子、研究、回测、策略设计、模拟盘仍然可用；
3. 行情数据源和交易执行源完全解耦；
4. 历史研究数据每天自动同步、校验、修复并发布可复现 Dataset Snapshot。

# 3. Tier-0 核心能力不可回退清单

以下能力必须在所有 Phase 中持续保留。

| 核心能力 | 当前/目标契约 |
| --- | --- |
| MCP | FastMCP Streamable HTTP；Cursor / Claude Desktop / 标准 MCP Client 可直连；工具发现和调用保持兼容 |
| REST API | FastAPI `/api/v1/*`；账户、行情、下单、回测、再平衡、风控、配置等继续保留 |
| WebSocket | 行情、账户、订单、成交、Algo、Condition、连接状态、对账等实时事件继续推送 |
| 行情共享 | 同一上游行情订阅去重，多客户端扇出；支持引用计数和可选跨实例总线 |
| 多券商/多账户 | 多 Broker、多账户、多客户端版本统一管理 |
| 多账户网格 | 跨券商/跨账户资产、资金、持仓、委托、成交统一看板 |
| 批量下单 | 跨账户批量下单能力保留，内部统一走 ExecutionService |
| 批量撤单 | 跨账户批量撤单能力保留 |
| 批量重连 | 跨连接批量重连能力保留 |
| 高级交易 | Signal / TargetPosition / Rebalance / Condition / Algo / Strategy Execution 保留 |
| 行情/研究 | 行情、K线、指标、条件选股、NL选股、因子、回测、研究、策略设计保留 |
| Paper / Dry Run | 模拟盘和 dry_run 保留，与 live 共享统一业务 Contract |
| 风控 | Mandatory Risk、额度、频率、价格偏离、标的限制等不降低 |
| WAL / Audit / Reconcile | 委托追踪、崩溃恢复、审计、对账核销保留并加强 |
| API Key / Scope / Rate Limit | REST/MCP 外部访问安全机制保留 |
| 通知/告警/Webhook | 现有外部通知和事件集成能力保留 |

任何一个 Tier-0 能力消失、协议静默改变、实时性明显退化或安全语义下降，都视为重构失败。

# 5. MCP / REST / WebSocket 作为一等平台入口

## 5.1 MCP

目标调用链：

```text
Cursor / Claude Desktop / Other MCP Client
                  ↓
        FastMCP Streamable HTTP
                  ↓
              MCP Adapter
                  ↓
         Application Services
                  ↓
Data / Research / Execution Core
```

MCP 继续保留工具发现、参数 Schema、错误语义和客户端兼容，但不再拥有独立业务实现。

禁止：

```text
MCP Tool → raw Broker / raw DB / gateway.place_order
```

## 5.2 REST

继续保留：

```text
/api/v1/*
```

核心路径和请求/响应 Contract 原则上保持兼容。确需破坏性变更时必须采用：

```text
新版本 API
+ deprecation warning
+ 迁移期
+ Contract test
```

## 5.3 WebSocket

实时事件继续覆盖：

```text
行情
账户快照
订单
成交
Algo
Condition
Strategy
连接状态
风控
对账
系统状态
```

要求：

- 同一上游订阅去重；
- 多前端/多客户端扇出；
- 断线重连；
- 有界重放；
- 有界队列/背压；
- 慢消费者不能拖垮行情主链；
- 事件 Contract 逐步 TypeScript/Pydantic 双向锁定。

QMT、tstdx、eltdx、BaoStock、新浪、腾讯及后续其他源都只是 Data Provider。

## 8.1 Capability Ports

一个 Provider 只实现真实拥有的能力，禁止用空壳或 mock 补齐。


# 14. Scheduler Plane：每天必须自动同步历史行情

“每天更新历史数据”属于系统基础设施，不是可有可无的按钮。

## 14.1 Durable JobRuntime

保留现有：

- 配额；
- 优先级；
- 进度；
- 取消；
- sync/screen/backtest runner。

升级增加：

```text
Durable Job Store
retry
misfire
lease
heartbeat
checkpoint
interrupted recovery
startup catch-up
```

## 14.2 Durable Scheduler

```text
Schedule Definition
      ↓
Schedule Store
      ↓
Scheduler
      ↓
Durable Job Store
      ↓
JobRuntime
      ↓
Registered JobKind
```

Scheduler 禁止执行任意 shell，只能运行平台注册 JobKind。

## 14.3 系统任务

至少：

```text

system.market.eod_reconcile
system.market.rolling_repair
system.instrument.sync
system.calendar.sync
system.corporate_action.sync
system.storage.maintenance
system.database.backup
```

## 14.4 EOD 历史同步

默认按 `Asia/Shanghai` 交易所日历，收盘后触发，例如 18:30。

执行链：

```text
Exchange Calendar
  ↓
Instrument Universe
  ↓
Provider Capability Selection
  ↓
Chunk / Rate Limit
  ↓
Raw Ingestion
  ↓
Normalize
  ↓

  ↓

  ↓

  ↓
```


# 17. 前端：Platform-First，不再 Broker-First

顶层 Context：

```text
PlatformProvider
 ├── CapabilityProvider
 ├── DataProvider
 ├── QuoteHubProvider
 ├── TradingConnectionProvider
 ├── SchedulerProvider
 └── WorkspaceProvider
```

`TradingConnectionProvider` 可以为空。

页面按 Capability Gate：

- 行情/选股/研究依赖 Data Capability；
- 账户/真实持仓/下单依赖 Execution Capability；
- 未连接交易客户端时交易动作禁用，但研究页面正常。

建议长期 Feature Architecture：

```text
frontend/src/
├── app/
├── features/
│   ├── market/
│   ├── trading/
│   ├── broker/
│   ├── accounts/
│   ├── strategy/
│   ├── backtest/
│   ├── research/
│   ├── data/
│   ├── scheduler/
│   └── settings/
└── shared/
    ├── api/
    ├── ws/
    ├── events/
    ├── ui/
    └── types/
```

优先 TypeScript 化交易/账户/持仓/Broker/策略执行/WS Event。

FastAPI OpenAPI 生成 TS Client，减少 REST 契约漂移。

# 27. 最终一句话目标

> **QMT Work 的 Core 负责标准模型、研究能力、任务调度和安全执行；Data Provider 决定“数据从哪里来”，Execution Connector 决定“订单往哪里去”，Plugin Platform 决定“能力如何扩展”，HistoricalStore/Dataset Snapshot 决定“研究如何稳定复现”，Scheduler 决定“数据如何每天持续完整”，而 MCP、REST、WebSocket、多账户网格和批量交易等现有核心能力在整个重构过程中必须始终可用且不能回退。**
