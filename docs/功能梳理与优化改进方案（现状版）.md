## 三、优化改进方案（分阶段，贴合现状）

> 优先级判定：影响“金融正确性/能否对外自称专业” > 架构天花板 > 研究深度 > 生态 > Agent（Agent 后端已删，重建成本高，单列）。

### 阶段 0：收尾清理（0.5 周，无外部依赖）
1. **孤儿表决策**：`sessions/messages/llm_config` 标注“为阶段 5 Agent 预留”或在迁移中保留但注明未启用；同步更新文档。
2. **文档数字同步**：README/方案里的“149 测试/24 页”改为“192 测试 + 13 冒烟 / 32 组件”，纳入 CI 自动核对（阶段 4）。✅ 已完成。
3. **风险点提示**：`risk` 默认持仓 100 万为演示级，需在 Dashboard/Settings 显式标注“未接入真实持仓时风控为演示值”。

### 阶段 1：A 股金融正确性（2–3 周，最高优先级，无外部依赖）⭐
目标：回测/模拟盘从“功能级”提升到“A 股规则正确级”。
1. **统一撮合内核（参数化）**：新增执行时点（当根 close / 次根 open）、滑点模型（固定 bps / 价差模型 / 成交量参与率上限）、涨跌停不可成交（买不进涨停/卖不出跌停）、成交量容量约束（单笔 ≤ 当根成交量 x%）。
2. **A 股交易规则**：100 股整手（回测/模拟盘/下单全链路）、模拟盘 T+1（记录可卖数量）、涨跌停价格校验。
3. **指标严谨性**：年化按 bar 频率换算（日线 252 / 分钟线按日内 bar 数）；新增基准收益、alpha/beta、信息比率、Calmar；夏普 rf 可配置。
4. **VWAP 真实化**：接入券商分时成交量分布（xtdata 历史分时）生成时间-量权重曲线；无数据时显式降级为 TWAP 并在返回标注。
5. **主动盯市**：模拟盘挂接 SyncEngine 行情事件（复用订阅聚合），替代读时触发；缺行情时市值冻结并标注。
6. **防过拟合基线**：回测作业增加 train/test 时间段切分参数 + 样本外指标对比输出。
- 验收：撮合规则单测（整手/T+1/涨跌停/容量）≥30 例；同一策略旧新内核差异报告；分钟线回测年化数值正确。

### 阶段 2：存储与架构加固（3–4 周，无外部依赖，部分高风险）
1. **行情写路径改造**：`market_cache` 改微批写入（随 WS 微批 100ms 窗口事务内批量 upsert），消除 tick 级写盘风暴。
2. **DB 层升级**：连接池或按线程分连接（替代单连接+全局锁）+ 批量事务 API；`account_snapshot/market_cache` 大表加分区/清理策略。
3. **内存治理**：订单指纹/成交去重/限流器加 LRU 上限与 TTL；`BrokerAdapter` 增加 `unsubscribe_quote` 抽象，bridge handler 支持退订。
4. **Registry 落库**：热插拔 profile 持久化；capabilities 从适配器实例动态探测。
5. **风控数据源升级**：仓位/总资产从 SyncEngine 账户快照实时喂入 `RiskManager`，替代内存默认值。
- 注意：300 行 `lifespan` 不强求完整 DI 容器重构（风险高、易回归），建议抽“组件装配函数 + 显式依赖”即可。
- 验收：100 标的并发订阅下 market_cache 写延迟/CPU 压测；无内存增长 24h 长跑。

### 阶段 3：研究深度（4–6 周，纯计算，无外部依赖）⭐
1. **因子分析层**：在现有 15 因子注册表上扩展 IC / ICIR、分组（分位数）回测、因子相关性矩阵；新增 MCP 工具 + 前端因子页。
2. **多标的组合回测**：向量化内核扩展 N 标的 × 权重矩阵（等权/目标权重/信号强度），接入现有 `target_portfolio` 差量逻辑，形成“回测→实盘同一份目标持仓”闭环。
3. **walk-forward**：滚动窗口 train/test + 参数自动寻优（optuna，复用 `run_param_sweep`），输出稳健性报告（各窗口夏普分布/参数漂移）。
4. **绩效归因增强**（吸收 EzQmt）：分策略/分标的贡献、滑点归因（分钟线成交价 vs VWAP）、成本拆解，接入现有 `analysis.py`。
- 验收：组合回测与单标的一致性测试；walk-forward 在示例策略输出样本外报告；IC 分析页可用。

### 阶段 4：接入广度与生态（持续，部分外部依赖）
1. **CI 与质量门禁**：GitHub Actions（pytest + ruff + 前端 build），PR 强制绿；补 RedisLock 真路径（fakeredis）。✅ **已完成（2026-08-16）**：`.github/workflows/ci.yml` 三道门禁（192 测试零 mock / ruff F+E9 / 前端 vite build）+ `scripts/ci_reconcile.py` 数字核对（192 测试、32 组件）纳入 CI 阻断。
2. **真接 1–2 家非迅投券商**：同花顺 > PTrade。把“多券商”从架构承诺变现实。🚧 **强依赖对方 SDK/客户端许可与版本稳定性**，建议契约优先、保持“无 SDK 即 503”。
3. **数据源兜底**：akshare/pytdx 接入 `reference` 层作为 xtquant 之外行情兜底（离线回测不强依赖券商在线）。需评估额外 pip 依赖。
4. **策略市场社区化**：策略带 schema 版本号/依赖声明/评分与下载榜；文档站（vitepress，从 docs/ 起步）。
5. **文档同步机制**：测试数字/功能清单写进 CI 自动核对。✅ **已完成**：`scripts/ci_reconcile.py` 校验后端测试数与前端组件数，与本文档一致才放行 PR。

### 阶段 5：Agent 重建与深化（持续，**注意：后端已删，是重建而非深化**）⚠️
1. **重建 AgentCore + Provider**（OpenAI 兼容 / Anthropic）：会话落 `sessions/messages/llm_config`（复用孤儿表）。✅ **已完成（2026-08-16）**：`backend/agent/`（core/providers/tools/errors/default_tools）+ REST `app/routes/agent.py`（status/sessions/chat，缺 Key 转 503）+ MCP `register_agent_tools` + 前端 `Agent.jsx`（会话列表+对话，未配置显式引导）。

## 五、建议执行顺序（务实路线）

1. **立刻可做、零风险**：阶段 0 收尾（孤儿表标注 + 文档同步）+ 阶段 4 的 CI 配置（纯 YAML）。
2. **核心差距、最高 ROI**：阶段 1（A 股金融正确性）—— 纯自研、可测、直接决定“能否称专业”。
3. **架构地基**：阶段 2（存储/内存/风控数据源）—— 为高频与多账户铺路。
4. **研究深度**：阶段 3（因子/组合/walk-forward/归因）—— 对标 qlib/QUANTAXIS。
5. **生态扩张**：阶段 4 券商/数据接入（视 SDK 可用性）。
6. **差异化护城河**：阶段 5 Agent 重建（独立大项）。
