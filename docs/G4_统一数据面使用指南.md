# G4 统一数据面使用指南（dataHub）

> 交付物：后端 `GET /api/v1/datahub/policies` 策略表 + 前端 `lib/dataHub.js`
> topic 总线。5 个试点页（MarketData/Boards/Etfs/IndexOverview/Rotation）已接入，
> 同一 topic 在刷新周期内不产生重复网络请求。

## 概念

- **topic**：数据订阅的键（如 `market:boards:industry:by_change_pct`）。
- **策略表**（后端单一真源）：每个 topic 前缀的 `ttl_ms`（缓存有效期）、
  `min_interval_ms`（最小请求间隔，节流）、`coalesce_within_ms`（合并窗口——
  窗口内多个订阅共享一次请求）、`priority`、`stale_ok`。
- **subscribe(topic, fetcher, cb)**：订阅。首次触发 fetcher 拉取，缓存期内重复
  订阅直接回调缓存快照（`{data, stale}`）。
- **peek(topic)**：同步读缓存（无缓存返回 null，不触发请求）。
- **invalidate(topic)**：手动失效（页面「刷新」按钮用它 + 重订阅）。

## 何时用 subscribe vs peek vs 直接 api

| 场景 | 选择 |
|---|---|
| 页面主数据（多次进入、数据变化慢） | `subscribe`（享受缓存/合并） |
| 需要「当前缓存立即给我，没有就拉」 | `peek` 后补 `subscribe` |
| 用户高频操作型数据（提交/删除后自刷） | 直接 `api.xxx` + 本地刷新（避免缓存干扰） |

## 新增页面接入模板

```js
import { subscribe } from "../lib/dataHub.js";

const unsub = subscribe(`market:boards:${kind}:${sortBy}`, () =>
  api.marketBoards({ kind, sort_by: sortBy }),
  (r) => setRows(r.data || []),
);
// 组件卸载时 unsub()
```

新 topic 前缀请在 `app/routes/datahub.py` 策略表登记（否则用 default 策略）。
