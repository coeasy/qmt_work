# 第 20 轮 · 客户端「启动 / 退出」机制修复

> 日期：2026-09-22
> 用户报障原文：「关闭客户端，在右小角没有展示图标，无法真实退出，需要修复客户端 启动退出机制，完善客户端能力，修复所有问题之后，重新构建客户端」

---

## 0. 一句话结论

**托盘图标没被打进 asar，导致托盘建不起来；而「关闭」的语义是「隐藏到托盘」，
于是窗口一关就再也没有任何退出入口 —— 这是一条自锁死的缺陷。**
本轮把它从根因（构建配置）到兜底（内嵌图标 + 关闭即退出 + 应用内退出入口）整条修完，
并补上 25 条护栏防止复发。

---

## 1. 根因链（逐环实测）

| # | 环节 | 事实 |
|---|---|---|
| 1 | 构建配置 | `electron-builder.yml` 的 `files` 只有 `electron/**/*` + `package.json` ⇒ `build/icon.png` **没进 asar**。实测 `asar list` 共 **1531** 条，`build/` 与 `icon.*` 命中 **0** 条 |
| 2 | 运行时路径 | 打包态 `__dirname` = `resources/app.asar/electron`，而 `trayIcon()` 找的是 `path.join(__dirname, "..", "build", "icon.png")` = `resources/app.asar/build/icon.png` ⇒ 不存在 |
| 3 | 级联失效 | `trayIcon()` 返回 `createEmpty()` ⇒ `icon.isEmpty()` 为真 ⇒ `createTray()` **直接 return** ⇒ **托盘不存在** |
| 4 | **自锁死** | `win.on("close")` = `e.preventDefault(); win.hide()`，而 `quitting` **只由托盘菜单的「退出」**置位 ⇒ 托盘不在时，「关闭」是**单向隐藏**：窗口消失、托盘没有、**再无任何退出入口** ⇒ 只能进任务管理器 |

### 为什么这个缺陷躲过了所有既有检查

每一行代码**单独看都是对的**：`trayIcon()` 的路径拼接对、`createTray()` 的空值判断对、
`win.on("close")` 的隐藏语义对。缺陷只存在于「**构建配置**」与「**运行时路径约定**」
之间 —— 单测、`tsc`、人工 code review 全都看不见。

这类缺陷**只能**由「把构建配置当契约来断言」守住。本轮的 25 条护栏里，
第 1 组（构建配置）就是为此而设。

### 另一个放大因素

**Windows 11 默认把新出现的托盘图标收进「隐藏的图标」溢出层**，用户看不见它。
所以即便托盘建起来了，**退出入口也绝不能只依赖托盘的可见性**。

## 2. 修复清单

### 2.1 根因：把托盘图标真正打进产物（`electron-builder.yml`）

```yaml
files:
  - "electron/**/*"
  - "package.json"
  - "build/icon.png"          # ★ 新增：托盘图标必须进 asar
extraResources:
  - from: ../backend/dist
    to: backend
  - from: build/icon.png      # ★ 新增：asar 外的第二条冗余路径
    to: build/icon.png
```

> ⚠️ **`directories.buildResources: build` 只决定「安装包 / EXE 用哪个图标」，
> 不会把它塞进 asar** —— 这两件事必须分开配。这是本次踩到的认知盲点。

### 2.2 兜底：内嵌图标 + `trayAvailable` 语义（`electron/main.cjs`）

- 新增 `TRAY_ICON_PNG_B64`（16×16 / 32×32 的 RGBA PNG base64）。
- `trayIcon()` 改为三级降级：`asar 内路径` → `resourcesPath 路径` → **内嵌 base64**。
  任何一步失败都继续往下，**永不静默返回空图**。
- 新增 `let trayAvailable = false`，**只有 `new Tray()` 成功之后**才置 `true`。

### 2.3 解锁自锁死：托盘不可用时「关闭」= 真退出

```js
win.on("close", (e) => {
  saveWindowState();
  if (quitting) return;
  e.preventDefault();
  if (!trayAvailable) { requestQuit(); return; }   // ★ 解锁点
  win.hide();
  hintTrayOnce();
});
```

同时 `app.on("window-all-closed")` 也加了同款兜底 —— 否则会以「无窗口」形态残留。

### 2.4 退出入口多路化（不依赖托盘可见性）

| 入口 | 通道 | 说明 |
|---|---|---|
| 托盘右键 → 退出 | `requestQuit()` | 主路径 |
| **应用内菜单栏 → 退出** | `app-quit` IPC | **新增**，走 `ConfirmModal` 二次确认 |
| **Ctrl+Q / Cmd+Q** | `before-input-event` | **新增**，本地快捷键（不占 `globalShortcut`） |
| 托盘不可用时的「关闭」 | `requestQuit()` | 兜底 |

`window-close`（隐藏到托盘）与 `app-quit`（结束进程）**语义严格区分，不许合并**。

### 2.5 顺带修掉的两个启动机制缺口

1. **单实例守卫缺失**：`app.quit()` 在 ready **之前**调用只是「预约退出」，
   `whenReady()` 依然会 resolve ⇒ 第二个实例照样 `startBackend()` + `createWindow()`，
   起出第二个后端（端口自动 +1、抢同一份 SQLite）再被退出流程杀掉。
   → 在 `whenReady()` 回调开头加 `if (!gotLock) return;`。
2. **托盘提示端口恒错**：托盘在 `createTray()` 建好，而 `activePort` 要等
   `waitReady()` 健康检查成功才知道（端口被占用会自动 +1）。旧实现只在建托盘时
   `setToolTip` 一次 ⇒ 端口一旦不是默认值，**托盘提示永远是错的**。
   → 抽出 `refreshTrayTooltip()`，在 `activePort` 定下来后调用。

## 4. 本轮新增硬约束

1. **★★ `directories.buildResources` ≠ 打进 asar**。前者只决定安装包 / EXE 的图标；
   要在运行时用 `path.join(__dirname, ...)` 读到的文件，**必须**写进 `files`。
2. **★★ 「关闭即隐藏」必须以「托盘真的建起来」为前提**。否则窗口一关就是单向隐藏，
   用户只能进任务管理器。判据必须是运行时事实（`trayAvailable`），不是「应该建起来了」。
3. **★★ 退出入口不能只依赖托盘的可见性**。Windows 11 默认把新托盘图标收进溢出层，
   用户看不见 ⇒ 必须有应用内入口 + 快捷键。
4. **★ `app.quit()` 在 ready 之前调用只是「预约退出」**，`whenReady()` 仍会 resolve
   ⇒ 单实例守卫必须写在 `whenReady()` 回调**内部**，光在顶层 `app.quit()` 不够。
5. **★ 内嵌 base64 兜底本身也要测**：抄错一个字符 `createFromDataURL` 就静默返回空图，
   兜底等于没有。断言必须解出 PNG magic + IHDR 尺寸 + IEND。
6. **★ 自绘标题栏里的按钮必须显式 `-webkit-app-region: no-drag`**，
   否则鼠标事件被系统拿去拖窗口 —— 表现为「点了没反应，还把窗口拖走」。
7. **★ 托盘提示里的端口要随 `activePort` 刷新**：端口被占用会自动 +1，
   建托盘时 `activePort` 还是默认值。
8. **★ 并行对同一文件发两次 Edit 会互相覆盖**（第二次写回时用旧快照冲掉第一次）。
   实测：`main.cjs` 的两处修改只落地了一处，而工具**两次都报 success**。
   ⇒ 同一文件的多处修改必须**串行**，改完用 `grep` 复核。

```
⨯ write ...\dist-electron\win-unpacked\electron.exe: There is not enough space on the disk.
```

#### Ctrl+Q 那条 FAIL 是探针错，不是产品坏（判别实验）

用 puppeteer 的 `page.keyboard.press` 发 Ctrl+Q 没有退出。按项目纪律
「报 FAIL 前先怀疑探针」，做了判别实验：**用同一个 CDP 通道发 F12**，
看主进程里另一个已知可用的 `before-input-event` 处理器（`F12 → toggleDevTools`）
会不会触发。

```
devtools 目标：0 → 0
⇒ CDP 按键【不经过】before-input-event（探针局限）
```

结论：CDP 注入的按键不经过 Electron 的 `before-input-event`。换真实键盘
（Win32 `keybd_event` + 先 `SetForegroundWindow`）后**一次通过**。

### 6.4 本轮新增硬约束（第 9–12 条）

9. **★ P: 盘必须留 ≥5GB 余量**。P: 占满时 electron-builder 在写
   `win-unpacked/electron.exe` 时报 `There is not enough space on the disk`，
   而**前端与 PyInstaller 都已成功** —— 失败点只在最后一步，极易误判成配置错。
   可回收项：`output/_live_db3`、`output/_prebuild_backup`。
10. **★ 释放磁盘要「移动」不要「删除」**：`mv` 到另一块盘既释放又可逆；
    `rm -rf` 会撞删除护栏且不可逆。
11. **★ CDP 注入的按键不经过 `before-input-event`** ⇒ 用 puppeteer 测 Electron
    快捷键**必然假红**。判别实验：同通道发 F12，看 `/json/list` 有没有
    `devtools://`。测快捷键必须走 Win32 `keybd_event`/`SendInput`，且先聚焦窗口。
12. **★ 前端/后端产物可复用**：`bash build_all.sh --desktop-only` 跳过 Step 1/2
    （复用 `backend/static` 与 `backend/dist`），只重跑 Electron 打包，省 ~10 分钟。
