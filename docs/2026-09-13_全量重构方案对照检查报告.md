## 5. 需要关注的问题

### 5.1 实盘交易风险（P0-1/2/3/5/7/8 共 6 项未修）

| 问题 | 后果 |
|------|------|
| P0-1 WAL 写后 | 下单成功后崩溃 → 委托永久失联，对账查不到 |
| P0-2 风控双执 | 频率/日额度**翻倍消耗**，正常单被提前误拦 |
| P0-3 引擎无幂等 | 重启后重复触发即**重复下单** |
| P0-5 资金非原子 | 并发多单同时通过占比闸门 → **超仓/超资金** |
| P0-7 webhook 空密钥 | 未配置 secret 即可**实盘下单** |
| P0-8 watchdog 撤单 | 无 WAL 记录，崩溃后无法重放撤单 |

> **建议**：这 6 项改动面较大且触及下单主链路，建议单独排期、每项配回归测试后再动。

### 8.1 10 条 E2E 流程：0 → 10（+1 条清单元验收）

**做法**（不是单元测的堆砌，而是「链路」验收）：

### 8.2 E2E 实测发现并修复的真实缺陷

**`POST /algo/{algo_id}/cancel` 未 await 协程**（`app/routes/algo.py:60`）：
`AlgoEngine.cancel` 是 `async def`，路由直接 `ok(engine.cancel(aid))` 包装 →
FastAPI 序列化一个 coroutine 对象 → 端点恒定失败。
表现为「前端点『取消算法单』没反应且无报错」。已改为 `await`。
（同批排查了 `paper.reset` / `strategy_run.start|stop` / `trade.conditions.*`，均为同步方法，无同类问题。）
