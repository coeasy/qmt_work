## 4. 优化改进方案

按「投入/收益」排序，P0 为低成本高确定性，P2 需决策或较大改动。

### P0 一致性修订（30 分钟内，低风险）

1. **统一页面数**：`README.md` 顶部与结构章节全部改为 **31**。
2. **重写「项目结构」组件清单**：以 `pagesRegistry.jsx` 的 31 个页面为准重新枚举，删除过时描述。
3. **`.gitignore` 追加 `.pytest_cache/`**（根 + backend）。

> 产出：README 与代码库完全对齐，消除用户侧误导。

### P1 死代码与技术债清理

4. **删除孤儿组件 `components/Hub.jsx`**：先 Grep 确认零引用（本轮已确认），删除后跑 `npm run build` 与 vitest 回归。
5. **echarts 按需分包**：
   - 方案A（推荐，见效快）：`echarts/core` + `echarts/charts` + `echarts/components` + `use([Chart, Line, Bar, Candlestick, Scatter, Gauge...])`，将 big-bundle 从 ~1MB 压到数百 KB。
   - 方案B：可选的按需 import 替代全量 `import * as echarts`，成本略高需逐页面核对。
   - 验收：`charts-*.js` 体积显著下降，各 K 线/图表页面渲染回归通过。
6. **消除弃用告警**（非阻断，可择机）：
   - `starlette.testclient` + `httpx` → `httpx2`（或在测试层确认兼容）
   - `authlib.jose` → `joserfc`（fastmcp 内部，通常随依赖升级解决）

### P2 需决策事项

7. **eltdx 商用路径最终决策**（务必处理，见 `THIRD_PARTY_LICENSES.md`）：
   - 维持研究用途 → 保持现状 + 在发布说明显著声明非商用。
   - 走商业化 → 替换为许可清晰的数据源（如自建行情缓存 / 合规券商源），或改为「安装时勾选非商业用途」。
   - 无论哪种，建议在 CI 增加「构建产物不含 eltdx」检查命令（licenses 门禁已有，可加产物扫描）。

### D 类增强（视资源排期）

8. **本地 pre-commit 挂 drift + classnames 门禁**：复用现有脚本，提交前 3 秒内完成。
9. **GlobalSearch 键盘导航**：↑/↓ 移动高亮、Enter 打开选中项。
