## 0. 对设计文档的两处勘误（先修正认知）

1. **`Hub.jsx` 不删除，改为复用**。它就是「一个中心页内多子页签」的通用容器（未激活子页签自动卸载、支持外部 `hub:switch` 事件切换）。之前判它孤儿是因为没有任何中心页挂载它——阶段一正是要挂载它。`lib/trade.js` 的 `quickTradeNavigate` 至今仍在派发 `hub:switch {hub:"trade"}` 事件，契约是活的。
2. **顶层页数修正：21 个**（设计文档写 18 是笔误）。构成：15 个直达页 + 6 个中心页（Hub 包装）。31 个能力入口一个不少（15 直达 + 16 子页签）。

## 3. 任务分解（按执行顺序，每步可独立验证）

### Task 1：key 别名兼容层（安全地基，先行）

**文件**：[pagesRegistry.jsx](file:///p:/github_public/qmt_work/frontend/src/pagesRegistry.jsx)（新增导出）、[nav.js](file:///p:/github_public/qmt_work/frontend/src/lib/nav.js)、[workspace.jsx](file:///p:/github_public/qmt_work/frontend/src/store/workspace.jsx)

1. `pagesRegistry.jsx` 新增：
   ```js
   // 旧 key → 新 key 归一（导航/持久化/迁移三处共用）
   export const KEY_ALIAS = {
     boards: "mktstructure", etfs: "mktstructure", index_overview: "mktstructure", rotation: "mktstructure",
     strategies: "strategy_hub", strmarket: "strategy_hub",
     factors: "factor_hub", research: "factor_hub",
     signal: "automation", alerts: "automation", notifications: "automation", webhooks: "automation",
     reference: "datacenter", markettools: "datacenter",
     audit: "audit_recon", reconcile: "audit_recon",
   };
   export function resolveKey(key) {
     const k = KEY_ALIAS[key] || key;
     return PAGES[k] ? k : DEFAULT_PAGE;
   }
   ```
2. `nav.js`：`normalizeNavDetail` 内字符串/对象分支都过 `resolveKey()`；旧 key 携带的子页签信息写入 `params.tab`（如 `navTo("boards")` → `pageKey:"mktstructure", params:{tab:"boards"}`）。
3. `workspace.jsx`：
   - `makeLeaf`/`sanitizeTree`/reducer `OPEN` 分支统一走 `resolveKey`；
   - `loadState` 增加一次性迁移 `migrateLeafKeys(state)`：遍历 tabs 的所有叶子，`KEY_ALIAS[leaf.pageKey]` 命中的改写为新 key 并把旧 key 写入 `leaf.params.tab`，包在 try/catch 内（失败回退默认，与现有 schema 兜底一致）。这样老用户 localStorage 里的「板块行情」tab 升级后自动变成「市场结构·板块页签」。
4. **验证**：`npx vitest run src/lib/__tests__/nav.test.js`；新增用例见 Task 6。

### Task 3：六个中心页组件（新增，均为薄包装）

**新增文件**：`frontend/src/components/hubs/`
- `MarketStructureHub.jsx` — tabs: boards(板块行情)/etfs(ETF基金)/index_overview(指数分析)/rotation(板块轮动)，`hubKey="mktstructure"`，`initial` 取 `props.params?.tab`
- `StrategyHub.jsx` — tabs: strategies(生成与运行)/strmarket(市场与导入导出)，`hubKey="strategy_hub"`
- `FactorHub.jsx` — tabs: factors(指标)/research(IC与归因)，`hubKey="factor_hub"`
- `AutomationHub.jsx` — tabs: signal(信号路由)/alerts(告警规则)/notify(通知与集成)，`hubKey="automation"`；`notify` 子页签纵向堆叠 `<Notifications/> + <Webhooks/>`（两块各带自己的卡片标题，Phase 1 不做组件内部融合）
- `DataCenterHub.jsx` — tabs: markettools(行情数据)/reference(参考数据)，`hubKey="datacenter"`
- `AuditReconHub.jsx` — tabs: audit(审计日志)/reconcile(对账核销)，`hubKey="audit_recon"`

统一写法（模板）：
```jsx
import Hub from "../Hub.jsx";
import Boards from "../Boards.jsx"; // ... 等 lazy 引入
export default function MarketStructureHub({ params }) {
  return (
    <Hub
      hubKey="mktstructure"
      initial={params?.tab}
      tabs={[
        { key: "boards", label: "板块行情", comp: Boards },
        { key: "etfs", label: "ETF 基金", comp: Etfs },
        { key: "index_overview", label: "指数分析", comp: IndexOverview },
        { key: "rotation", label: "板块轮动", comp: Rotation },
      ]}
    />
  );
}
```
注意：Hub 的 `comp` 传函数组件（`typeof === "function"`）即可，无需再包 `lazy`（外层 pagesRegistry 已对该 Hub 页做 lazy 分包）。

## 5. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 老用户 localStorage 旧 key 叶子被 sanitize 成 dashboard | Task 1 的一次性迁移 + 现有 schema 校验双兜底；迁移在 try/catch 内 |
| Hub 卸载未激活子页签导致子页内部状态（筛选条件）丢失 | 与 Hub 既有设计一致（停止轮询的代价）；后续可加 sessionStorage 保留，本阶段不做 |
| classnames 门禁拦截 Hub 新类 | Task 2 先行确认/补样式 |
| `useHotkeys` 数字键分组变 7 个 | 行为自动适配，验收手工确认 |
| 漏改某个 `PAGES[旧key]` 消费点 | 全仓 grep 旧 key（Task 4 验收步骤）+ vitest 遍历用例兜底 |

**回滚**：整体一个 commit（或 2 个：兼容层+Hub 中心页 / 文档收尾），`git revert` 即可完全回退；无数据迁移副作用（localStorage 兼容层是单向宽容的——新 key 不在 KEY_ALIAS 里，原样通过）。
