## 2. R1：GitHub 发布后自动构建安装包

### 2.1 现状核查

`release.yml` 确实在 `release: published` 时构建 —— 但**构建出来的包是坏的**，且 CI 全绿。
这类「自动构建成功但包不可用」正是最该盯的断链。

### 2.2 三处断链

| # | 断链 | 证据 | 影响 |
|---|---|---|---|
| C1 | `backend/runtimes/`（嵌入 Python 3.8–3.12，**336 MB**）在 `.gitignore` 内 | `git check-ignore -v backend/runtimes` 命中；`git ls-files backend/runtimes` 为空 | CI 检出后**没有运行时** ⇒ 桥接不可用 |
| C2 | `build_exe.py` 对缺失运行时**只打印「跳过」** | `_verify_bridge_imports`：`if not runtimes.is_dir(): print("跳过…"); return` | 装完连不上券商，而**发布流程显示成功** |
| C3 | `build-client.yml` 上传 `frontend-next/release/*` | electron-builder 的 `directories.output` 是 `dist-electron` | 上传的 Release 资产**恒为空** |

### 2.3 修复

1. **`backend/tools/fetch_runtimes.py`**：新增 `--with-deps`（pip 装桥接闭包依赖
   `cryptography / pydantic / pydantic-settings / psutil` —— 裸 embed 包不含这些，
   子进程 `import cryptography` 会直接炸）与 `--strict`（任一目标失败即非 0 退出）。
2. **`backend/build_exe.py`**：新增硬闸门。
   ```python
   REQUIRE_RUNTIMES = os.environ.get("QMT_BUILD_REQUIRE_RUNTIMES", "0") == "1"
   if REQUIRE_RUNTIMES and not runtimes_dir.is_dir():
       raise SystemExit("构建中止：CI 要求嵌入 Python 运行时，但 runtimes/ 不存在…")
   ```
   `_verify_bridge_imports` 同级地把「跳过」改成「失败」，并校验 `cryptography` 可导入。
3. **`.github/workflows/release.yml`**：重写为
   `备运行时（--with-deps --strict）→ 前端 build → 后端 EXE（QMT_BUILD_REQUIRE_RUNTIMES=1）
   → 打包 zip + NSIS → 产物结构核验 → 上传资产`。
4. **`.github/workflows/build-client.yml`**：上传路径改 `dist-electron`，匹配 `*.zip/*.exe/latest*.yml`。

### 2.4 验证

以 `QMT_BUILD_REQUIRE_RUNTIMES=1` 在**无 runtimes** 的模拟环境下执行构建脚本，
**必须以非 0 退出**（实测已拦下）；本地有运行时则正常通过。造了探针验证闸门真的会拦，
而不是「看起来拦了」。

## 3. R2：控制流 / 生命周期 / 资源

### 3.1 三个引擎同步调用 async 回调（最严重）

```python
def _emit(self, event: dict) -> None:
    if self._on_event:
        try:
            self._on_event(event)      # ← _on_event == ws_manager.broadcast (async)
        except Exception:
            pass
```

`algo` / `limitup` / `condition_order` 三处同款。后果两层且**都不报错**：
事件**静默丢失**（前端只能轮询）＋ 每次 GC 一条 `coroutine was never awaited`。
**为什么长期没被发现**：护栏 `test_emit_event.py` 只扫 `gateway/`（因为缺陷最早是在
`health.py` 里发现的），engines 从未被纳入。

修复：三处改用 `core.emit.emit_event(self._on_event, {...})`（唯一出口，自动
`create_task` 异步回调）。**并把护栏升级**：AST 全量扫描（不用正则，避免注释/字符串
误报 —— 这是本项目的既有教训）＋ 扫描面扩到 `engines/` + `switch`。随后注入探针
验证护栏**真能拦下**违规写法。

### 3.2 停机漏停能下单的引擎

`shutdown.py` 停了 condition/limitup，但**漏了 `algo_engine` 与 `strategy_runtime`**。
两者都会真实下单：停机后仍在跑的拆单/策略任务会继续发单。已补，且严格排在
`db.close()` 之前。

### 3.3 冷仓搬移无上限（TD-25 同族）

`cold_store.migrate_from` 是 `while True`，每批搬完只看「这批是否满」，不设总量上限；
且跑在启动期线程里。已加 `max_batches` 与无进展退出，调用点改 **daemon 线程 + 有界等待**。

### 3.4 静态复核结果

| 扫描项 | 数量 | 结果 |
|---|---|---|
| `while True` / 条件循环 | 44 | 除 4 处外全部有 sleep/wait/有界退出；4 处已修 |
| `threading.Thread(` | 17（源码 2 处 + 第三方随包） | 业务线程**全部** `daemon=True` |
| 跨日缓存 | `sync/_order_fp`、`_deal_seen` | 按交易日 clear ✓ |
| WS 环形缓冲 | `WSManager._recent` | `deque(maxlen=3000)` ✓ |
| 批处理缓冲 | `_batch_buf`、`_batch_rows` | ❌ 无界 → 已改 `deque(maxlen=20000)` |
| 翻页循环 | `aggregates.py` | 有界（空页 / `has_more` false / 800 上限）✓ |

### 3.5 停机永久卡住（TD-25 同族，第 2 处）

`_RWLock.write()` 的 `self._cond.wait()` **没有超时**；`db.close()` 在其上做
`wal_checkpoint(TRUNCATE)`。只要某后台线程持写锁做慢操作，**进程就永远退不出去**。
已给 `write()` 加 `timeout=` 参数，`close()` 用有界获取（`QMT_DB_CLOSE_TIMEOUT=5`），
超时则跳过 checkpoint（WAL 下次打开自愈，数据不丢）。

### 4.2 参数名漂移（会返回静默错误数据）


```python
# 后端
async def reference_sector_stocks(sector: str = "沪深A股"): ...
```

## 8. 遗留与建议

1. **门禁盲区**：`check_api_contract_drift.py` 只核**路径存在性**，不核**参数名/取值**。
   §4.2 的 `code`/`sector` 漂移正是从这个盲区漏出去的。建议后续增加
   「前端 query/body 键 ⊆ 后端签名参数名」的静态核对。
2. **`check_frontend_classnames.py` 已是空转**（旧 `frontend/` 退役后直接 `[SKIP]` exit 0），
   不再提供任何保护。若需要等价的「样式类名缺失」防护，应针对 `*.module.css` 重写。
3. **3 个指标/图表端点是 UI 盲区**：能力可达（REST + MCP），但前端不消费。
   要么接回，要么在 `/capabilities` 层面标为 API-only，避免读者误判。
4. **两处 TD-25 同族**（`db.close` 无界锁等待、冷仓搬移无上限）已修；建议在
   `TECH_DEBT.md` 归纳为一条「**停机路径禁止无界等待**」的通用纪律。
