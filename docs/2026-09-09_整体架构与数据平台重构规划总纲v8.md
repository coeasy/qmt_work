# QMT Work 整体架构与数据平台重构规划总纲 V8

> 日期：2026-09-09  
> 仓库：`coeasy/qmt_work`  
> 状态：当前统一规划总纲。V3–V7 保留作为阶段审计与演进记录；后续实施优先以本总纲为依据。  
> 目标：将 QMT Work 从“围绕 QMT 的本地量化工作台”升级为“插件化、多行情源、多交易连接、本地优先、可离线研究、可持续同步、可审计实盘”的量化研究与交易平台。

---

# 1. 最终产品定位

QMT Work 的最终定位为：

> **插件化、多行情源、多交易客户端、本地优先的量化研究与交易平台。**

核心原则：

1. QMT 是首个重点支持的交易/行情 Connector，但不是 Core 的宿主依赖。
2. 不连接 QMT 时，行情、历史数据、选股、指标、因子、研究、回测、策略设计、模拟盘仍应正常工作。
3. 行情数据源与交易执行源完全解耦。
4. 多行情源通过统一 Capability / Provider 体系接入，不把供应商逻辑写死进 Core。
5. 所有真实交易入口统一经过 ExecutionService，插件或页面不能绕过风控、WAL、审计和幂等。
6. 历史研究数据以本地统一数据仓为核心，每个交易日自动同步、校验、修复和发布数据快照。
7. 插件体系用于扩展能力，但 Mandatory Risk、Execution、WAL、Audit、Permission 等安全内核不允许被第三方插件替换。
8. 平台采用强边界 Modular Monolith，不为了“架构现代化”盲目拆微服务。
9. 所有重要行为改变都必须增加对应 CI/契约/回归门禁。

# 4. Data Plane：多行情源平台化

## 4.1 DataSource 不再是“万能接口”

统一拆成能力端口：

```text
QuoteSnapshotPort
QuoteStreamPort
HistoricalBarsPort
InstrumentDirectoryPort
InstrumentDetailPort
TradingCalendarPort
CorporateActionPort
AdjustmentFactorPort
FundamentalPort
FinancialStatementPort
BoardSectorPort
MoneyFlowPort
NewsPort
```

一个 Provider 只实现自己真实拥有的能力。

禁止为了满足接口而返回 mock / 空壳假数据。

## 4.2 Provider Manifest

每个数据源插件声明：

```text
id / version / provider type
markets
capabilities
freshness class
rate limits
license policy
network permissions
secret requirements
runtime requirements
```

Core 不再硬编码 `broker -> eltdx`。

## 4.3 Capability Router

从当前统一 `auto_chain` 升级为按能力路由：

```text
quote.snapshot      → Provider Route A
quote.stream        → Provider Route B
history.daily       → Provider Route C
instrument.list     → Provider Route D
financial.statement → Provider Route E
```

只有 `source=auto` 可以 fallback。

当用户显式指定 `source=qmt / baostock / eltdx / ...` 时，该源不支持能力必须明确返回 `UNSUPPORTED_CAPABILITY`，禁止静默换源。

## 4.4 数据溯源

继续强化统一 `DataResult`：

```text
results
source
as_of
stale
warnings
quality
provenance
```

多源字段富化时不能再只保留一个 `source` 字符串，应允许字段级或段级 provenance。

# 5. 历史数据仓与数据治理

## 5.1 LocalStore 是研究链核心，而不是展示缓存

研究主链：

```text
Provider
  ↓
Ingestion
  ↓
Raw Layer
  ↓
Normalize
  ↓
Quality Gate
  ↓
Canonical Layer
  ↓
Dataset Snapshot
  ↓
Screener / Factor / Backtest / Research
```

实时行情走独立 Live Path，不与全市场研究扫描混用。

## 5.2 立即修复 LocalStore latest-N 语义

当前 `ORDER BY dt ASC LIMIT N` 与“最近 N 根”语义冲突。

目标：

```text
内部倒序取最近 N 根
→ 输出恢复升序
```

并补边界测试，禁止再次回归。

## 5.3 多源 Raw 数据不能互相覆盖

当前 `(code, period, adjust, dt)` 主键不足以承载多源历史数据。

Raw Layer 至少要包含：

```text
provider_id
code
period
adjust
trade_time
payload/version
batch_id
fetched_at
checksum
quality_state
```

Canonical Layer 再根据质量规则选择最终值。

## 5.4 Dataset Snapshot

正式研究/回测必须支持：

```text
dataset_snapshot_id
calendar_version
corporate_action_version
adjustment_version
provider_policy_version
created_at
```

这样同一个回测结果可以复现，而不会因为第二天数据被修订而悄悄变化。

## 5.5 数据状态

历史数据增加：

```text
provisional
final
revised
invalid
```

EOD 第一次同步得到的数据可以是 provisional，完成对账后再进入 final。

# 6. 每日定时同步与 Scheduler Plane

“每天更新历史行情”必须成为系统基础设施，而不是用户手工点击。

## 6.1 现有 JobRuntime 的定位

保留其：

- 任务配额；
- 优先级；
- 进度；
- 取消；
- sync/screen/backtest runner。

但必须升级，因为当前运行状态主要在内存，不满足：

- 持久化；
- Cron；
- 重启恢复；
- misfire；
- retry；
- lease；
- heartbeat；
- interrupted recovery；
- missed-run catch-up。

## 6.2 新 Scheduler 架构

```text
Schedule Definition
       ↓
Durable Schedule Store
       ↓
Scheduler
       ↓
Durable Job Store
       ↓
JobRuntime
       ↓
Registered JobKind
```

Scheduler 不执行任意 shell 命令，只能调度平台注册 JobKind。

## 6.3 系统内置任务

至少提供：

```text
system.market.eod_history_sync
system.market.eod_reconcile
system.market.rolling_repair
system.instrument.sync
system.calendar.sync
system.corporate_action.sync
system.storage.maintenance
system.database.backup
```

## 6.4 每日历史行情同步

默认：

```text
时区：Asia/Shanghai
触发：交易日收盘后，例如 18:30
```

执行链：

```text
Exchange Calendar
    ↓
Instrument Universe
    ↓
Provider Capability Selection
    ↓
Chunk / Rate Limit
    ↓
Raw Ingestion
    ↓
Schema Normalize
    ↓
Data Quality
    ↓
Cross-Source Reconcile
    ↓
Canonical Publish
    ↓
Coverage Check
    ↓
DatasetSnapshot
    ↓
Screener / Factor Index Refresh
```

## 6.5 失败补偿

采用：

```text
at-least-once
+ idempotent writes
+ lease
+ checkpoint
```

失败状态：

```text
partial
retrying
failed
repaired
complete
```

客户端关机导致错过定时任务时，下一次启动执行 catch-up。

## 6.6 OS 级保障

仅依赖 Electron 进程不能满足“必须每天同步”。

长期支持：

```text
Windows Task Scheduler
macOS launchd
Linux systemd timer
```

桌面端安装器可选注册系统任务；未注册时仍依靠启动补偿保证最终一致性。

# 10. 前端架构

根状态从 Broker-First 改成 Platform-First：

```text
PlatformProvider
 ├── CapabilityProvider
 ├── DataProvider
 ├── QuoteHubProvider
 ├── TradingConnectionProvider
 ├── SchedulerProvider
 └── WorkspaceProvider
```

`TradingConnectionProvider` 可以为空，而 Data/Research 仍正常。

页面按 Capability Gate 控制：

- 行情/选股/研究页依赖 Data Capability；
- 账户/真实持仓/交易页依赖 Execution Capability；
- 未连接交易客户端时页面可打开，但交易动作禁用并明确说明原因。

长期目录：

```text
frontend/src/
├── app/
├── features/
│   ├── market/
│   ├── trading/
│   ├── broker/
│   ├── accounts/
│   ├── strategy/
│   ├── backtest/
│   ├── research/
│   ├── data/
│   ├── scheduler/
│   └── settings/
└── shared/
    ├── api/
    ├── ws/
    ├── events/
    ├── ui/
    └── types/
```

优先把交易、账户、持仓、Broker、策略执行、WS Event TypeScript 化。

FastAPI OpenAPI 生成 TS Client，减少手写 API 契约漂移。

```text
→ 账户
→ 持仓
→ 下单
→ 撤单
→ 成交回报
```

全部通过。

## 场景 E：QMT 深度能力

标准交易链走统一 Port；QMT 特有接口走 `vendor.qmt.*` Extension，不污染 Core。

# 23. 不做的事情

当前阶段明确不做：

1. 不拆微服务；
2. 不大规模机械移动目录；
3. 不一次性重写 React/TypeScript；
4. 不立即替换 SQLite；
5. 不把所有 Provider SDK 打进默认客户端；
6. 不允许插件绕过真实交易安全主链；
7. 不为了 CI 绿色降低测试、Ruff、安全或交易门禁；
8. 不用 mock 掩盖真实数据缺失；
9. 不让平台继续以“是否连接 QMT”决定整体 READY；
10. 不把定时同步实现成单一进程内 `sleep` 循环后宣称“可靠调度完成”。

# 24. 最终架构目标一句话

> **QMT Work 的 Core 负责标准数据模型、研究能力、任务调度和安全执行；Data Provider 负责“数据从哪里来”，Execution Connector 负责“订单往哪里去”，插件负责“能力如何扩展”，本地数据仓负责“研究如何稳定复现”，Scheduler 负责“数据如何每天持续保持完整”。**
