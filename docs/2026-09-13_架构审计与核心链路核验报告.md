## 0. 结论先行

| 问题 | 结论 |
|------|------|
| 核心功能是否全部实现？ | **大部分已实现且非空壳**。行情/交易/券商连接/风控/运维五大块均有真实代码（212 个 REST 端点、114 个 MCP 工具）。**但存在 2 处"假实现"级缺陷**：TDX 数据源全链失效、4 个前端 Hub 未注册导致约 12 个页面在生产环境不可达。 |
| 主体链路是否全部贯通？ | **链路骨架贯通，但交易链路的正确性保证未达标**。下单能从 UI 走到柜台，但 **WAL 是"写后"而非"写前"**、**风控被执行两次导致额度翻倍消耗**、**引擎路径无幂等**。这三项在实盘场景下可导致重复下单 / 委托失联 / 正常单被误拦。 |
| 前端质量门禁 | **红的**。`npx vitest run` 实测 3 个文件 5 个用例失败（含样式类名门禁），CI 前端检查形同虚设。 |
| 架构合理性 | 骨架合理（分层清晰、契约驱动、门禁意识强），但**存在 4 处结构性重复**：双状态容器、双数据源链、双连接抽象、双模拟盘实现。 |
| 是否可直接进入前端全面重构？ | **建议先修后端 P0，再重构前端**。前端重构会大量改动交互契约，若后端交易正确性问题未先收敛，重构期无法有效回归验证。 |

**一句话**：这是一个"工程化意识很强、骨架搭得好，但关键正确性细节失守、且前后端都有未清理的历史沉积"的项目。

## 3. 五条核心链路核验

### 链路 1：行情数据流 ✅ 贯通
`前端 → REST → DataSourceManager auto 链 → 每源 wait_for(8s) + 熔断 → 首个成功结果`
- **基本属实**，但「每源 8s 超时」对同步阻塞源**无效**：tstdx/baostock/akshare 用 `asyncio.to_thread` 包阻塞调用，`wait_for` 只取消协程，**线程继续占用**（`optional_sources.py:26,118`；`akshare_source.py:64,107`）。
- tstdx 硬编码 IP `119.147.212.81:7709`，超时后线程/连接泄漏。
- **实时链路无跨源校验**：首成功即返回，reconcile 仅在离线 job。

### 链路 2：交易执行 ⚠️ 贯通但正确性失守
`OrderTicketModal → SignalRouter（风控+幂等+WAL）→ ExecutionService → BrokerAdapter → 桥 → 柜台`

逐环核实：
- ✅ UI → `/trade/order` → `signal_router.submit` → `route()` → 风控 → `_live` → `ExecutionService.place_order` → `bridge.call_locked` → `trader.order_stock`（加锁）
- ❌ **WAL 在下单成功之后才写**（`signal_router.py:291` 下单 → `:310` 写 WAL）
- ❌ **风控被执行两次**：`route()` 一次（`:160`）+ `ExecutionService` 一次（`execution.py:74`）
- ❌ **幂等不在 `route()` 内**：仅当 `submit()` 显式传 `idempotency_key` 才包 `single_flight`；引擎路径（algo/condition/limitup/rebalance/strategy/target）**均不传**

### 链路 3：多 Tab 前端 ✅ 贯通
`eventBus → workspace dispatch OPEN → LRU keep-alive(8) → 非激活 display:none 常驻 DOM`
- **基本属实，但一处描述错误**：非激活 Tab 用的是 `visibility:hidden`（`styles.css:745`），不是 `display:none`（DOM 常驻、尺寸保留）。
- 逐出 tab 仅恢复 `params`，**本地 UI state（滚动/输入/drawings）丢失**。
- 每个 Tab 调 `useQuotes`，最多 24 个 WS 订阅（`Workbench.jsx:192`）。

### 链路 4：券商连接 ✅ 贯通（描述需更正）
`BrokerManager → 专属线程桥 → (bridge_server) → adapter`
- 无 `adapter.connect()`；`bridge_server` 仅在 ABI 不兼容时启用。
- 活跃连接**全局唯一**（`_active_id`），不支持按账户并发。
- **重连期间下单直接失败**，无排队/幂等缓冲。

### 链路 5：启动编排 ✅ 贯通（关闭非逆序）
`6 阶段（DB → 券商 → 引擎 → 看门狗 → WAL 重放 → 杂项）`
- 阶段划分属实（`app/main.py:161-168`），Required/Optional 分层明确。
- ❌ **关闭非逆序**：`bootstrap/shutdown.py:21-116` 为手写扁平序列，与文件头声明的逆序不符，且**无 `db.close()`**。
- ❌ 你描述的「WAL 重放」实际**只重放算法单**：`replay(handlers)` 从未被启动流程调用，条件单走 DB 恢复。文档宣称的"重放委托/条件单"不实。

### P0 — 实盘风险 / 门禁失效

## 5. 重构方案纲要

### 5.1 总体策略

**分三阶段推进，前端重构不以牺牲交易正确性为代价：**

```
阶段 A（前置·必须先做）  后端 P0 收敛 + 门禁转绿
        ↓
阶段 B（主体）           前端 UI 层全面重建（对标专业客户端）
        ↓
阶段 C（收尾）           架构去重 + 文档口径重建
```

理由：前端重构会大规模改动交互契约（下单流程、二次确认、状态展示）。若 P0-1/2/3/5 未先修，重构期间**无法区分"重构引入的 bug"与"既有的正确性缺陷"**，回归验证失去意义。

### 5.2 阶段 A：后端 P0 收敛（建议 2 周内）

| 动作 | 对应问题 | 验收标准 |
|------|----------|----------|
| WAL 改为**写前日志**：下单前写 intent，成功后写 result | P0-1, P0-4 | 崩溃注入测试：kill -9 后重启，对账能发现未完成 intent |
| 风控**单点执行**：只保留 `SignalRouter` 一处，`ExecutionService` 改为纯执行器 | P0-2 | 频率/日额度计数与下单数 1:1 |
| 引擎路径**强制幂等**：`route()` 内部生成幂等键（source+code+side+vol+price+时间窗） | P0-3 | 同一信号重复投递只产生 1 笔委托 |
| 手动单**接入二次确认**：`auto_confirm` 改为按配置决定，或区分"人工单/引擎单"两条策略 | P0-5 | 大额手动单触发 TOTP |
| 资金/仓位检查**原子化**：下单锁内复查，首快照前拒绝下单而非用演示值 | P0-6 | 并发压测不超仓 |
| 模拟盘**统一**为 `PaperEngine` 单实现，复用同一风控 | P0-7 | paper 与 live 走同一风控代码路径 |
| 修正 `pytdx` → `tstdx` 标识 | P0-8 | tstdx 进入能力链，`test_default_chain_order` 更新 |
| 前端测试转绿（含类名门禁） | P0-9 | `npm test` 0 失败 |
| 注册 4 个 Hub 或明确下线其组件 | P0-10 | 无不可达页面组件 |

### 5.3 阶段 B：前端 UI 层重建（主体工作量）

**对标目标**：通达信（多窗口/多周期联动/快捷键）、大智慧（盘口深度/画线）、东方财富（信息密度/自选股体系）

能力缺口（按对标目标）：

| 缺口 | 现状 | 目标 |
|------|------|------|
| 多窗口/多屏 | 单 BrowserWindow | Electron 多窗口 + 拖出 + 位置持久化 |
| 可拖拽分栏 | 固定等分 | splitter + 比例持久化 + 双击最大化 + 窗格互换 |
| 多周期/多图联动 | 仅指标广播 | 十字光标跨窗同步 + 时间轴对齐 + `echarts.connect` 分组 |
| 专业盘口 | 仅五档基础 | 逐笔成交 + 买卖队列 + 分时叠加 |
| 画线工具 | 有 drawings 雏形 | 斐波那契/通道/形态 + 持久化 |
| 行情表格性能 | 仅 Screen 虚拟化 | 全表虚拟滚动 + 单元格级增量更新 |
| 快捷键体系 | 90 行 | 通达信式（代码直达 / F5 周期循环 / 数字键） |
| 主题与个性化 | 仅暗色 | 多主题 + 涨跌色切换 + 布局模板导入导出 |
| 设计系统 | 单文件 CSS | 令牌 + 组件层（Button/Table/Chart 容器） |

### 5.4 阶段 C：架构去重与文档重建

- 统一状态容器：废弃 `core/state.py` 模块级单例，收敛到 `AppContext`
- 统一数据源链：`_auto_chain` 与 `resolve_chain` 合并为单一真源
- 清理 `connectors/` + `plugins/` 死代码（或接线）
- 重建文档口径：页数/组件数/能力数由 `ci_reconcile.py` 守门
