# qmt_work 功能体系设计（2026-08-31）

> 建立日期：2026-08-31 · 依据当前代码库实测盘点（31 个页面 / 167 个 `api.*` 方法 / 9 大功能分组 / 105 个 MCP 工具）。
> 定位：对现有功能做「保留 / 合并 / 降级 / 扩展」的全量决策，并给出**全新功能体系的目标结构、页面映射与迁移路线**。
> 参照系：通达信 / 大智慧（界面范式）· 东方财富（资讯与选股）· 专业量化终端（研究链路）。
> 设计铁律（继承自项目既有约束）：真实券商数据无 mock、连接可靠性为根本、零删除可用能力（只重组不砍功能价值）。

---

## 1. 设计总纲

### 1.1 一句话定位

**qmt_work = 多券商交易执行终端 + 量化研究工作台**，核心价值链只有一条：

```
连得上（券商连接） → 看得清（行情） → 下得去（交易执行） → 算得明（研究回测） → 管得住（风控运维）
```

一切功能决策以这条链为主轴：链上的功能是「必须功能」；服务链路的横向能力是「支撑功能」；不在链上也不服务链路的，是「可去功能」。

### 1.2 三条设计原则

1. **交易优先（Execution First）**：这是与同花顺 iFinD / 东方财富终端的本质差异——我们的不可替代价值是「多券商统一下单 + 条件单 + 算法单 + 风控闸门」。任何界面改动不能削弱交易路径的直达性。
2. **通达信式信息密度 + 量化式工作流**：行情展现学通达信（多 Pane 分屏、报价牌、F10），研究链路学量化平台（回测 → 因子 → 组合），两者通过「工作台多窗口」共存。
3. **一个能力一个入口（Single Surface）**：同一能力不允许多个页面重复暴露（如现在 K 线缓存管理藏在「行情工具」、又可在系统状态看到统计）。能力收口到唯一入口，页面数量做减法。

## 2. 现有功能体系评估（31 个页面的全量决策）

### 2.1 必须功能（P0，交易链路不可缺）

| 功能 | 现页面 | 判定理由 |
|---|---|---|
| 券商连接管理（含自动探测/诊断/运行时桥接） | `Brokers.jsx` | **全系统地基**。多运行时桥接（cp38~cp312 ABI 兼容）是本项目最深的护城河 |
| 手动交易（下单/撤单/条件单） | `Trade.jsx` | 核心价值。快速交易、二次确认、幂等（single_flight） |
| 多账户网格 + 批量操作 | `AccountsGrid.jsx` | 多券商差异化的主战场（批量下单/撤单/重连） |
| 报价牌（自选/板块/排名） | `QuoteBoard.jsx` | 行情入口，通达信式核心界面 |
| K 线分析（多周期/多 Pane/指标） | `MarketData.jsx` | 行情分析主界面，QuoteHub 单连接 + chart-spec 单一真源 |
| 风控配置（日级限额/熔断/超时撤单） | `Settings.jsx` 内 | 交易安全闸门，**必须继续强化** |
| 系统状态（健康/能力自述/metrics） | `SystemStatus.jsx` | 运维探针（live/ready/metrics），连接可靠性的一部分 |

### 2.2 保留但重组的功能（P1，价值真实但入口需归位）

| 功能 | 现页面 | 问题 | 重组方向 |
|---|---|---|---|
| 涨停监控（三因子） | `LimitUp.jsx` | 定位清晰，但属「策略型交易」 | 并入**交易中心**页签 |
| 算法交易 TWAP/VWAP | `Algo.jsx` | 同上 | 并入**交易中心**页签 |
| 模拟盘 | `Paper.jsx` | 使用频率低于实盘，但回测验证需要 | 并入**交易中心**页签（降为子页签） |
| 目标持仓差量同步 | `TargetPortfolio.jsx` | 与再平衡是一体两面 | 与 Rebalance 合并为**组合中心** |
| 即时再平衡 | `Rebalance.jsx` | 同上 | 同上 |
| 条件选股 + NL 选股 | `Screen.jsx` | 功能强但藏在「行情」组 | 独立为**选股中心**，NL 选股是特色能力（本地零依赖） |
| 板块行情/ETF/指数/轮动 | `Boards/Etfs/IndexOverview/Rotation.jsx` | 4 个页面同属「市场结构」 | 合并为**市场结构**中心（多页签），轮动为其中一个视图 |
| 回测 + 参数扫描 | `Backtest.jsx` | 研究链路主件 | 并入**研究中心** |
| 因子/指标 + 研究深度（IC/分位/walk-forward） | `Factors/Research.jsx` | 量化研究主件 | 并入**研究中心** |
| 参考数据（财务/日历/板块成分） | `Reference.jsx` | 工具属性 | 并入**数据中心** |
| 信号路由 | `Signal.jsx` | 外部策略接入通道 | 并入**自动化中心**（与告警同组） |
| 告警规则 + 历史 | `Alerts.jsx` | 独立合理 | 并入**自动化中心** |
| 通知渠道 | `Notifications.jsx` | 与出站 Webhook 高度重叠 | **与 Webhooks 合并为「通知与集成」** |
| 出站 Webhook | `Webhooks.jsx` | 同上 | 同上 |
| 审计日志 + 对账核销 | `Audit/Reconcile.jsx` | 都是事后合规 | **合并为「审计与对账」** |
| 全局搜索 | `MenuBar` 内 | 保留（刚修复样式门禁） | 保留 |
| 行情工具（缓存/抓取/同步） | `MarketTools.jsx` | **错位页面**：它是运维工具不是行情功能 | 迁入**数据中心**页签 |

### 2.3 建议去掉的功能（P2，做减法）

| 项 | 现状 | 处置 | 理由 |
|---|---|---|---|
| 策略市场（DB 目录 + zip/json 导入导出） | `StrategyMarket.jsx` 独立页 | **降级为「策略中心」内一个页签**，不再独立 | 使用频率低；「市场」概念（发布/安装）在单机多用户场景价值存疑；导入导出保留即可 |
| 策略模板生成 + 策略运行时 | `Strategies.jsx` + `StrategyRunner.jsx` | 与策略市场合并为**策略中心**（模板 → 运行 → 导入导出 三页签） | 三者本就是同一工作流的三步 |
| `components/Hub.jsx` | 孤儿组件（无中心页挂载） | **复用**：作为「中心页 + 子页签」通用容器（未激活子页签自动卸载、支持 `hub:switch` 事件） | 旧 Tab 结构遗留，现被中心页采用 |
| K 线缓存管理（若保留两处入口） | MarketTools + SystemStatus | 只保留**数据中心**一处 | Single Surface 原则 |

> 注：**不砍任何后端能力**。上述"去掉"全部是前端入口合并，后端端点与 MCP 工具照旧（capability drift 门禁继续保证 52 个 agent_visible 端点全暴露）。这也符合零 mock 铁律：能力不减，只做入口减法。

## 3. 全新功能体系（目标态）

### 3.1 六层能力架构（后端视角，功能即能力）

```
┌──────────────────────────────────────────────────────────┐
│ L6 治理层  鉴权 / 审计 hash 链 / 对账 WAL / 能力自述 / metrics │
├──────────────────────────────────────────────────────────┤
│ L5 研究层  回测引擎(向量化+扫参) / 因子库 / IC与归因 / NL选股    │
├──────────────────────────────────────────────────────────┤
│ L4 策略层  模板生成 / 策略运行时 / 信号路由 / 目标持仓 / 再平衡   │
├──────────────────────────────────────────────────────────┤
│ L3 执行层  手动交易 / 条件单 / 算法单 TWAP/VWAP / 涨停监控 /     │
│           模拟盘 / 风控闸门 / 幂等 / 订单看门狗                │
├──────────────────────────────────────────────────────────┤
│ L2 数据层  多源行情(券商/eltdx降级) / K线缓存 / 数据总线 /       │
│           QuoteHub / 财务参考数据                            │
├──────────────────────────────────────────────────────────┤
│ L1 连接层  多券商 BrokerManager / 运行时桥接(ABI) / 自动探测 /   │
│           连接诊断 / 单例端口锁                               │
└──────────────────────────────────────────────────────────┘
        ↑ REST(/api/v1) + WebSocket + MCP(105工具) 三平面暴露
```

这条分层**后端已基本就位**（`app/routes` + `xtquant_client` + `gateway`），本次功能体系重构的主要工作在**前端页面重组**与**能力深化**。

### 3.2 前端页面新结构：31 页 → 7 中心 21 顶层页

以 `pagesRegistry.jsx` 为单一真源重组（工作台多 Pane 分屏不变，只改功能树）：

| 中心（功能树分组） | 页面（含页签） | 吸收自旧页面 |
|---|---|---|
| **① 总览** | 仪表盘（账户聚合/PnL/滑点/市场温度） | Dashboard |
| **② 行情中心** | 报价牌 · K线分析 · 市场结构（板块/ETF/指数/轮动 4 页签） | QuoteBoard · MarketData · Boards+Etfs+IndexOverview+Rotation |
| **③ 交易中心** | 快速交易（手动+条件单） · 算法单 · 涨停监控 · 模拟盘 | Trade · Algo · LimitUp · Paper |
| **④ 组合与策略** | 目标持仓 · 再平衡 · 策略工场（模板生成/运行/导入导出 3 页签） | TargetPortfolio · Rebalance · Strategies+StrategyRunner+StrategyMarket |
| **⑤ 研究中心** | 回测对比 · 因子研究（指标/IC/分位/walk-forward 2 页签） | Backtest · Factors+Research |
| **⑥ 选股与信号** | 选股器（条件+NL 2 页签） · 信号与自动化（信号路由/告警/通知 3 页签） | Screen · Signal+Alerts+Notifications+Webhooks |
| **⑦ 系统运维** | 连接管理 · 多账户网格 · 数据中心（K线缓存/手动抓取/同步/参考数据 2 页签） · 审计对账（审计+对账 2 页签） · 系统状态 · 设置 | Brokers · AccountsGrid · MarketTools+Reference · Audit+Reconcile · SystemStatus · Settings |

**页面数变化：31 个顶层页 → 7 中心 / 21 个顶层页 / 33 个功能页签**。顶层入口减少 32%，但每个能力仍有直达页签（通达信式「分组 → 叶子」不变，`Workbench` 多 Pane 分屏、`CommandPalette` 命令面板、全局搜索照常工作，`pagesRegistry` 的 key 可平滑兼容旧 URL，被归并的旧 key 由 `KEY_ALIAS` 归一后自动落到对应子页签）。

### 3.3 必须功能的核心交互红线（不许破坏）

1. **下单路径 ≤ 2 次点击**：报价牌/K线 → 买/卖按钮直达下单（现有 `lib/trade.js` quickTradeNavigate + Pane 直达机制，保留）。
2. **二次确认 + 风控前置**：`ConfirmTradeModal`（risk=high）与 `precheck` 顺序不可变。
3. **连接状态全局可见**：`BrokerBar` 常驻顶栏（券商 + QuoteHub WS 状态），断线必须即时可见。
4. **非活跃 Pane 静默**：`useActiveInterval` 的可见性感知轮询（后台页签不跑定时器）不能因重组回退。

## 5. 迁移路线（三阶段，均可独立验收）

### 阶段一：入口合并（纯前端，低风险）

1. `pagesRegistry.jsx` 重组为 7 中心 18 页（key 兼容旧 key 跳转映射，老 URL 重定向）。
2. 删除孤儿组件 `Hub.jsx`。
3. `MarketTools` 迁入数据中心页签；`Notifications + Webhooks` 合并；`Audit + Reconcile` 合并。
4. 验收：31 个旧 key 全部有新归宿跳转；vitest 71 用例 + build + lint + 两个 CI 门禁全绿。

### 阶段二：核心扩展（交易质量 + 行情体验）

5. 执行质量报告页签（滑点/成交率/撤单率统计）。
6. 分屏模板保存/载入；快捷键体系补全。
7. 连接体检报告（diagnostics deep + 修复建议知识库）。
8. 验收：新增 vitest 用例；`check_frontend_classnames` 零新增缺失类。

### 阶段三：研究闭环

9. 回测 → 模拟盘一键部署。
10. 选股结果 → 目标持仓计划。
11. 因子看板快照。
12. 验收：新增后端 pytest 用例（paper/backtest 衔接、target-portfolio 生成）。

## 7. 与既有约束的对齐确认

- **不恢复已删功能**：Agent 对话 / Scheduler 定时任务 / Observability 独立页 / Registry V2 不因本方案复活（信号与自动化中心中的"自动化"仅指信号路由与告警触发，非定时任务框架）。
- **MCP 能力不减**：105 个 MCP 工具与 52 个 agent_visible 端点保持全暴露，`check_capability_drift.py` 门禁继续生效。
- **零 mock 铁律**：所有新增功能（滑点报告、体检报告、因子看板）全部基于既有真实数据端点扩展，不引入模拟数据。
- **UI 参照**：页面重组后的视觉密度与交互模式继续遵循 `DESIGN_SYSTEM.md` 与通达信/大智慧范式。
