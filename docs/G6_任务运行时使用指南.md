# G6 任务运行时使用指南（JobRuntime）

> 交付物：`backend/app/runtime/jobs.py` + `app/routes/runtime.py`。
> 把全市场同步 / 条件选股 / 回测统一为**带进度的异步任务**（kind 配额 +
> 优先级 + 可取消），替代同步阻塞调用。

## 端点

| 方法 | 路径 | 说明 | 暴露 |
|---|---|---|---|
| POST | `/api/v1/runtime/jobs` | 提交任务 | 写域（人工确认） |
| GET | `/api/v1/runtime/jobs` | 任务列表（最近优先） | MCP auto |
| GET | `/api/v1/runtime/jobs/{job_id}` | 状态 + 进度 | MCP auto |
| POST | `/api/v1/runtime/jobs/{job_id}/cancel` | 取消（queued/running） | 写域 |

## kind 与配额

| kind | 并发配额 | 说明 |
|---|---|---|
| `sync` | 1 | BarsSyncer 全市场日线同步（params: limit/concurrency/lookback/adjust） |
| `screen` | 1 | 条件选股（params: conditions/limit/sort_by/adjust/max_codes） |
| `backtest` | 2 | 回测（params: symbol/strategy/params/initial_capital/count/broker_id/费用） |
| `report` | 2 | 预留（未接 runner） |

全局并发上限 `GLOBAL_MAX=4`；`priority` 1 最高，同优先级按提交序号先到先跑。

## 提交示例

```bash
curl -X POST http://127.0.0.1:21118/api/v1/runtime/jobs \
  -H "Content-Type: application/json" \
  -d '{"kind":"screen","name":"放量选股","params":{"conditions":{"and":[
        {"indicator":{"name":"volume_ma","params":{"win":20},"output":"volume_ma",
                      "op":"gt","value":1,"window":-1}}]},
       "limit":100}}'
# → {"id":"screen-0003","status":"queued"}

curl http://127.0.0.1:21118/api/v1/runtime/jobs/screen-0003
# → {"id":...,"status":"running","progress":42,"message":"扫描 210/500",...}
```

## 前端消费

任务状态经 `GET /runtime/jobs/{job_id}` 轮询（或 dataHub `runtime:jobs` topic
合并）。无需 WS——进度天然幂等，轮询即可。完成后 `result` 携带结构化结果
（SyncSummary / scan 输出 / 回测 metrics），失败时 `error` 说明原因。

## 取消语义

- `queued`：直接移出队列；
- `running`：`asyncio.Task.cancel()`（同步/选股内部协作取消；网络 IO 处
  CancelledError 立即传播）；
- 已终态（done/failed/canceled）：返回 400。

## 与 BacktestQueue 的关系

`backtest` runner 复用 `backtest/__init__.py` 的真实引擎（fetch_kline_async_meta
+ run_backtest_engine），在 JobRuntime 内执行并落库——两套队列已收敛到统一
调度层，避免双队列竞争。
