# qmt_work 真实交易场景对齐·全面排查与优化方案（2026-09-06）

> 状态：**第一期（P0 资金风险）已完成**。本文档基于一轮覆盖全部下单入口的专项审计。

## 一、审计总结论

下单确认与幂等的骨架是好的（Trade/AccountsGrid/LimitUp 高危确认、幂等透传、后端 single_flight），
但存在 **3 个 P0 资金风险缺口** 和一批功能断点，集中在「目标持仓差量同步」「模拟盘」「信号全局模式可见性」三处。

## 二、P0（资金风险）——第一期，✅ 已修复

1. **按金额模式后端未实现，权重会被当股数执行**：前端提供 按股数/按金额/按比例 三模式，
   后端 tools/target_portfolio.py 只实现 weight —— value 模式把 0.3 当目标股数 → 差量 = -持仓 →
   **可能生成批量清仓卖单**。修复：移除「按金额」按钮 + syncPortfolio 内 value 模式兜底拒绝。
2. **实盘同步无二次确认、预演明细不展示**：此前 dry_run=false 一键直发；预演只显示"N 笔"。
   修复：实盘前强制先跑 dry_run，把差量明细（代码/方向/股数，前 12 条）摆进 ConfirmTradeModal，
   确认后才真实提交；提交结果中 `pending_confirmation` 的笔数明确提示"待信号页人工确认"。
3. **全局信号模式（signal.mode 默认 paper）对用户不可见**：Algo/条件单/打板/目标持仓切片全走
   signal_router，非 live 模式下页面却显示"真实下单"。修复：TargetPortfolio 页头加模式徽章
   （paper→「模拟盘（不会真实下单）」/dry_run→「预演」），其余页面第二期统一接入。

## 三、P1/P2 清单（第二、三期，待办）

### 第二期（功能断点）
- **模拟盘下单 100% 失败**：Paper.jsx 发 `{symbol,side:"BUY",qty}`，后端要 `{code,side:"buy",volume,price}`；
  MARKET/BEST 档是假的（引擎只按给定价立即全额成交）。修字段+下掉假市价+重置加确认。
- **市价单无法提交**：tradeApi.normalizeOrderPayload 对市价也强制 price>0，比后端更严属误伤；
  同时补 100 整数倍前端校验。
- **QuickTrade 无二次确认**（预检后单击即真实下单）；**Algo 提交/取消无确认**且限价 0 时后端
  静默改最新价；**AccountsGrid 批量确认弹窗只回显第一行参数**。
- **卖出无可用持仓/T+1 前端校验**（实盘链路比模拟盘还弱）；涨跌停边界提示缺失。
- **OrderTicketModal 不带 conn_id**（多账户下永远打给活跃券商）。

### 第三期（体验）
- 委托状态列用 STATUS_MAP 上色（部成/已撤/废单区分，Algo 页已有范式）。
- 下单/撤单成功后主动刷新列表（当前依赖 WS+30s 兜底）；批量下单面板回显可用资金。
- 条件单取消/Algo 暂停恢复补确认；Paper 重置确认+自定义初始资金；Paper 表格中文化。
- 信号模式徽章推广到 Trade/Algo/LimitUp。
