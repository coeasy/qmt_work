## 〇、结论先行

### 0.1 一句话判断

**qmt_work 的"交易与运维纵深"已是五家中唯一同时具备实盘通道与原生 MCP 的产品，但"数据地基 + 分析广度 + 能力暴露面"三处存在结构性缺口——缺的不是页面，是三个地基：本地数据仓、统一指标引擎、能力自描述层。**

五个参照系恰好各补一块，且**互不重叠**：

| 参照系 | 它最强的一点 | qmt_work 该抄的 | 不该抄的 |
|---|---|---|---|
| **通达信** | 本地数据仓 + 公式 DSL + 条件选股 | 数据主源本地化、指标一处定义四处复用 | 封闭式板块格式、无 API |
| **大智慧** | Level-2 深度 + DDX 资金流 + 主题投资 | 资金流指标的呈现范式与主题聚合 | 商业化堕落路径 |
| **东方财富** | 数据广度 + 社区 + **AI 闭环** | 自然语言选股的交互范式（妙想/问财） | 社区/资讯的运营成本 |
| **Fincept Terminal** | DataHub 统一数据面 + 屏幕生命周期纪律 | 统一数据面、生命周期治理、任务运行时 | C++/Qt 技术栈、4000 脚本堆量 |

### 1.2 协议红线（最高优先级约束）

**Fincept Terminal 与 OpenBB 均为 AGPL-3.0**（OpenBB LICENSE 首句原文："All files in this repository are licensed under the GNU Affero General Public License v3.0."）。AGPL 的传染性在**网络服务场景**下尤其强：只要对外提供修改了 AGPL 代码的服务，就必须公开对应源码。

因此本文所有借鉴项的执行纪律：

1. **只借鉴架构范式与接口契约，不复制任何一行代码。** 所有实现均为 qmt_work 独立编写。
2. **不引入 AGPL 依赖。** 新增依赖须先过许可扫描（现有 `fastmcp`/`pandas`/`numpy` 均为宽松许可，安全）。
3. **不反向污染**：qmt_work 若未来要闭源商业化，AGPL 代码一旦混入即不可逆。
4. **立即补 LICENSE**（G0-1），否则"借鉴"与"抄袭"在法律上无边界可守。

### 1.3 明确不借鉴清单

| 不借鉴 | 来源 | 理由 |
|---|---|---|
| C++20 + Dear ImGui / Qt6 技术栈 | Fincept | 其自身正处迁移中途（README 称 v4 为 C++ 重写，v4.1.0 CONTRIBUTING 仍描述 Qt6），栈不稳定 |
| 4000+ 分析脚本堆量模式 | Fincept | 无契约的脚本增殖 = 长期维护灾难；改为 **G10 先定契约再长脚本** |
| 100+ 连接器广度竞赛 | Fincept | 与 A 股主线无关，且稀释工程质量 |
| 30+ Provider 广度竞赛 | OpenBB | qmt_work 的真实瓶颈是深度与一致性，不是源的数量 |
| OpenBB Workspace 闭源化路线 | OpenBB | 与其社区版 AGPL 存在张力，且 qmt_work 已有更灵活的 React 前端 |
| 订阅制商业化 / 社区运营 | 三家 | 非技术项，超出本方案范围 |

### 2.2 必须守住的五大护城河（对标中不可丢失）

1. **真实券商零 mock**——`BrokerAdapter` 全真实调用，未连接返回业务码 503 引导而非假数据（零 mock 铁律）。
2. **交易纵深**——WAL、审计链、对账、风控（`risk`）、多账户网格、算法单、目标持仓差量同步（`target_portfolio_sync` + `dry_run` 预演）。
3. **多券商多版本兼容**——`XTPQuantAdapter` 覆盖迅投系 6 家，多版本 xtquant 差异集中在 `xtp.py` 用 `_pick` + 签名自省处理。
4. **工作区分屏 + keep-alive**——多任务并行观察能力，**灵活性优于通达信自定义版面**。
5. **原生 MCP + Agent**——`FastMCP("qmt_work")` 已带交易确认护栏（instructions 明确"交易类操作必须先与用户确认方向、数量、价格"）。

> **战略判断**：2026 年五家的竞争焦点已收敛到"自然语言 × AI Agent × 交易闭环"。**qmt_work 恰好持有另外四家都不具备的资产：真实券商通道 + 原生 MCP + 交易护栏。** 但它们要真正生效，必须先补齐能力暴露面（G3）与选股器（G7）。

### 2.3 七条根因（按解释力排序）

| # | 根因 | 证据 | 解释的现象 |
|---|---|---|---|
| **R1** | **缓存被当加速手段，而非数据主源** | TTL 散落 **9 个函数签名**、**3 套独立缓存** | 不能离线、不能秒开、不能全市场扫描、做不了选股器——**总闸门** |
| **R2** | **指标各写一份** | 后端 19 个 Python 因子 vs 前端 7 个 JS 指标（`MarketData.jsx:85-180`，`calcKDJ`/`calcWR` 为 O(n×period) 嵌套循环） | 前后端指标必然不一致；TDX 用一套 DSL 供显示/选股/交易系统/五彩K线四处复用 |

## 四、最终方案：G0–G12 工程包

### 4.0 总体依赖图

```
[G0 合规基线] ──────────────────────────────────── 全链路前置（本周）
```

## 附录 C：参照系规格速查

### C.1 OpenBB TET / Fetcher 契约
```python
class Fetcher(Generic[Q, R]):
    require_credentials = True
    @staticmethod
    def transform_query(params: dict) -> Q: ...          # ① 标准参数 → Provider 参数
    @staticmethod
    async def aextract_data(query: Q, credentials) -> Any: ...  # ② 取原始数据
    @staticmethod
    def transform_data(query: Q, data: Any, **kw) -> R: ...     # ③ 原始数据 → 标准模型
    # __init_subclass__ 自动以 aextract_data 为默认（同步/异步无感）
```
- 标准模型：Provider 子模型通过 `__alias_dict__` 映射自有字段（如 `last_price` ← `price` / `last_price`）
- 统一容器 `OBBject`：`results` + `provider` + `warnings` + `chart` + `extra`
- 扩展发现：Python 入口点三组 —— `openbb_core_extension`（路由）/ `openbb_provider_extension`（数据源）/ `openbb_obbject_extension`（输出插件）
- 自省：`/coverage/command_model` 可查询任意命令的序列化结构

### C.2 Fincept DataHub 要点
- topic 命名 `domain:subdomain:id`
- `TopicPolicy`：`ttl_ms` / `min_interval_ms` / `coalesce_within_ms` / `priority`
- 双 API：`subscribe()` 实时流 / `peek()` 快照
- 只有注册的 producer 能 publish；按前缀最长匹配路由
- 生命周期：P2 懒构造屏幕、P3 定时器在 show/hide 启停、`active_for_work` 抑制后台投递
- PythonRunner：单例、最大 3 并发、按脚本路径路由 venv
