## 本次实际落地（2026-08-18，HEAD b0ce266）

逐项核实 `连接层与核心功能缺陷排查及改进方案.md` 的全部 P0/P1 后，绝大部分已闭环（C1/C2/C3/C4/C6/C7/C8/C9/C22、F2/F3/F4/F5/F6/F7/F8/F9/F10/F11/F12/F13/F14 均已修复并有对应单测）。**唯一确认残留并本次修复的缺陷：**

### 🔧 修复 1：F1 —— `tools/trading.py` place_order 幂等竞态
- **问题**：幂等"get 检查 → `await` 下单 → set 写入"之间无锁；两个同 `idempotency_key` 并发调用（LLM 超时重试/前端双击）会同时通过检查各下一单 → 真实重复成交。
- **修复**：引入 per-key `asyncio.Lock`，把"get→下单→set"包成原子临界区，同一幂等键并发只有一个进入下单；释放后按缓存过期清理锁表防无界增长。
- **验证**：3 并发同 key → 仅 1 单 + 2 次重复拦截；`test_stage0b` 幂等用例全绿。

### 🔧 修复 2：`gateway/idempotency.py` 模块级 `asyncio.Lock` 跨事件循环绑定
- **问题**：模块级 `_lock = asyncio.Lock()` 绑定首个使用它的事件循环，在多个 `asyncio.run()`（多测试函数/多 loop 场景）下跨循环复用会抛 `bound to a different event loop`，`test_stage0b` 因此偶发失败。
- **修复**：改用 `threading.Lock` 保护无 `await` 临界区，并把 `await fut`（等待进行中执行）**移出锁外**，避免单线程事件循环下"持锁等待→其他协程阻塞→死锁"。
- **验证**：`test_stage0b` 8 项全绿，跨多个 `asyncio.run` 不再报错。
