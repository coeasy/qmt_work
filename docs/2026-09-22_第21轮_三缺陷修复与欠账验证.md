## 1. 缺陷 A：MCP 工具同名遮蔽

### 1.1 症状

```
Error calling tool 'save_qmt_strategy': 'FunctionTool' object is not callable
Error calling tool 'generate_strategy':  'FunctionTool' object is not callable
```

**只有真正调用才炸**：`tools/list` 正常列出两个工具、参数 schema 正常、`/capabilities`
里也在 —— 一切「静态检查」都是绿的。

### 1.2 根因

`backend/tools/strategy_gen.py` 里，模块级有两个函数：

```python
def generate_strategy(strategy_type, code, ...): ...      # L189
def save_qmt_strategy(filename, content, ...): ...        # L219

def register_strategy_tools(mcp):
    @mcp.tool()
    async def generate_strategy(...):        # ← 与模块级函数同名
        return generate_strategy(...)        # ← 解析到的是「自己」
```

`@mcp.tool()` 会把**被装饰的名字重绑为 `FunctionTool` 对象**。
于是嵌套函数体内的 `generate_strategy(...)` 解析到的是**闭包变量** ——
也就是装饰后的 `FunctionTool` 自己，而不是模块级函数。

> ⚠️ 这是 Python 作用域规则与装饰器语义的交叉盲区：
> **函数体内引用的名字，优先解析到本函数所在作用域的名字**，而装饰器恰好把那个名字换掉了。

### 1.3 一次失败的修法（必须记下来）

第一版修法用的是「别名法」：

```python
def register_strategy_tools(mcp):
    _generate_strategy_impl = generate_strategy   # ← 想先抓住模块级函数
    @mcp.tool()
    async def generate_strategy(...):
        return _generate_strategy_impl(...)
```

**结果：实例启动即崩。**

```
UnboundLocalError: cannot access local variable 'generate_strategy'
where it is not associated with a value      (strategy_gen.py:256)
```

原因：Python 里**只要函数体内任何位置出现对该名字的赋值，该名字整体就是局部变量** ——
`_generate_strategy_impl = generate_strategy` 这一句读到的，是「尚未绑定的局部变量
`generate_strategy`」，而不是外层的模块级函数。

### 1.4 正确修法

**嵌套函数改名 + `@mcp.tool(name="原名")` 保持对外契约**（工具名是 MCP 客户端的契约，
不能变）：

```python
def register_strategy_tools(mcp):
    # ★★ 嵌套工具函数**必须改名**（2026-09-22 修的真缺陷）。
    # 原因：`@mcp.tool()` 会把被装饰的名字重绑为 `FunctionTool` 对象。此前嵌套函数与
    # 它要调用的**模块级**函数同名，于是函数体里的 `name(...)` 解析到的是
    # **本函数的闭包变量**（装饰后的 FunctionTool 自己）⇒ 运行期
    # `TypeError: 'FunctionTool' object is not callable`。
    # ⚠️ 反面教训：不要用「先 `_impl = generate_strategy` 再定义同名函数」的写法 ——
    #   Python 里函数内任何位置被赋值的名字**整体是局部变量**，那句赋值会读到
    #   「尚未绑定的局部」⇒ `UnboundLocalError`（已实测踩到）。

    @mcp.tool(name="generate_strategy")
    async def _generate_strategy_tool(strategy_type: str, code: str = "600519.SH",
                                      client_path: str = "", account_id: str = "",
                                      params: dict | None = None) -> dict:
        """生成 QMT 策略代码（ma_cross/macd/rsi/limitup 四类模板），返回代码内容。"""
        return generate_strategy(strategy_type, code, client_path, account_id, params)

    @mcp.tool(name="save_qmt_strategy")
    async def _save_qmt_strategy_tool(filename: str, content: str,
                                      client_path: str = "") -> dict:
        """把策略代码保存到 QMT 客户端 mpython 目录（QMT 内可导入运行）。"""
        return save_qmt_strategy(filename, content, client_path)
```

> 前置核实：`fastmcp 2.14.7` 的 `FastMCP.tool()` **支持 `name` 参数**
> （实测签名含 `name_or_fn, name, title, description, icons, tags, output_schema,
> annotations, exclude_args, meta, enabled, task`）。

### 1.5 护栏：`backend/tests/test_strategy_tool_shadowing.py`（新增，4 用例）

1. **对外工具名不变** —— `sorted(tools) == ["generate_strategy", "save_qmt_strategy"]`
2. **`generate_strategy` 调用得通** —— 实跑 `tool.run(...)`，断言返回内容含 `on_bar`
3. **`save_qmt_strategy` 真落盘** —— 断言 `{tmp}/mpython/shadow_probe.py` 内容逐字相符
4. **★ 静态护栏（最重要的一条）** —— AST 扫全仓 `tools/` + `mcp_server/` 的
   `register_*_tools`，凡「嵌套带装饰器函数名 ∩ 模块级函数名，且函数体内直接按名字调用」
   即判 offender。

> 第 4 条是**唯一能在「注册得成功、调用必炸」这类缺陷上提前报警**的检查。
> 运行期用例只能覆盖「已发现的 2 处」，静态护栏覆盖「未来新增的所有处」。

## 2. 缺陷 B：前端预设「放量且收阳」是空条件

### 2.1 症状

选股页的预设示例「**放量（当日量 > 前 5 日均量 1.5 倍）且收阳**」，点下去
**几乎所有标的都命中** —— 而它的条件树是：

```jsonc
{ "and": [
  { "indicator": { "name": "volume_ma", "params": { "win": 5 }, "window": -1, "op": "gt", "value": 0 } },
  { "indicator": { "name": "close",     "window": -1, "op": "gt", "value": 0 } }
] }
```

**成交量均线恒为正、收盘价恒为正** ⇒ 两个条件对任何真实标的都成立 ⇒ **恒真**。

### 2.2 实测定论（`GET /market/screen`，24 只真实标的）

| 条件 | 命中 |
|---|---|
| 旧预设（`volume_ma(5) > 0 AND close > 0`） | **24 / 24** ← 空条件 |
| 修复后（`vol_ratio(5) > 1.5 AND close > open`） | **2 / 24** ← 真在筛 |
| 对照组（`close > MA20`） | **4 / 24** ← 量级合理 |

### 2.3 根因：DSL 表达力缺口

条件树叶子的 `value` **只能是字面量** —— 写不出「均量 × 1.5」这种**倍数**。
而注册表里当时只有**绝对量**的 `volume_ma`。于是「想表达倍数」的人**只能**退化成
`volume_ma(5) > 0`（因为不知道该拿什么当基准）。

> ★ 关键判断：**修法应该是「补一个比值指标」，而不是「想办法凑表达式」。**
> 加算术运算会牵动解析器、求值器、前端编辑器三处；加一个指标只动注册表。

### 2.4 修复：新增标准「量比」指标

`backend/app/indicators/builtin.py`：

```python
def vol_ratio(volume, period: int = 5) -> np.ndarray:
    """量比：当日成交量 ÷ **前 period 日**（不含当日）成交量均线。

    口径：基准取**前 period 根**（``shift(1)`` 后再取 MA），与通达信 / 同花顺的
    「量比」一致 —— 用含当日的均线做分母会把放量本身算进基准，把信号抹平。
    """
    v = _as_float(volume)
    n = v.shape[0]
    out = np.full(n, np.nan)
    if n > period:
        base = ma(v, period)
        base = np.concatenate(([np.nan], base[:-1]))     # shift(1)：基准不含当日
        with np.errstate(divide="ignore", invalid="ignore"):
            out = np.where(base > 0, v / base, np.nan)
    return out
```

数值自证：序列 `[100]*7 + [300]`

| 口径 | 计算 | 结果 |
|---|---|---|
| **不含当日**（本实现） | `300 / mean(V[-6:-1]) = 300 / 100` | **3.0** |
| 含当日（错误口径） | `300 / mean(100,100,100,100,300) = 300 / 140` | 2.143 |

注册（`registry.py`）：`inputs=["volume"]`、`outputs=["vol_ratio"]`、
`params=[IndicatorParam("period", PARAM_INT, 5, 1, "基准窗口（不含当日）")]`。
指标总数 **16 → 17**。

预设改为（`ScreenPanels.tsx`，并把 `PRESET_EXAMPLES` 改为 `export` 供测试断言）：

```tsx
{
  label: "放量（当日量 > 前 5 日均量 1.5 倍）且收阳",
  conditions: JSON.stringify({
    and: [
      { indicator: { name: "vol_ratio", params: { win: 5 }, output: "vol_ratio",
                     window: -1, op: "gt", value: 1.5 } },
      { compare: { op: "gt",
                   left:  { kind: "field", name: "close", window: -1 },
                   right: { kind: "field", name: "open",  window: -1 } } },
    ],
  }, null, 2),
}
```

### 2.5 ⚠️ 两个「量比」不是同一个东西（有意保留差异）

| 位置 | 口径 | 用途 |
|---|---|---|
| `indicators.vol_ratio` | **不含当日**（标准） | 供条件树表达「量 > 均量 × k」 |
| `classic.py` 明细里的 `"vol_ratio"` | **含当日** | 与同文件 `vol_ok = vol >= vol_ma * vol_mult` **同源** |

`classic.py` 那一处**有意保留**含当日口径 —— 改它会**改变选股结果**。
已在源码里加注释说明，防止后人「为了看起来一致」把两边对齐。

### 2.6 护栏

- `backend/tests/test_vol_ratio.py`（新增，6 用例）：基准不含当日（3.0 ≠ 2.143）、
  无基准返 null、注册元数据、预设命中「放量+收阳」、**空条件复发闸门**
  （无放量必须 `hit is False`）、放量但收阴不命中。
- `frontend-next/tests/screenPresets.test.ts`（新增，4 用例）：预设都是合法 JSON 且含叶子、
  **无「对常量 0 做大于」的空条件**、放量预选用 `vol_ratio>1.5` + `close>open`、
  「站上 20 日均线」用 `compare(close, ma)`。

## 3. 缺陷 C：字段条件「静默恒 False」

### 3.1 症状

修缺陷 B 时，`compare(close > open)` 在 dict 形态的 bars 上**恒返 False** ——
不报错、不命中、日志干净。

### 3.2 根因

`backend/app/screener/conditions.py` 用 `getattr(b, name, None)` 取字段 ⇒
传 **dict** 时 `getattr` 静默返回 `None` ⇒ 条件恒 `False`。

而**指标侧**的 `indicators.registry._col` **一直是两态兼容的**（按首元素有无该属性判断）。
于是同一份数据上出现极难定位的分裂：

> **指标算得出，字段条件永远不命中。**

### 3.3 修复：抽出两态兼容的取值函数

```python
def _field_series(bars: list, name: str) -> list:
    """取某字段的整列（**Bar 对象与 dict 两态兼容**）。

    ★ 为什么必须两态（2026-09-22 修）：这里此前只写 ``getattr(b, name, None)``，
    传 dict 时**静默**得到 ``None`` ⇒ 字段条件恒为 ``False``（不报错、不命中）。
    而指标侧 ``indicators.registry._col`` 一直是两态兼容的 ⇒ 同一份数据会出现
    「指标算得出、字段条件永远不命中」这种极难定位的分裂。
    """
    if not bars:
        return []
    first = bars[0]
    if hasattr(first, name):
        getter = lambda b: getattr(b, name, None)
    else:
        getter = lambda b: b.get(name) if isinstance(b, dict) else None
    return [float(v) if v is not None else None for v in (getter(b) for b in bars)]
```

`_operand_value` 与 `_eval_leaf` 两处调用点均改用 `_field_series`。

> ★ 判据沉淀：**字段取值必须与 `_col` 同构**（同一套 Bar/dict 分叉规则）。
> 只改一处 = 埋一颗静默哑弹。

## 4. 文档缺陷 D：`dsl.py` 的示例「照抄必然报错」

`backend/app/indicators/dsl.py` 的文档示例里写着：

```
"C > MA(20) AND (VOLUME > MA(VOLUME,20)*1.5 OR KDJ.K(9) > 80)"
```

而 v1 实现：**没有算术运算**、**指标参数只接受数字** ⇒ 这一条**解析不了**。
用户照抄文档 ⇒ 必然得到「无法解析」。**示例与实现不符比没有示例更糟。**

修复：改为可解析的等价写法 + 显式写明 3 条已知边界：

```
示例（**下面每一条都必须能解析**，由 `tests/test_dsl_examples.py` 守）：
    "C > MA(20) AND RSI(14) < 30"
    "C > MA(20) AND (VOL_RATIO(5) > 1.5 OR KDJ.K(9) > 80)"
    "MACD.DIF(12,26,9) > 0 AND NOT WR(14) < -80"

⚠️ 已知边界（v1 **不支持**，别照直觉写）：
  1. **没有算术运算**：`MA(20)*1.5`、`(C-O)/O` 都解析不了。
  2. **指标参数只能是数字**：`MA(VOLUME,20)`（对成交量求均线）不行。
  3. **没有截面算子**：`RANK(x)` / `TOP(x,n)` 尚未接入。
```

护栏 `backend/tests/test_dsl_examples.py`（新增，7 用例）：从 `__doc__` 抠出示例区
逐条 `parse`；示例条数 ≥3（防用例空转）；**锁住** `MA(20)*1.5` 与 `MA(VOLUME,20)`
确实不支持（实现变更时提醒同步文档，而不是删用例）。

## 9. 沉淀的判据（已写入 `MEMORY.md`）

1. **★ `tools/list` 只证明「注册了」，不证明「调用得通」** —— 工具类缺陷必须**真调一次**。
2. **★ 装饰器会改变名字的含义** —— 嵌套函数与被装饰/被调用的模块级函数**必须不同名**；
   且**不能**用别名法绕过（函数内被赋值的名字整体是局部 ⇒ `UnboundLocalError`）。
3. **★ 空条件（对恒正字段做 `> 0`）恒真、标签说谎、用户无从察觉** ⇒ 预设必须有
   「空条件闸门」用例。
4. **★ DSL 表达力缺口不要用「凑表达式」绕过** —— 缺比值就补比值指标。
5. **★ 字段取值必须与 `_col` 同构** —— 两态（Bar/dict）分叉规则只许有一套。
6. **★ 文档示例必须可执行** —— 由用例从 `__doc__` 抠出来逐条 `parse`。
7. **★ 探针读 JSON 前先 dump 键集** —— 本项目已 3 次因读错层级（`picks` vs `count`）误判。
