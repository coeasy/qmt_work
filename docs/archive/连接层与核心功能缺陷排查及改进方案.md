## 三、三条根因主线

1. **订单状态/幂等链路断层**：`xtp` 不注册回调（拿不到柜台 order_id 与成交回报）→ `place_order` 用 seq 冒充 order_id → 撤单/对账/看护/watchdog 的状态语言与 xtp 实际状态**完全对不上** → WAL 重放又不识别后续 cancel/final。这条链上任何一环单独修都无效，必须**端到端打通"报单→确认→回报→对账→重放"的状态闭环**。
2. **风控旁路矩阵**：`algo`/`limitup`/`rebalance`/`strategy_runtime`/`position` 均直接调 `gateway.place_order` 绕过 SignalRouter 与 check_order；叠加双 RiskManager 实例与 direction 归类错误，任何单点被触发即整层风控失效。**必须把"下单唯一入口"收敛到单一受控通道。**
3. **连接生命周期缺陷**：断线零感知（无回调）+ 重连后订阅不恢复 + start 无锁 + 阻塞事件循环，使"多券商/长时间运行"场景的可用性无保障。

## 四、详细改进方案

### 阶段 0 · P0 紧急修复（建议 1 周内，先于一切新功能）

原则：**一次只动一条主线，每条主线配回归测试；先修"重复下单"与"错误核销"，再修连接。**

**0-A 订单状态闭环（修 C1/C2/F2/F12/F11 + watchdog）**
1. `xtp.py` 注册 `XtQuantTraderCallback`：`on_disconnected`（翻转 `_connected`、触发重连）、`on_order_stock_response`（拿真实柜台 order_id + 报单错误，建立 seq→order_id 映射表）、`on_cancel_error`、`on_stock_trade`（成交回报直推 sync 引擎，替代纯轮询）。
2. `place_order` 改为"提交→等待 response 回调（带超时）→返回柜台 order_id"；`-1` 显式判为失败抛 `BrokerSDKError`；超时返回 `status="unknown"` 而非"submitted"。
3. 建立**统一状态词汇表**（xtp 原始状态 → 平台标准状态 `pending/partial/filled/cancelled/rejected/unknown`），`reconcile._norm_status`、`order_watchdog._ACTIVE`、`sync._order_fp` 全部引用同一映射，消除三处各说各话。
4. `reconcile` "查无此单"改为"连续 N 轮未命中 + 跨日校验"才标 stale；`_apply`/`_fire` 等处异常必须落日志。
5. 回归测试：mock xtquant 回调序列（成功/拒单/-1/断线/乱序回报），断言 order_id 映射、状态迁移、对账结果。

**0-B 幂等与风控唯一入口（修 F1/F4/F5/F6/F7/F8/F9/F13 + trading 竞态）**
1. 幂等改为"**先占位后执行**"：`_idempotent_set(key, status=pending)` 原子占位（DB 唯一约束），下单成功更新为 result、失败回滚删除，杜绝 get→set 竞态。
2. 收敛下单唯一入口：所有引擎（algo/limitup/rebalance/position/strategy_runtime）一律经 `SignalRouter.submit()`（含 check_order + 幂等 + 审计），禁止直接 `gateway.place_order`；`SignalRouter` 成为唯一"真实下单"闸门。
3. 消灭双 RiskManager：`build_mcp` 改收 `state`（取 `state.risk`）或全局单例；MCP 工具调用时动态取当前实例。
4. `risk.check_order` direction 归一化（去空格/小写/中英映射表），未知值**拒绝**而非按卖处理；被拒单不占用频率额度；柜台拒单回退已扣额度。
5. `signal_router` confirm 前重跑风控；市价单估值用最新价而非 100.0；入站 webhook 默认强制签名（空 secret 拒绝启动或随机生成）。
6. 回归测试：并发同键下单只成交一次；熔断状态下各引擎下单全被拒；direction 边界值用例。

**0-C WAL 重放正确性（修 F3）**
1. `_replay_algo` 改为"扫描全部记录→按 algo_id 聚合出最终状态→仅重放最终态为 pending/running 者"；WAL snapshot 改为"覆盖写 + 原子 rename"，truncate 与 snapshot 写入合并为一个事务窗口。
2. 回归测试：构造"create→cancel"、"create→final"、"create（悬挂）"三种 WAL 序列，断言只重放悬挂者。

**0-D 连接生命周期（修 C3/C4/C5/C6/C7）**
1. `main.py` 把 `conn.bridge.on("quote", sync_engine.on_event)` 移到 `SyncEngine` 构造之后；并在 `manager.connect`/热插拔路径统一补注册 handler。
2. `health.py` `_reconnect` 成功路径显式 `conn.reconnect_task=None`；`_check` 用 `task.done()` 判定而非仅 `is None`。
3. 订阅恢复：`BridgeAdapter` 记录已订阅 codes，`start()` 成功后自动重新下发；`SyncEngine` 监听桥接重启事件清空 `_subscribed_codes` 触发重订。
4. `start()` 加 `asyncio.Lock`（幂等 + 防并发双开）；disconnect/remove 清 `cfg.active` 并取消 `reconnect_task`。
5. connect/test/add/batch-reconnect 全部 `asyncio.to_thread` 或 executor 化，事件循环不阻塞；批量重连并行+限并发。
6. 回归测试：断线→自动重连→订阅自动恢复行情；并发 connect 只产生一个子进程/一个会话。

**0-E 安全基线（修 F10 + auth 系列）**
1. loopback 免鉴权仅在**明确未启用 proxy-headers**时生效；否则强制鉴权；`token` 比较改 `hmac.compare_digest`。
2. `scope_for_path` 未匹配改为 **default-deny**；修正 `PATH_SCOPES` 前缀错配（strategies/run 独立 scope）；`_is_expired` 解析失败按"已过期"处理。
3. 默认配置加固：`host=127.0.0.1`、启动检测 `api_key==qmt-dev-key` 强制告警/拒绝远程、`run.py` 移除明文日志密钥。

### 阶段 1 · 连接可靠性深化（1~2 周）

- **桥接并发与背压**（C11/C12/C14）：bridge_server 改"读循环仅解析+分发、执行用线程池"；`_rpc` 加方法级超时；写 stdin 统一持锁；quote handler 移出 reader 线程（独立事件队列）。
- **行情真·实时**（C8）：`subscribe_quote` 区分 tick/1m 两种订阅；tick 回调禁止同步重调用，缺数据异步补拉；去重重复订阅。
- **网关线程模型**（C15）：`XTQuantBridge.stop()` 加超时、回调队列设上限+丢弃策略（记 metrics）、handler 异常走 logger。
- **WS/状态机**（C20/C22/manager）：WSManager cid 改自增/uuid；`get_sector_stocks` 改正确 RPC 并传参；`_persist_active` 支持多 active 恢复。
- **热插拔落地**（C21）：`create_adapter` 同时查 `registry` 动态档案与 `_PROFILE_MAP`；profile 落库持久化。

### 阶段 2 · 引擎与对账正确性（1~2 周）

- algo：`cancel` 真撤柜台子单；`_confirm_fill` 以真实成交回报为准，未成交不计 done；任务句柄托管、stop 清理。
- condition_order：`_fire` 捕获全异常并保留 triggered 记录待恢复；拒单进"次日重试"队列；触发用最新价校验。
- limitup：修复 buf 逻辑（涨幅应基于**触发前**的 tick 序列，而非涨停后的序列）；加交易日/时段判定；`_auto_buy` 任务托管。
- paper：`lots` 迁移补默认值（存量持仓按总量构造单 lot）；`marking_source` 据实标注。
- sync：成交去重键加入 `seq`/回报唯一 id；指纹集合按交易日清理；状态迁移加终态锁（filled/cancelled 不可回退）。

### 阶段 3 · 存储与可观测性（1 周，可与阶段2并行）

- DB：同步 sqlite 移出事件循环（`asyncio.to_thread` 或 aiosqlite）；`_migrate` 改事务化迁移 + 失败回滚；`db_backup` 改 `sqlite3` backup API / `VACUUM INTO`。
- WAL：`append` 的 fsync 改批量/后台；损坏行记录并告警而非静默跳过。
- 可观测：为"断线/重连/订阅恢复/幂等命中/风控拦截/对账差异"增加 metrics 与告警事件，使阶段0/1 的修复效果可被监控验证。

### 阶段 4 · 回归测试体系（贯穿，收口）

- 建立 **mock xtquant 契约测试**：用 `fake_bridge_server` 模拟完整回调序列（连接/断线/报单/拒单/成交/撤单/乱序），覆盖阶段0各主线；纳入 CI 门禁。
- 补齐盲区：algo/condition/limitup/rebalance 执行循环、RedisLock 真路径（fakeredis）、BacktestQueue 编排、并发下单/重连竞态。
- 冒烟升级：smoke2 增加"断线重连行情恢复""幂等并发""风控熔断拦截"三项端到端断言。

## 五、优先级与排期建议

| 优先级 | 内容 | 建议周期 | 阻断关系 |
|---|---|---|---|
| P0-最高 | 阶段 0-A/0-B/0-C（订单闭环+幂等风控+WAL） | 3-4 天 | **真实资金交易的前置门槛** |
