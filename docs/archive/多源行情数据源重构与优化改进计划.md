# 多源行情数据源重构与优化改进计划

> 目标：引入 `EltdxSource`（通达信 TDX 公共行情）作为非券商场景下的行情补充源，
> 并将原本散落各处的「券商 vs eltdx」硬编码回退收敛为**单一多源编排入口**，
> 使后续新增数据源（akshare / tushare / eastmoney …）零侵入接入。

---

## 一、本次已完成重构（EltdxSource + 多源架构）

### 1.1 现状问题
重构前行情数据来源存在以下痛点：
- `source: auto / broker / eltdx` 的回退逻辑在 **4 处重复实现**：
  `app/routes/market.py`（quote / stock-info / search）、`app/tools/__init__.py`（K 线）、
  `app/sync/__init__.py`（WS 推送补名）、`app/main.py`（预热）。
- `EltdxSource` 已被实现，但**从未被统一编排**：各调用方直接 `import EltdxSource` 并自行写
  fallback，语义不一致、难扩展。
- `app/datasource/manager.py`（`MarketDataHub`）其实**已经写好却游离未接线**——属于半成品，
  且 `search_stocks` 调用了不存在的 `EltdxSource.search` 方法（若接线会直接 AttributeError）。
- `eltdx_source.py` 反向 `from app.routes.market import classify_board`，造成 datasource →
  routes 的**循环依赖隐患**。
- `classify_board` 存在复制粘贴 bug：`num.startswith("11") or num.startswith("11")` 重复条件。
- `EltdxSource._get_industry` 每次请求都**整文件重写行业缓存**且无锁，高并发下有写放大与丢更新风险。

### 1.2 落地改动
| 文件 | 改动 |
|------|------|
| `app/datasource/board.py`（新增） | 抽取 `classify_board` + 新增 `limit_ratio`，统一板块/涨跌停比例推断，消除循环依赖；修正重复条件 bug |
| `app/datasource/manager.py`（完善） | `MarketDataHub` 作为**唯一多源编排入口**：`register()` 注册补充源、`auto_chain` 控制回退序、`get_quote/get_kline/get_instrument_detail/get_stock_list/search_stocks`、`health()`、`lookup_name()`、`warmup()`；修复 `search_stocks`；新增 `list_sources/set_auto_chain/health` |
| `app/datasource/eltdx_source.py` | `classify_board`/`limit_ratio` 改从 `board.py` 引入；新增 `lookup_name`/`is_ready`；`_get_industry` 加 `_industry_lock` 并仅在新增记录时落盘 |
| `app/datasource/__init__.py` | 导出 `MarketDataHub` / `get_hub`，移除对已删 `registry` 的引用 |
| `app/routes/market.py` | quote / stock-info / search 全部改走 `get_hub()`；新增 `GET /market/sources` 端点（列出源 + 健康） |
| `app/tools/__init__.py` | `fetch_kline_cached` 的 eltdx 分支改走 `get_hub().get_kline`，返回 `(bars, src)` |
| `app/sync/__init__.py` | WS 补名改用 `get_hub().lookup_name(code)` |
| `app/main.py` | 预热改为 `get_hub().warmup()` |
| `app/datasource/registry.py` | **删除**（与 `manager.py` 重复的多源抽象，避免两个竞争实现） |

### 1.3 多源接入契约（新增数据源只需 3 步）
1. 继承 `app/datasource/base.py:DataSource`，实现 `get_quote / get_kline / get_instrument_detail / get_stock_list`（可选 `lookup_name / is_ready / warmup`）。
2. 在 `get_hub()` 单例中 `register(YourSource())`。
3. 端点 `source=` 即可直接指定新源名；`auto` 回退链自动包含（排在 eltdx 之后，或经 `set_auto_chain` 调序）。

## 三、优化改进路线图（建议执行顺序）

### P0（立即可做，保障正确性）
- [ ] **补数据源单测**：用 fake `DataSource` + fake broker 验证 `MarketDataHub` 的
      `auto` 回退、显式源 503 文案、`auto` 复权改走 eltdx、单源异常不击穿整体。
- [ ] **CI 接线校验**：`pytest backend/tests` 至少覆盖 `datasource` 包与 `market` 路由的
      `source=broker/eltdx/auto` 三态（可用 fake broker 注入）。

### P1（稳定性 / 性能）
- [ ] **合并 eltdx 行情网络调用**：`get_quote` 与 `get_instrument_detail` 复用同一次
      `get_snapshots`（预收已在快照内），行业/概念走本地缓存 + 惰性补充，避免 3 次 RTT。
- [ ] **TDX 连接池 / 信号量**：为 `eltdx` 增加 `asyncio.Semaphore`（如 8）限制并发线程数，
      并对 `TdxClient` 做短生命周期复用，防止高频订阅下线程耗尽。
- [ ] **配置化多源**：在 `app/config.py` + `.env.example` 增加
      `QMT_DATASOURCE_AUTO_CHAIN`（默认 `broker,eltdx`）、各源 `timeout` / `enabled`，
      `get_hub()` 启动时读取，支持不改代码调整优先级与开关。
- [ ] **前端源动态化**：`/market/sources` 已提供 `sources + health`，前端据此渲染数据源
      下拉与标签（替换硬编码 `SRC_LABEL`），新增源自动可见。

### P2（可观测 / 扩展）
- [ ] **熔断 + 失败预算**：单源连续 N 次失败后短期剔除出 `auto` 链，恢复后探测重入。
- [ ] **每源指标埋点**：用现有 `get_metrics()` 记录各源 `quote_latency / kline_ok / kline_err`，
      进 `/api/v1/metrics`（Prometheus）。
- [ ] **新增数据源模板**：提供 `akshare` / `tushare` / `eastmoney` 的 `DataSource` 骨架
      （pip 可选依赖、缺失自动跳过注册），演示多源并行。
- [ ] **搜索/列表缓存**：`get_stock_list` 结果按 TTL 缓存，避免每次 keystroke 全量遍历。

## 四、验收口径
- 无券商连接时 `GET /market/quote?code=600519.SH&source=eltdx` 返回 TDX 行情；
  `source=auto` 自动回退且 `source` 字段正确标注 `eltdx`。
- `GET /market/sources` 返回 `broker` + `eltdx` 及各自 `available` 状态。
- 新增任意 `DataSource` 子类后，无需改动 `routes/tools/sync`，仅注册即生效。
- 单源异常（网络超时 / 空数据）不会让整体返回假数据，仅按 `auto_chain` 回退或 503。
