## 一、目标与非目标

### 1.1 目标

| 编号 | 目标 | 衡量标准 |
|---|---|---|
| G1 | **前后端契约一致**：消灭因枚举/字段漂移导致的静默错误 | 周期、字段、错误码三张契约表单点定义，未知值显式报错而非降级 |
| G2 | **连通性可观测**：链路健康度全站可见 | 券商连接、WS 状态、数据源、延迟在状态栏常驻 |
| G3 | **链路韧性**：断网/后端重启/代理超时后自愈 | WS 无限重连 + 心跳保活；REST 超时重试；用户无需手动刷新 |
| G4 | **通达信体验对齐**：行情主界面达到 TDX 可用水位 | 真分时、十字光标+OHLC 信息条、指数条、增强盘口、周期条 |

### 1.2 非目标

- 不引入任何 Mock 数据（项目硬约束：真实券商、零 mock，未连接时返回 503 + 引导）
- 不改动 `BrokerManager` 的连接态唯一真相来源定位
- 不在本轮做策略/回测/交易链路重构（仅保证其 REST 客户端共享本方案的超时重试能力）

## 三、问题诊断

> 诊断依据：本次对 `backend/app/routes/market.py`、`backend/app/datasource/eltdx_source.py`、`backend/sync/__init__.py`、`frontend/src/api.js`、`frontend/src/lib/quoteHub.jsx`、`frontend/src/components/{MarketData,QuotePanel,QuoteBoard,BrokerBar,Chart}.jsx` 的逐行核对 + 一次全量构建验证。

### 3.1 P0 级（静默错误，用户无感知地看到错误数据）

#### **P0-1　周期契约断裂：点「月线」「季线」实际返回日线，且污染缓存**

**证据链：**

| 环节 | 代码 | 实际行为 |
|---|---|---|
| ① 前端发出 | `MarketData.jsx:29-41` `PERIODS` 定义 `{ v: "1mo", label: "月线" }`、`{ v: "1q", label: "季线" }` | 请求 `/market/kline?period=1mo` |
| ② 后端映射 | `eltdx_source.py:107-118` `_map_period` | 映射表**仅有** `1mon/month/mo`，**无** `1mo`、`1q`/`quarter` |
| ③ 静默降级 | `return m.get(p, "day")` | 未知周期 → **降级为 `day`，不报错、不告警** |
| ④ 缓存污染 | `db.py:238` `UNIQUE(code, period, dt)` | 缓存以**前端传入的 `period`** 为键写入 → `1mo` 键下存的是**日线数据** |

**危害（三层叠加，逐层加重）：**
1. **直接错误**：用户点月线/季线，看到的是日线 K 线，界面无任何提示；
2. **缓存固化**：错误数据入库，`KlineCache` 后续请求直接命中污染缓存 —— 即使后续修好映射，只要不清缓存，用户**仍然看到错的**；
3. **跨页扩散**：`factors.py:88`、`research.py:56` 同样走 `fetch_kline_cached`，研究/因子模块的月线口径一并被污染。

**根因归类**：同一概念（周期枚举）在 4 处各自硬编码，无契约校验，且失败策略是「静默降级」而非「显式报错」。

| 定义位置 | 内容 |
|---|---|
| `frontend/src/components/MarketData.jsx:29` | `["tick","1m","5m","15m","30m","60m","1d","1w","1mo","1q","1y"]` |
| `backend/app/datasource/eltdx_source.py:110` | `1d/1w/1m/5m/15m/30m/60m/1mon/1y` 等别名表 |
| `backend/app/datasource/registry.py:302` | `adj_periods = ("1d","day","1w","week","1mon","mon","month")` |
| `backend/app/routes/market.py:391` | `periods` 默认 `["1d","1w"]`（同步任务） |

## 四、契约规范（本方案落地的长期约束）

> 原则：**单点定义、显式失败、契约驱动 UI**。未知值一律报错，禁止静默降级。

### 4.1 周期枚举契约（唯一真相）

统一采用 **前端请求值（canonical）** 作为契约值，后端负责映射到各数据源：

| canonical | 含义 | eltdx 参数 | 备注 |
|---|---|---|---|
| `tick` | 分时 | —（走 `/market/minutes`） | 不进 K 线缓存 |
| `1m` | 1 分钟 | `1m` | |
| `5m` | 5 分钟 | `5m` | |
| `15m` | 15 分钟 | `15m` | |
| `30m` | 30 分钟 | `30m` | |
| `60m` | 60 分钟 | `60m` | |
| `1d` | 日线 | `day` | |
| `1w` | 周线 | `week` | |
| `1mo` | 月线 | `month` | **当前断裂，须修复** |
| `1q` | 季线 | 待实测（见 A4） | **当前断裂，须修复或置灰** |
| `1y` | 年线 | `year` | |

**失败策略**：后端收到不在上表的 `period` → 返回业务码错误 `不支持的周期: {p}`，**不得** fallback 到 `day`。

### 4.2 快照字段契约

`/market/quote` 与 WS `quotes` 帧统一字段（缺失为 `null`，前端渲染 `—`，零 mock）：

| 字段 | 含义 | 来源 | 状态 |
|---|---|---|---|
| `last/open/high/low/lastClose` | 现价/开/高/低/昨收 | eltdx | ✅ |
| `volume/amount` | 成交量(手)/成交额 | eltdx | ✅ |
| `bids/asks[5]` | 五档（price/volume） | eltdx | ✅ |
| `inside/outside` | 内盘/外盘(手) | eltdx | ✅ 本轮补 |
| `current_hand` | 现量(手) | eltdx | ✅ 本轮补 |
| `bid_total_vol/ask_total_vol` | 委买/委卖总量 | eltdx | ✅ 本轮补（前端亦可由五档派生） |
| `limit_up/limit_down` | 涨跌停价 | — | ⬜ 待补（P1-A5） |
| `vol_ratio` | 量比 | — | ⬜ 待补（P1-A5） |
| `turnover_rate` | 换手率 | — | ⬜ 待补（P1-A5） |

**派生规则（前端）**：委比/委差由五档派生（`QuotePanel.jsx:66-71`），后端不重复计算。

### 4.3 WS 协议契约

| 方向 | 消息 | 说明 |
|---|---|---|
| C→S | `{"action":"subscribe","codes":[...]}` | 幂等，重复订阅安全；后端随即回全量快照 + 最近 30s 补窗 |
| C→S | `{"action":"unsubscribe","codes":[...]}` | 后端已实现；前端暂不退订（引用计数为 0 仍需保留，见 P1-4 说明） |
| C→S | `{"action":"ping"}` | 心跳，25s 一次 |
| S→C | `{"type":"pong","seq":n}` | 心跳应答 ✅ 已实现 |
| S→C | `{"type":"quotes","data":{"items":[...]}}` | 微批增量 |
| S→C | `{"type":"quotes_replay","data":{"items":[...]}}` | 断线补窗 |
| S→C | `{"type":"quote","data":{...}}` | 单只推送 |
| S→C | `{"type":"heartbeat","ts":...}` | ⬜ **待新增**（P1-A6，服务端主动心跳） |

## 六、实施顺序建议

```
阶段 A（P0 静默错误，必须先行，解耦于 UI）

## 七、风险与回滚

| 风险 | 影响 | 应对 |
|---|---|---|
| A2 清缓存导致用户重拉耗时 | 首次加载变慢 | 仅清理 `1mo/1q/1mon/mo` 四个污染键，不动 `1d/1w` 等大量正常缓存 |
| A1 显式报错可能让旧前端（发 `1mon`）直接失败 | 兼容性 | `CANONICAL_PERIODS` 保留历史别名 → canonical 的**入向**兼容映射，仅对完全未知值报错 |
| A4 季线若不支持需置灰 | 功能减少 | 置灰 + tooltip 说明，优于当前的错误数据 |
| C1 十字光标高频回调引发重渲染 | 性能 | 信息条用独立 state + `requestAnimationFrame` 节流，不触发图表 `setOption` |
| C2 指数条新增订阅 | WS 负载 | 复用 QuoteHub 引用计数，指数代码常驻订阅仅 3-5 只 |

**回滚**：本方案所有改动均为增量文件/局部替换，A1 若引发兼容问题可回退 `_map_period` 为双映射（canonical + 历史别名），其余任务独立可回滚。
