## 一、需求 ① 自选股默认展示最新行情（休市显示最近交易日）

### 现象（修复前）
`useLiveQuotes` **只走 WS 订阅**，而 WS 是**券商实时推送**：**休市 / 节假日 / 盘后 /
没连券商**时一条都不推 ⇒ 自选股 4 只全是 `--`，界面还写着「最近交易日 · 2026-09-18 已收盘」
—— 日期对、数字空，用户会读成「软件坏了」或「这票退市了」。

### 修法（两层，缺一不可）

**① 后端**：`market.py::market_quotes` 的价格归一化（**唯一出口**）

`/market/quotes` 是**唯一**对外返回行情列表的端点，但两条来源键名**不一致**：
- 券商 WS 快照缓存：给 `price`
- eltdx / 打源补齐：给 `last`（`marketApi.quote` 的注释里那条老警告）

前端 `Quote` 类型只有 `price` ⇒ 直接读 `last` 会得到一堆 `undefined`
（「订阅到了但没数字」的老坑）。用 `core.quote_fields.pick_last_price`
（键序唯一入口 `lastPrice → last → price → close`）统一成 `price`：

```python
px = pick_last_price(it)
if px is None:
    it.pop("price", None)   # 取不到就删掉，绝不写 0
else:
    it["price"] = px
```

把 `_fill_missing_names` 升级为 `_normalize_quotes`（补名 + 归一价）。

**② 前端**：新增 `useDisplayQuotes` / `useFallbackQuotes`（`hooks/useLiveQuotes.ts`）

| Hook | 作用 |
| --- | --- |
| `useFallbackQuotes(codes)` | 拉**最近交易日收盘**快照（含 1s 快重试 + 15s 轮询） |
| `useDisplayQuotes(codes)` | **WS 实时优先，缺失时回退收盘快照** —— 看板类列表用它 |

合并规则（双源不打架）：
- WS 有实时价（判据唯一实现 `isLivePrice`）⇒ 用它，名称缺失用兜底名补齐
- WS 无实时价 ⇒ 用最近交易日收盘快照
- 两边都没有 ⇒ `undefined` 渲染成 `--`

**为什么抽成 hook 而不是在组件里各写一遍**：`QuoteBoard`（自选股全页 / 工作台左栏）和
`DataPanel`（侧栏自选面板）是**两套实现**，各兜一遍必漂移。抽一层后两处同时受益。

### 一个必须记住的坑：后端 tencent 源全局节流
`TencentSource._MIN_INTERVAL = 0.3s`（跨请求共享一把 `asyncio.Lock`），
4 只并发打源时常在 5s 超时窗口内拿不到任何东西。所以 `useFallbackQuotes` 做了
**「首次空 → 1s 快重试 → 仍空 → 15s 常规轮询」**，否则用户要盯着 `--` 发呆 15 秒。

## 六、遗留项收尾：后端批量行情接口（本轮已修完）

上一版报告里的遗留 ②「4 只并发有概率超时」已彻底修掉，过程里踩了两个坑，都值得记。

### 坑 1：加在了错误的类上 → 批量链路**完全没生效**

`get_quotes` 最初加在 `datasource/base.py` 的 **`DataSource` 基类**上，
但 `/market/quotes` 里 `m = get_hub()` 拿到的是 **`DataSourceManager`**
（`datasource/registry.py`）——**两者没有继承关系**。

后果极其隐蔽：`m.get_quotes(...)` 抛 `AttributeError`，被 `_fill_batch` 的
`except Exception: return [None] * len(cs)` **静默吞掉**。

- 现象：冷启动连拉 3 次，`items.len` 都是 **0**；
- 更关键的判据：后端日志里 **一次腾讯 HTTP 都没有**（`grep -c qt.gtimg.cn` = 0）。
  「声称在用某个源，但日志里这个源一次都没出现」= 代码根本没跑到。

修法：给 `DataSourceManager` 也加 `get_quotes`，复用它自己的
`_merge_quote` / `_resolve_sources` / `_call_source` 链路。

### 坑 2：批量省下的 HTTP，被「批量取画像」原样加回去

第一版 manager 批量实现里，画像走 `src.get_details(codes)`；而
`_PublicSource.get_details` 内部又调了一次 `get_quotes` ⇒ **每次 API 调用打 2 次腾讯**。
当时还写了句「复用批量那次 HTTP」的注释 —— **是假的**（这正是项目里最忌讳的那类错误）。

修法：新增零请求的派生钩子 `DataSource.derive_detail(raw)`
（默认 `None` = 不支持），`_PublicSource` 重写为「从已取到的快照取 6 个键」。
manager 批量路径先派生，派生不了的才回源取画像。

### 实测证据（可证伪）

```
=== 单次 /market/quotes（4 只）===
items.len= 4
  000001.SZ 平安银行 price=11.70  chg%=+0.78  src=tencent
  600519.SH 贵州茅台 price=1257.12 chg%=-0.78  src=tencent
  000300.SH 沪深300  price=4507.39 chg%=+1.06  src=tencent
  399006.SZ 创业板指 price=3372.68 chg%=+2.25  src=tencent
耗时 1300 ms
=== 后端日志 ===
总腾讯 HTTP 次数: 1
去重 URL: 1 × qt.gtimg.cn/q=sz000001,sh600519,sh000300,sz399006
```

修复前：3 次调用全部 `items.len=0`；修复后：**首次调用即 4/4，且只 1 次 HTTP**。

### 顺带修掉的一个静默坑

`_merge_quote` 原来写 `raw["pre_close"] = detail.get("pre_close") or raw.get("lastClose")`。
批量路径的画像只有 6 个键，一旦缺 `pre_close`，源层已解析好的昨收会被**抹成 None**，
进而让 change/change_pct 推导整体失效（界面显示「有价格、涨跌全空」）。
现改为三级回退：详情层 → 源层 `pre_close` → 源层 `lastClose`。

## 八、全量审计发现的第三个真缺陷：市场概览 9.2s 且只显示 2/8 个指数

改完上面两项后跑 35 页全量审计（`tests/ui_audit_r17.mjs`），
`行情 › 市场结构` 报 **⚠仍在加载**（文本=331、表格=0）。顺着查下去是个很值钱的坑。

### 现象与定位

`/market/overview` 冷启动 **9.24s**（其它端点都是几十毫秒），且返回 `indices: 2`
—— 配置里是 **8 个**指数。

### 根因

```python
ires = await asyncio.gather(*[_iq(c) for c in configured_indices(state)])  # 8 个指数
```

看着是并发，实则被公开源的**全局 0.3s 节流锁**串成串行：8 只 × 单只 `get_quote`
**2 次 HTTP**（行情 + 详情）= 16 次请求 ≈ 9.2s。

### 最隐蔽的后果（比慢严重得多）

每只外层还有 6s 超时 ⇒ **8 个指数只有 2 个活下来**。而 `unavailable` 的判据是
「breadth 与 indices 与 trend **三者全空**」——breadth 非空，所以它**不置** `unavailable`。
结果：页面安静地少显示 6 个指数，**一句提示都没有**，谁都不会发现。

（顺带印证了批量接口的价值：同一个坑，报价牌是「4 只全空」，这里是「8 个只剩 2 个」。）

### 修法

`aggregates.py::overview` 的指数快照改走批量接口 `get_hub().get_quotes(codes)`
—— 1 次 HTTP 拿全部。

### 实测

| --- | --- | --- |
| 冷启动耗时 | **9.24s** | **0.68s** |
| 拿到的指数 | **2 / 8** | **8 / 8** |

## 九、追加：把 flaky 测试追到底，挖出「剪枝会删掉最新备份」

前几轮里 `test_db_backup_policy.py::test_budget_prunes_oldest` 隔三差五失败，
此前两次都被判成「flaky（测试间状态污染），非本轮引入」而放过。这次追到底了 ——
**它不是 flaky，是会删掉最新还原点的真缺陷。**

### 复现（3 次里失败 2 次）

```
test_budget_prunes_oldest: assert [1000, 3000] == [2000, 3000]
```

### 根因

```python
# gateway/db_backup.py::DBBackup._files
files.sort(key=lambda p: p.stat().st_mtime, reverse=True)   # 「新 → 旧」
```

两个原因叠加，让 mtime 完全不可靠：

1. 回退复制路径用 `shutil.copy2`，它把**主库的 mtime 复制给备份**
   ⇒ 备份文件的 mtime 记的是「主库最后写入时间」，不是「备份生成时间」；
2. Windows/NTFS 下短间隔连续写同一文件，mtime 可能**完全相同** —— 实测三个备份
   `mtime_ns` 都是 `1789918599694760700`。

`sort` 在键相等时是**稳定排序** ⇒ 顺序退化为 `glob` 的目录顺序 ⇒
「哪份最旧」变成随机。而 `_plan()` 正是按这个顺序决定删谁。实测同一脚本里：

| 轮次 | 该删 | 实际删了 |
| --- | --- | --- |
| round1 | 1000（最旧） | **2000** |
| round4 | 1000（最旧） | **3000（最新的那份！）** |

保留策略的本意是「保住最新的还原点」，实际却可能把它删掉。
`_unique_name` 的注释里就写着「启动 + 手动 + 关闭，实测两次调用落在同一秒」——
这是**生产会发生**的路径，不是测试专用。

### 修了三处

| 位置 | 改动 |
| --- | --- |
| `_files()` | 排序键改成**文件名**（`app.<%Y%m%d_%H%M%S>.db` 字典序即时间序，不依赖文件系统时间戳精度） |
| `_unique_name()` | 同秒碰撞序号**补零**（`_002`）：不补零时 `_10` 字典序小于 `_2`，顺序会错 |
| 复制路径 | 复制后 `os.utime(dst, None)`：mtime 改回落盘时刻（`copy2` 会把主库 mtime 带过来，界面「备份时间」显示的是错的） |

### 验证

- 复现脚本 6 轮：**修复前 2 轮失败 → 修复后 6/6 通过**；
- 三个相关文件连跑 5 次：**5/5 全过**；
- 新增两条**可证伪**的回归测试，并**实际回退验证过它会失败**：
  - `test_prune_orders_by_name_not_mtime`：把 mtime 设成反向（最新备份 mtime 最旧），
    按 mtime 排必然把 3000 判成最旧而删掉 ⇒ 实测旧实现得到 `[1000, 2000]`（真失败）。
  - `test_backup_mtime_is_creation_time_not_source`：主库 mtime 设成古老值，
    备份不得继承它。

### 顺带修掉的：市场概览「部分缺失」静默

`overview()` 原来只在 **breadth + indices + trend 三者全空**时才置 `unavailable`。
实测现在 breadth 缺失、trend 缺失、indices 有 8 个 ⇒ **一句提示都没有**。
改成按块判定：


   于是作用域变成整页，把侧栏自选股的行也混了进来 —— 页内页签要直接找 `[role="tab"]`。
3. **名称断言不能写死**：标题是行情源返回的真名，实测 `000002.SZ` 是「万  科Ａ」
   （全角 Ａ + 空格），写死「万科A」会把**正确行为**判成失败。

⚠️ 前两个坑值得记住：**报 FAIL 之前先怀疑探针**（此前已多次印证）。

### 13.2 补充的字段 —— 全部来自**同一条**快照，零额外请求

腾讯快照（`qt.gtimg.cn/q=sh600519`）一条响应里本来就有 ~50 个字段，**以前只解析了 7 个**。

⚠️⚠️ **下标是实测的，不是照抄文档猜的**：拉了 `sh600519` / `sh000001` / `sz300750`
三个真实样本逐位核对，并用「涨停价 = 昨收 × 涨跌停比例」自洽性验证

### 13.5b ★ 打包态实测暴露的真问题：装了 eltdx 的客户端上，这些字段全是 `--`

打完包用**打包态后端 EXE** 打接口，返回的是：

```json
{"source":"eltdx", "open":null, "avg_price":null, "pe_ttm":null, "circ_mv":null, ...}
```

**根因**：详情源优先链是 `broker → eltdx`，而**本地 TDX 与券商都不提供**市值 / PE / PB /
换手 / 振幅 / 均价 / 量比 —— 它们是「行情快照派生字段」，只有公开行情源（腾讯/新浪）有。
打包版自带 eltdx ⇒ 用户实际看到的是一整列 `--`，**功能等于没做**。
（开发实例上恰好是 tencent 赢，所以之前怎么测都是好的 —— 典型的「换环境才暴露」。）

**修法**（`app/routes/market.py`）：详情取完后，若仍有缺口，就再从
**声明了这些字段的源**补一次行情 —— 只补缺的那几个键，补齐即停。

```python
missing = [k for k in _METRIC_KEYS if info.get(k) is None]
if missing:
    for name in _metric_sources():      # 按「声明的字段键集」动态找，不写死 "tencent"
        q = await get_hub().get_quote(code, source=name, conn_id=conn_id or None)
        for key in list(missing):
            if q.get(key) is not None:
                info[key] = q[key]; missing.remove(key)
```

三条纪律：
- **动态找源**，不写死 `"tencent"` —— 源是可插拔的，写死会在没有腾讯源的部署里
  变成一句永远失败的请求；
- **只在确有缺口时**才多打一次行情（详情源已给全 ⇒ 一次都不多打，有测试锁住）；
- 补齐过程**任何异常都吞掉**：补不上就保持 `None`（前端 `--`），绝不让整个接口失败。

**诚实性**：此时 `source` 仍是详情源（eltdx），所以响应额外给 `metrics_source`
说明这些字段来自谁；界面上「数据源」一格会同时显示 `eltdx` 与 `行情 · tencent` 两枚标签 ——
否则「数据源写着 eltdx、市值却是别处来的」会被当成 eltdx 的数据。

**实测**（源码实例，强制 `source=eltdx`）：
`source=eltdx` + `metrics_source=tencent`，`open 1262.99 / 均价 1259.84 / 市盈 19.3 / 流通市值 1.5715e12` 全部补齐 ✓

### 13.8 ★ 打包态验收脚本抓到的**第二个**真问题：`det is None` ⇒ HTTP 500

把「缺口补齐」这条补进 `scripts/verify_packaged_backend_api.py`（它是唯一能跑打包态后端的入口）
之后，第一次运行就报红：

```
[FAIL] GET /market/stock-info   status=500 body={'code': 500, 'message': '服务器内部错误', ...}
```

后端日志给出真因：

```
File "app\routes\market.py", line 424, in market_stock_info
AttributeError: 'NoneType' object has no attribute 'get'
```

**根因不是本次新增的代码**（`git diff` 显示那一行只改了 `or code` → `or _lookup_name(code)`），
而是一条**早就存在、只在特定形态下才走到**的假设：

- `get_instrument_detail` 在**全链都不可用**时抛 `MarketDataUnavailable`（端点有专门分支接住）；
- 但在**全链都返回空壳**时走的是 `return last`，而 `last` 仍然是 `None` ——
  端点没有接住这一种，直接 `det.get(...)` ⇒ 500。

触发条件恰好是**刚装好的客户端**：没连券商 + 本地还没下载过 TDX 数据。
也就是说，这个缺陷正好砸在本次新增的「基本信息快速查看」上 —— 用户点开面板看到的是报错。

**修法**（`app/routes/market.py::market_stock_info`）：

```python
    if not isinstance(det, dict):
        info["note"] = "未取到本地画像（未连券商、本地也无该标的资料），仅展示行情字段"
        det = {}
```

三条设计取舍：

1. **降级而不是 500**：画像字段留空 → 前端 `--`，板块仍按代码前缀推断（不依赖任何源）；
2. **仍然走行情补齐**：公开行情源与「本地有没有 TDX 数据」**无关**，
   所以即便画像为空，市值 / PE / 换手… 仍可能拿到实时值 —— 不该一并放弃；
3. **诚实说明**：`note` 讲清「为什么是空的」，否则用户会以为是自己写错了代码。

**回归**（`tests/test_stock_info_fields.py` 新增 2 例）：

- `test_detail_none_degrades_instead_of_crashing` —— 断言仍返回结构、有 `note`、
  数值全 `None`、板块仍推断、**名称不许拿代码冒充**；
- `test_detail_none_still_fills_metrics_from_public_source` —— 画像为空时
  仍从公开源补齐 12 个字段，且 `high_limit` 这类画像字段保持 `None`。

**顺带记下的教训**：「源都不可用」与「源都在、但都返回空壳」是**两种不同的空**，
只接住前一种，就会在后一种上炸 —— 和 §十三 里「部分缺失只判全空」是同一类思维漏洞。

### 14.6 反面对照：源码实例的**正常路径**没被守卫改坏

`det is None` 那条守卫是在「没有本地画像」时降级用的，必须证明它**不影响有画像时的正常路径**。
在独立源码实例上（真实库副本 `VACUUM INTO`，`QMT_BROKER_AUTO_CONNECT=false`）实测三个标的：

| 标的 | source | metrics_source | 关键字段 | 说明 |
| --- | --- | --- | --- | --- |
| `000001.SH`（上证指数） | tencent | tencent | 今开 3891.96 / 均价 3905.27 / 振幅 0.80 / 换手 1.00 / 量比 1.02 / PE 17.06 / 成交额 9941.69亿 / 总市值 697380.59亿 | 涨跌停与市净率 **`None`**（哨兵 -1 / 0.00 被正确挡掉） |
| `600519.SH`（贵州茅台） | tencent | **None** | 涨停 1393.68 / 跌停 1140.28 / PE 19.30 / PB 6.25 / 均价 1259.84 | 详情源已给全 ⇒ **不多打一次行情**；涨停 = 1266.98 × 1.1 ✓ 自洽 |
| `000002.SZ`（万  科Ａ） | tencent | **None** | PE **-0.43** / PB 0.39 / 振幅 10.26 / 量比 5.14 | **负 PE 被保留**（证明「不许 `<=0` 就当没有」）；名称含全角与空格，正是不能用死字符串断言的原因 |

三条被这张表同时验证的性质：

1. 守卫**只**在 `det` 非 dict 时生效 —— 有画像时字段一个不少；
2. `metrics_source` 只在**真的补过**时才出现（茅台/万科为 `None`）⇒ 界面不会虚标来源；
3. 哨兵与边界值都按规则处理：指数涨跌停/市净率 → `None`，亏损股负 PE → **原样保留**。
