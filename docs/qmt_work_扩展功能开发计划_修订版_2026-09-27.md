### 1.2 五条核心实现链路（详细逻辑）

**① 下单主链（写路径，唯一合法通道）**
```
POST /api/v1/trade/order
 → AuthMiddleware(apikey scope 匹配，未映射端点默认 admin)
 → RateLimitMiddleware(滑动窗口)
 → EnvelopeMiddleware({code,message,data}) + request_id(trace_id)
 → routes/trade.py:precheck 可选
 → gateway/execution.ExecutionService.place_order()
     ├ checker is None → 硬拒绝（不可绕过）
     ├ _risk_price(): 用 core.quote_fields.pick_order_ref_price 解析真实参考价
     ├ RiskManager.check_order(): 锁内 日切→挂单清理→60s 频率窗→_validate_order
     │    → 通过后计数 + _reserve_pending(120s TTL 占用在途金额)
     └ bridge.call_locked(...) → 非零网关码 → ok=False + audit(order.failed)
 → WAL(cancel_intent/cancel 等) → audit_log(hash 链) → metrics.record_order → WS 广播
```
规则要点：`normalize_direction` 未知方向返回 None 即拒（绝不当卖出）；熔断只挡买入；
`volume % 100 == 0`；买单要求 `require_account` 且 `data_source == "live"`（禁止拿 DEMO 资产当分母）；
价格偏离 / 白黑名单 / 单票与组合仓位比 / 日额度与日亏损熔断。

**② 行情与数据链（读路径）**
```
源(QMT|eltdx|akshare|baostock|sina|tencent|local)
 → DataSourceManager.resolve_chain(capability)  5 道过滤：默认链→已注册→依赖可用→商用许可→声明能力
 → 超时/熔断/节流 → 失败换下一跳
 → degrade.py：远程全失败时回落 local_bars（stale=True, as_of=最后bar），本地也空 → 返回 None → 路由 503
 → 绝不返回伪造数据；envelope 合并 {source, stale, as_of, warning(s)}
```

**③ MCP 暴露链（Agent 只读面）**
```
build_mcp(risk)
 ├ 15 个手写 registrar（tools/*.py + engines/*.py 内 @mcp.tool，56 个）
 └ register_auto_tools(): 遍历 capabilities.agent_visible_reads()
      仅 GET + agent_visible + 参数签名安全 → exec(compile(src)) 生成同签名 async 函数
      → 进程内直调 handler（绕过 HTTP 鉴权/限流，故只放只读）→ 解包 code==0 返回 data，否则原样返回信封
红线：_EXEC_DENY_DOMAINS（trade/rebalance/algo/brokers/scheduler/ws/…）永不自动暴露 → 写操作 Agent 只能看不能做
门禁：scripts/check_capability_drift.py 比对 127 工具基线，缺失即 CI 红
```

**④ 启动与调度链**
```
run.py：单例锁(.qmt_work.lock) → 自检(非回环+默认 api_key 直接拒启) → 端口锁/扫描 → uvicorn
create_app() lifespan：6 相位串行，Required 相位失败即中止（broker 为唯一 Optional）
   phase_misc L105-145 启动 durable scheduler
ScheduleRunner：tick 30s → CronExpr.parse(5 段) 命中 → catch_up 补跑（上限防雪崩）
   → JobRuntime.submit(配额 sync=1/backtest=2/global=4，优先级，租约 90s，持久化 runtime_jobs)
   → runner factory：system.sync_bars(工作日16:00) / system.classic_screen(16:15) / system.eod(18:00)
     / reconcile_bars / rolling_repair / coverage / publish_snapshot / refresh_universe / sync_fundamentals
   → 写 local_bars + dataset_snapshots(coverage/row_count/checksum/quality_state)
```

### 治理阶段

#### A1' · 本地 pre-commit 四门禁 + CI 三缺陷修复（1d，P0）

- **背景**：CI 已有 7 项门禁，但本地无任何强制；CI 自身有 3 个已实证缺陷。
- **改动**：
  1. 新增 `.pre-commit-config.yaml`（跨平台兜底，替代母文档的 ps1-only 方案）：
     `ruff` + `check_execution_architecture` + `check_capability_drift` + `check_licenses`（秒级）；
     另把现有 `scripts/post-commit.hook`（自动构建）与新钩子职责分离，`scripts/install-git-hooks.ps1` 同步改为安装 `pre-commit`。
  2. **CI 缺陷修复**（均已实证）：
     - `.github/workflows/build-client.yml:129` 上传 `frontend-next/release/*`，
       但 `electron-builder.yml:21` 输出在 `dist-electron/` → 干净 runner 上**上传空产物**。改为 `dist-electron/*`（与 `verify_artifacts.py:69` 对齐）。
     - `build-client.yml` 的 `pip install ruff` 未钉版本（`ci.yml` 钉 `0.16.3`）→ 统一钉 `0.16.3`。
     - CI 用 Node **20**，`TOOLCHAIN.json` 声明 **22.22.2** → 统一 `22.22.2`（或显式改 TOOLCHAIN 并记录理由）。
  3. 把 `check_capability_coverage.py`、`check_ws_consumption.py` 接入 CI（先以 warning 模式跑一周，再转硬门禁）。
  4. `check_frontend_classnames.py` 已退役：从 CI 移除调用或保留 `[SKIP]` 并在脚本头部注明退役日期与替代品。

## 第五部分 · 执行规范（继承母文档 + 补充）

1. **任务粒度**：一个任务 = 一个 PR；PR 描述写清「改动文件 / 行为变化 / 验证方式」。
2. **先测试后代码**：指令顺序固定为「读这几个文件 → 写/改测试 → 实现 → 跑 ruff + pytest + 门禁」。
3. **零 mock 红线**：不得为让测试通过而返回伪造行情或假成交；未连接真实源一律错误码 + 修复提示
   （`datasource/degrade.py` 的"降级≠伪造"是唯一合法例外，且必须带 `stale/as_of/warnings`）。
4. **每 PR 必跑的验证闭环**：
   ```
   cd backend && ruff check . && pytest -q
   python scripts/check_capability_drift.py          # backend/scripts 下
   python ../scripts/check_execution_architecture.py
   python ../scripts/check_licenses.py
   python tests/smoke2.py                            # 需起后端，真机项
   cd ../frontend-next && npm run typecheck && npx vitest run && npm run build
   ```
5. **真机项单独管理**：真实券商/行情源验证不进 CI，`@pytest.mark.broker` 手动执行（**先在 pyproject 注册该 marker**），
   演练结果记入 `docs/`（模板：`docs/archive/QMT真机全链路演练单.md`）。
6. **AI 产出必查三项**：是否绕过 `gateway/execution.py` 直接下单（门禁 G1）；
   是否在数据源不可用时静默返回空/假数据；是否新增未注册的 GET 端点（漂移门禁拦）。
7. **每 PR 后更新** `scripts/ci_reconcile.py` 的 `EXPECTED_TESTS/EXPECTED_PAGES/EXPECTED_COMPONENTS`（用 `--update`，
   ⚠️ 必须在 Python 3.11 下执行，否则会被写成 0 —— 见 `docs/TECH_DEBT.md`（Python 版本约束）。

## 第六部分 · 风险与红线

- **架构分叉风险（本版新增，最高优先）**：`connectors/`（9 端口，未接线）vs `xtquant_client/adapters`（生产，stub）
  的双真源必须在 C1' Step 0 定案，否则第二连接器会做成第三套并行实现。
- **合规**：接入第三方 SDK/数据源先过 `check_licenses.py`；GPL/AGPL 默认不进主包；`eltdx` 为 Research-Only 禁商用。
- **资金安全**：新增写能力默认 dry-run；实盘开关需显式配置 + 二次确认 + 审计；MCP 侧永不自动执行（`_EXEC_DENY_DOMAINS` + C2' token）。
- **数据正确性优先于功能数量**：B 组全部完成前，不推广 D 组研究功能。
- **Windows 依赖**：xtquant 仅 Windows + QMT 同机；任何改动须保留"无 QMT 纯研究模式"可通过。
- **门禁一致性**：改 Tier-0 基线（`rest_endpoints.json` / `mcp_tools.json`）必须跑 `backend/scripts/gen_contracts.py --diff` 并在 PR 说明中列出差量。
