### 0.1 本期 / 延后期划分（v1.3 修订）

| 分区 | 内容 | 依据 |
|---|---|---|
| **本期（Phase 0–9）** | 工程基线归零 → Tier-0 契约锁定 → **QMT 下单正确性与强化** → 数据面单链最小闭环 **+ 多源 Provider 扩展** → **多源选股引擎强化** → AppContext+Lifecycle → Connector 平台 → Durable Scheduler + EOD 多源治理 → 前端 Platform-First + TS → 打包发布 | D1 / D9 / D10 / D12 |
| **Backlog A（回测）** | 回测口径修复（next_open / T+1 / 复权 / 因子 IC 转置）+ `BacktestPort` 适配 backtrader / vnpy / qlib / rqalpha | D7 |
| **Backlog B（插件）** | Plugin Runtime（manifest 签名 / 进程-RPC 隔离 / SecretProxy / storage / install-update-rollback） | D6 |
| **Backlog C（研究增强）** | NL 选股语义扩展 + MCP 暴露、涨停引擎持久化、QMT 托管算法单、融资融券/期权期货、账户资产推送、委托成交历史、同花顺/PTrade/掘金真实 adapter、**tushare/efinance/adata 等更多 Provider** | D2 + §5.7 |

> **本期为什么要先做数据面单链 + 多源 Provider，再做选股强化**：当前选股读的是 `local_bars`，而这条链的**唯一实际供数方是 `eltdx`（qfq）** —— 因为 `registry.py:425-435` 的 qfq 分支**显式跳过 broker**，且 `get_manager()` 把 auto 链写死为 `["broker","eltdx"]`，导致 sina / tencent / tstdx / baostock **虽已注册但永不参与 auto**（等同死代码）。三个后果：
> 1. **选股结果与 QMT 客户端看到的行情不是同一份数据**（QMT 侧历史 K 线还被硬编码 `dividend_type="none"`，只有不复权）；
> 2. **没有 QMT 的用户实际只有 eltdx 一条路**，而 eltdx 是 **Research-Only 许可、明文禁止商用**（`docs/THIRD_PARTY_LICENSES.md` §3.2）→ **商用构建下选股数据为零**；
> 3. 用户无法选择、也无法知道「这次选股用的哪份数据」。
>
> 因此本期把「数据面单链」与「多源 Provider 扩展」合并为 Phase 3 一起做：先建立 `raw_bars → canonical_bars` 的可溯源链路，再把 QMT / eltdx / baostock / akshare / pytdx / sina / tencent 全部接成**同一条能力链上的平级 Provider**，最后由 Phase 4 让选股引擎按能力链取数并输出溯源信息。
>
> **v1.3 锁定的默认降级链**（项目所有者确认）：
>
> ```
> QMT（默认，可用时一律优先）
>   └─► eltdx     （第 2 优先；研究构建正常参与，商用模式自动跳过）
>         └─► baostock   （第 3；BSD、免 token、复权规范、财务与停复牌字段齐）
>               └─► akshare  （第 4 / 末位兜底；MIT、仅需网络、能力最全的公共源）
>                     └─► pytdx / tencent / sina  （仅显式指定，或 quote 类能力的末位兜底）
> ```
>
> **为什么「eltdx 第 2」与「eltdx 禁止商用」不矛盾**：许可证约束是**构建/运行模式层面的过滤器**，不是排序依据。研究构建（默认 `commercial_mode=false`，产物内含 eltdx）下 eltdx 排第 2 是合理的——它能力最全、且是本项目当前唯一真正在跑的 K 线源（把已工作的路径降级才是风险）；而 `commercial_mode=true` 时，**链在求值阶段就跳过 `commercial_ok=false` 的源**，链自动变成 `QMT → baostock → akshare`，行为与「运维层面移除 eltdx」等价，不需要在业务代码里写例外。

#### A.1 QMT 下单能力现状（v1.1 专项审计结论）

**一句话结论**：当前 QMT 下单链是**「单账户、同步、二元价格类型」的最小子集**，且有三处正确性硬伤。

| QMT 能力 | 平台现状 | 证据 |
|---|---|---|

#### C.1 选股链 QMT 侧接入现状（专项审计结论）

**一句话结论**：**选股链当前完全没有走 QMT**，QMT 只贡献了「图表 / 涨停扫描 / 参考数据」旁路。

```
前端 Screen.jsx
  └─ GET /api/v1/market/screen → routes/screen.py:33 → screener/engine.py:scan()
       ├─ universe  = local_stock_list 全部 code       engine.py:49      ← 非 QMT 板块/指数
       ├─ 逐只 get_bars(code, "1d", adjust="qfq")      engine.py:62
       │     └─ datasource/local_store.py:102  单条窗口 SQL（逐只一次）
       └─ evaluate() → app/indicators 本地 numpy 现算  conditions.py:69-79

填充这条链的是 app/sync/bars.py:116-144：
  hub.get_kline(source="auto", adjust="qfq")
    └─ registry.py:425-435  ★ qfq 分支【显式跳过 broker】→ 实际只有 eltdx(TDX) 供数
       （QMT 侧 quotes.py:127-130 历史 K 线被硬编码 dividend_type="none"，只有不复权）

### D-A. `OrderIntent` 与 `ExecutionService` 收口

新建 `core/domain/execution.py`：

```python
@dataclass(frozen=True, slots=True)
class OrderIntent:
    intent_id: str            # uuid4，幂等与 WAL 主键
    source: IntentSource      # rest|mcp|ui|strategy|signal|algo|condition|limitup|rebalance|target_position|batch
    broker_id: str
    account_id: str
    code: str
    side: Side                # buy|sell
    volume: int
    price: float | None
    price_type: PriceType
    mode: ExecutionMode       # live|paper|dry_run
    idempotency_key: str       # 由调用方提供或 run_id+batch_id+idx 派生
    batch_id: str | None
    require_confirm: bool
    risk_context: dict         # 组合/持仓参考
    actor: Actor               # api_key_id / request_id / user
    remark: str
    created_at: float
```

`ExecutionService.handle(intent) -> ExecutionResult` 内部**严格顺序**（这是 A2 的修复）：

```
1. schema validate                        （无副作用）
2. PricingPolicy.resolve(intent)          （市价单必须拿到真实最新价，取不到即拒绝）
3. idempotency.claim(key)                 （持久化；已存在则返回原结果，不重复下单）
4. MandatoryRisk.check(intent)            （唯一一次计数；checker 为 None 即拒绝）
5. PermissionGate(intent)                 （require_confirm 且超阈值 → 挂起等 TOTP；支持 remote_force）
6. WAL.write_ahead(intent, "pending")     （先落盘再下单）
7. mode dispatch:
     dry_run → 返回计划，WAL 记 dry_run
     paper   → PaperEngine.fill(intent)，WAL 记 paper_filled
     live    → ExecutionPort.place_order(intent)
8. WAL.update(intent, status)             （submitted / rejected / timeout_unknown）
9. audit.close(intent, result)
10. metrics + notifier + WS event         （事件名语义化：order.accepted / order.rejected /
                                            order.timeout_unknown / order.filled / deal.*）
```

`SignalRouter` 降级为**薄适配层**：`route(Signal)` → 构造 `OrderIntent` → `ctx.execution.handle(intent)`。所有入口（含 `BatchExecutionService`、`order_watchdog`、`routes/trade.py`、`tools/*`）统一走 `handle`。

#### J.1 六条设计原则（不可违反）

| # | 原则 | 含义 |
|---|---|---|
| J-1 | **选股引擎不得绑定任何 Provider** | 引擎只依赖「能力端口」（`HistoricalBarsPort` / `InstrumentDirectoryPort` / `FundamentalPort` …），具体来源由 **Source Policy** 决定；引擎代码里不允许出现 provider 名字 |
| J-2 | **能力优先，名称兜底** | 路由只按**已声明且已实现**的能力选源，禁止按 provider 名称猜测能力；`PROVIDER_CATALOG` 的能力声明必须与实现一致（修 P1-42） |
| J-3 | **显式降级，禁止静默换源** | 任一源不满足能力/口径时，要么报错，要么**带 `degraded + degraded_reason + provider(s)_used` 返回**；绝不静默返回口径不同的数据（修 P1-4 / P1-44） |
| J-4 | **同源一致性** | 同一次扫描（同一 `dataset_snapshot`）内，同一能力的取数**必须来自同一 Provider**。跨源混合（如 K 线 akshare + 财务 QMT）默认禁止；确需混合须显式 `allow_mixed_sources=true`，并把各能力的来源写入 `provider_policy_version` 与快照成员表 |
| J-5 | **许可证合规（链求值期过滤）** | `eltdx` = Research-Only（禁止商用，`docs/THIRD_PARTY_LICENSES.md` §3.2）。`commercial_mode=true` 时链**在求值阶段跳过** `commercial_ok=false` 的源（不报错、不静默），链自动退化为 `QMT → baostock → akshare`；因此 **`baostock` 与 `akshare` 必须在商用模式下实测可用**，并加「无 eltdx 环境跑通选股 E2E」CI 门禁 |
| **J-6** | **默认顺序即契约** | 默认链 `QMT → eltdx → baostock → akshare` 是**产品契约**而非实现细节：它写入 `runtime_config`、由 `/data/providers` 返回给前端、并有 CI 断言守着（§5.5）。改链顺序必须改配置 + 改文档 + 更新契约快照，三处同步 |

#### J.2 Source Policy 契约（新增，一期核心）

```python
class SourcePolicy(str, Enum):
    AUTO        = "auto"          # 【默认】QMT 可用即用 QMT；否则按 CapabilityChain 依次降级 eltdx → baostock → akshare
    PREFER_QMT  = "prefer_qmt"    # 与 auto 同链，但语义上强调「QMT 优先」；未连 QMT 时必定标注 degraded
    QMT_ONLY    = "qmt_only"      # 钉死 QMT；未连接/能力缺失 → 明确 503，不降级
    LOCAL_ONLY  = "local_only"    # 只用本地 canonical 层，完全离线可复现（回放/复现场景默认）
    EXPLICIT    = "explicit:<id>" # 钉死某 provider（qmt/eltdx/baostock/akshare/pytdx/sina/tencent）
```

> `auto` 与 `prefer_qmt` 的差别只在**语义标注**：两者都按同一条链求值，但 `prefer_qmt` 会在响应里显式写出 `qmt_unavailable_reason`（例如 `no_broker_connected` / `qmt_local_data_incomplete`），便于前端提示「本次选股用的是 eltdx，不是 QMT」。这样「默认 QMT」在用户侧是**可见**的，而不是一个隐含假设。

**CapabilityChain（替代写死的 `["broker","eltdx"]`）**：链由 `runtime_config.data.provider_chain` 配置，且**按能力分别求值**——因为不同源的能力集不同（如 baostock 无实时行情、sina 无复权）。

**★ v1.3 锁定的默认顺序（项目所有者确认）：`QMT → eltdx → baostock → akshare`**，`pytdx / tencent / sina` 仅用于显式指定或个别能力的末位兜底。

```yaml

  commercial_mode: auto            # auto | true | false；auto = 探测产物与运行环境（含 eltdx 且非商用时为 false）
  allow_mixed_sources: false       # J-4 同源一致性；置 true 时须把各能力来源写入 provider_policy_version
  provider_chain:                  # ★ 默认顺序：qmt → eltdx → baostock → akshare（逐能力独立求值）
    kline:            [qmt, eltdx, baostock, akshare, pytdx, tencent, sina]
    kline_qfq:        [qmt, eltdx, baostock, akshare, tencent]      # 仅支持复权的源参与
    kline_hfq:        [qmt, eltdx, baostock, akshare, tencent]
    stock_list:       [qmt, eltdx, baostock, akshare, pytdx]

    sector:           [qmt, eltdx, akshare, baostock]

```

> **链的求值发生在能力路由层**（Phase 3 的 `CapabilityRouter`），不在引擎里。求值顺序固定为：
> `① 读配置链 → ② 过滤 dependency_available=false → ③ 过滤能力未声明的源 → ④ 过滤 commercial_mode=true 下的 ⛔ 商用禁源 → ⑤ 过滤显式 source_policy 之外的源 → ⑥ 逐项探测健康（缓存 TTL 内不重复探测）→ ⑦ 取首个通过者`。
> 第 ④ 步是**跳过**而不是报错（这是 v1.3 对 v1.2 的关键修正）：研究构建下链是 `qmt → eltdx → baostock → akshare`，商用构建下同一条配置自动生效为 `qmt → baostock → akshare`，**不需要在业务代码里写任何例外分支**。
>
> 链可被请求级 `source_policy` 覆盖（`explicit:<id>` 即把链缩成单元素且**不降级**）。

|---|---|---|---|
| 1 | **QMT** | **交易同源首选** | 与下单/持仓看到同一份行情，零口径偏差；批量接口一次拉全市场，最快且无需外网。未连接则直接落到下一顺位 |

| 3 | **baostock** | **复权与财务的稳健兜底** | 免 token、无需鉴权、`adjustflag` 复权口径规范、四张报表 + `tradestatus` 停牌字段齐。**商用模式下的第一顺位**（eltdx 被跳过时） |

| 末位兜底 | pytdx / tencent / sina | 显式或个别能力兜底 | pytdx 低延迟但**无复权**（须显式声明）；tencent 有 qfq/hfq 但无列表/板块；sina 无复权。**三者仅在 `explicit:<id>` 或个别能力的链尾参与** |

| 指标计算 | 每条件叶子对同份 bars 重算（`conditions.py:69-79`） | 从条件树**收集去重的指标需求集合**，一次性算完挂到 bars 上下文，叶子只做取值比较 |
| 求值 | Python 逐只循环 | 对齐 `[n_days, n_codes]` 矩阵，指标与条件向量化，返回布尔命中矩阵 |
| 并行 | 单线程串行 | 大规模走 `ProcessPoolExecutor` 分片；在线多源走 `asyncio` 并发（并发度按源可配，默认 **eltdx=4、baostock=2、akshare=4**；QMT 走批量接口，并发度=1） |

| 溯源 | 无 | 结果对象携带 `providers_used / data_as_of / degraded / degraded_reason / snapshot_id / adjust`，透传到 REST/MCP/前端 |

#### J.11 降级与失败语义（禁止静默）

| 场景 | 行为 |
|---|---|
| 首选源不支持该能力（如 sina + qfq） | **跳过并写下 `fallback_tried`**，继续下一源；链耗尽 → `503` + `degraded_reason="no_provider_for_capability:kline_qfq"` |
| `explicit:<id>` 且该源不支持 | **立即 4xx/503 并列出该源的真实能力**，不降级（修 P1-4） |
| 源超时/熔断 | 按熔断冷却跳过，结果标注 `degraded=true` + 原因；**若命中集为空且全部源失败 → 503，绝不返回空列表冒充"无符合条件标的"** |
| 部分标的数据缺失 | 该标的从结果中剔除，并在 `provenance.*.missing_codes` 列出；`count` 语义为「成功评估的命中数」 |
| 本地仓为空 + 无任何在线源 | `503` + 明确安装指引（`pip install akshare baostock` / 连接券商 / 先跑同步） |
| **源被许可证过滤**（`commercial_mode=true` 遇 eltdx） | 静默跳过 + 写入 `fallback_tried[{provider,reason:"license:commercial_disabled"}]`，**但 `degraded=false`**（预期行为，非降级） |
| **QMT 已连接但客户端数据缺失**（未下载历史/无财务权限） | 不视为「QMT 不可用」而整体降链；**该能力**降到下一源，响应中标注 `degraded=true` + `degraded_reason="qmt_capability_unavailable:kline_qfq"`，其余能力仍走 QMT |

| **Phase 4 性能目标（≤3s 全市场）可能达不到** | 中 | 分级验收：本地向量化 ≤3s，本地并行 ≤10s，**在线首次 ≤60s（含落库）**；最差允许「首次冷启慢、二次命中缓存快」；性能门槛设宽线性阈值而非硬编码秒数 |
| **QMT 客户端本地数据不完整/无权限**（财务需权限、历史数据需先下载） | 中 | 能力探测（`xtp/env.py:QmtCapabilities`）+ 启动时提示「需在 QMT 客户端补充数据下载」；不可用时**按链自动降级到 eltdx → baostock → akshare → canonical 并显式标注来源与降级原因**（这正是 D9/D12 的设计目的） |
| Phase 8 TS 化周期长 | 中 | 分域渐进（FE 每域一个 PR），`allowJs` 过渡；**交易/选股/账户三域优先**，其余可延后 |
| 破坏性变更影响既有用户 | 中 | 迁移期双发 + deprecation warning；`VERSION` 单一来源 + CHANGELOG |
| Backlog A 启用后回测结论翻转 | 高（业务） | 延后执行；届时显式告知 + `legacy` 口径开关保留一个 minor 版本 |
